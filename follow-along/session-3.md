# 3회차: 사건 상세 · 정보 수정 · 판단과 조치 기록

시작: `milestone-2` 브랜치(또는 지난 회차까지 내가 만든 코드)
끝나면: 사건을 눌러 상세 화면에서 사진을 보고, 정보를 고치고(버전이 오른다), 내 판단과 조치를 남길 수 있다. 남긴 판단·조치에 따라 홈의 추가 확인·검토 대기·대응 필요 숫자와 사건 상태가 바뀌고, 상세 화면 아래에서 사건 이력을 볼 수 있다.

## 시작하기 전에
1. Antigravity에서 `vision-risk-dashboard-student` 폴더를 엽니다.
2. 지난 회차 브랜치에서 시작하려면 터미널에서 `git switch milestone-2`를 칩니다. 내가 만든 코드로 이어 가면 이 줄은 건너뜁니다.
3. `npm.cmd install`로 설치하고 `npm.cmd start`로 서버를 켭니다. 브라우저에서 `http://127.0.0.1:8765`를 엽니다.
4. 사건 목록에 사건이 하나도 없으면 "사진 등록"으로 두세 건 등록해 둡니다. 그중 하나는 사진을 2장 이상 골라 주세요. 사건 번호(예: `R-101`)를 하나 적어 둡니다.

이번 회차는 서버 코드를 자주 고칩니다. 서버 쪽을 고친 단계 뒤에는 서버 창에서 `Ctrl+C`로 끄고 `npm.cmd start`로 다시 켭니다. 화면만 고친 단계는 브라우저 새로 고침만 하면 됩니다.

## 3-1. 사건 하나 불러오기 (서버)
상세 화면이 쓸 사건 하나의 정보를 서버가 돌려주게 합니다.
```text
사건 번호로 사건 하나를 돌려주는 API(GET /api/records/사건번호)를 서버에 만들어 줘.
사건 정보와 함께 마지막 판단 기록, 조치 기록 목록, 이력 목록도 돌려줘. 지금은 판단은 없음, 나머지는 빈 목록이면 돼.
없는 번호면 404와 "기록을 찾지 못했습니다. 목록에서 다시 골라 주세요."를 돌려줘.
지난 회차에 저장한 기록 파일에 판단·조치·이력 칸이 없어도 빈 목록으로 채워서 오류 없이 열리게 해 줘.
```
확인: 서버를 다시 켜고 `http://127.0.0.1:8765/api/records/R-101`(적어 둔 번호)을 열면 `"success":true`와 사건 정보가 보인다. `R-999`는 오류 문구가 보인다.

## 3-2. 등록할 때 버전과 이력 남기기 (서버)
```text
사건을 등록할 때 버전 1과 마지막 수정 시각(처음에는 등록 시각)을 같이 저장해 줘.
등록하면 그 사건의 이력에 "사건 등록" 한 줄을 남겨 줘. 내용은 "사진 N장 보존 완료 (장소)", 작업자는 "시스템"으로 해 줘.
이력 한 줄에는 시각, 단계(등록·정보 수정·판단·조치 중 하나), 작업 이름, 내용, 작업자를 담아 줘.
지난 회차에 등록한 사건처럼 버전이나 마지막 수정 시각이 없으면 버전 1, 등록 시각으로 봐 줘.
```
확인: 서버를 다시 켜고 사건을 하나 새로 등록한 뒤, 그 번호로 3-1의 주소를 열면 이력에 "사건 등록"이 한 줄 있다.

## 3-3. 사건 상세 화면 틀
```text
사건 상세 화면(주소 #records/사건번호)을 만들어 줘. 3-1의 API로 사건을 불러와.
맨 위 제목은 장소, 그 아래에 분류와 등록 시각을 보여 줘. 화면 위에 "← 사건 목록" 링크를 둬 줘.
불러오는 동안은 "사건 정보를 불러오고 있어요."를, 실패하면 "사건을 불러오지 못했습니다."와 오류 문구, "다시 조회" 단추를 보여 줘.
```
확인: 주소창에 `http://127.0.0.1:8765/#records/R-101`을 치면 그 사건의 장소가 제목으로 보인다. `#records/R-999`는 불러오지 못했다는 문구와 "다시 조회" 단추가 보인다.

## 3-4. 사건 목록에서 상세로 가기
사건 목록에서 상세 화면으로 가는 길을 만듭니다.
```text
사건 목록 표의 사건 번호를 누르면 그 사건의 상세 화면으로 가게 해 줘.
표 끝에 "이동" 칸을 만들고 "상세 보기" 단추를 넣어 줘. 사진 수 앞에는 "버전" 칸을 넣어 v1, v2처럼 보여 줘.
```
확인: 사건 목록에서 사건 번호나 "상세 보기"를 누르면 상세 화면이 열리고, 버전 칸에 v1이 보인다.

## 3-5. 등록한 뒤 상세로 가기
```text
사건 등록에 성공하면 방금 등록한 사건의 상세 화면으로 바로 가게 해 줘.
```
확인: 사진을 골라 사건을 등록하면 새 사건 번호의 상세 화면이 열린다.

## 3-6. 상세 화면의 사진 구역
```text
사건 상세 화면 왼쪽에 "확인할 사진" 구역을 만들어 줘. 위에 장소와 "사진 총 N장"을 보여 줘.
첫 사진을 크게 보여 주고 사진 아래쪽에 "사진 1 / N"을 표시해 줘. 사진을 불러오지 못하면 "사진을 불러오지 못했습니다."를 보여 줘.
사진이 2장 이상이면 큰 사진 아래에 작은 사진 단추를 장수만큼 두고, 누르면 큰 사진과 "사진 n / N"이 그 사진으로 바뀌게 해 줘.
```
확인: 사진 2장 이상으로 등록한 사건에서 작은 사진을 누르면 큰 사진과 번호가 바뀐다. 1장짜리 사건에는 작은 사진 단추가 없다.

## 3-7. 사진 아래 메모와 사진 출처
```text
상세 화면의 사진 아래에 "현장 메모: …"를 보여 줘. 메모가 없으면 그 줄은 빼 줘.
저장소 사진으로 등록한 사건은 메모 끝에 붙은 사진 출처 부분을 메모에서 떼고, "사진 출처"라는 접힌 칸 안에 넣어 줘.
```
확인: 저장소 사진으로 등록한 사건은 사진 아래에 메모가 보이고, "사진 출처"를 펼치면 출처 글이 나온다.

## 3-8. 확인 순서와 "내 판단 남기기" 칸
```text
상세 화면 제목 아래에 "이 사진에서 확인할 점을 살펴보고, 처리할 내용을 남겨주세요."와 확인 순서 "1. 사진", "2. 내 판단 남기기"를 보여 줘.
지금 할 단계(사진이 있으면 2)를 눈에 띄게 하고, 그 아래에 "사진과 사건 정보를 확인하고, 직접 확인한 판단을 남겨주세요."를 보여 줘.
사진 구역 오른쪽에 "2. 내 판단 남기기" 칸을 만들고 "문제가 있는지, 기준에 맞는지, 더 확인해야 하는지 선택합니다."와 "판단 기록하기" 단추를 넣어 줘.
"판단 기록하기"는 #records/사건번호/review 주소로 가게만 해 줘. 판단 화면은 다음 단계에서 만들어.
```
확인: 상세 화면에 "1. 사진", "2. 내 판단 남기기"가 보이고 2가 강조되어 있다. 오른쪽에 "판단 기록하기" 단추가 있다.

## 3-9. 이전 기록과 사건 정보 (이력)
```text
상세 화면 맨 아래에 "이전 기록과 사건 정보"라는 접힌 칸을 만들어 줘.
펼치면 사건 ID, 버전(v1), 최종 수정 시각을 보여 주고, 그 아래 "감사 이력" 표에 일시, 단계, 작업, 내용, 작업자를 보여 줘.
단계는 화면에 "사진 등록", "정보 수정", "내 판단", "조치 기록"으로 보여 줘. 이력이 없으면 "감사 이력이 없습니다."를 보여 줘.
```
확인: 3-2 뒤에 등록한 사건은 펼쳤을 때 "사진 등록 · 사건 등록 · 사진 N장 보존 완료" 줄이 보인다. 그 전에 등록한 사건은 "감사 이력이 없습니다."가 보인다.

## 3-10. 사건 정보 수정 API (서버)
```text
사건 정보를 고치는 API(PATCH /api/records/사건번호)를 만들어 줘. 장소, 분류, 현장 메모만 바꿀 수 있고 다른 값은 무시해 줘.
저장할 때마다 버전을 1 올리고 마지막 수정 시각을 지금으로 바꿔 줘. 장소가 비면 "장소를 입력해 주세요.", 분류가 둘 중 하나가 아니면 "분류는 산업안전 또는 택배 발송 확인 중에서 골라 주세요."로 거절해 줘.
이력에 "사건 정보 수정"(작업자 "현장 작업자")을 남기고, 내용에 바뀐 항목의 이전 값과 새 값을 적어 줘(예: 수정(v1->v2) [장소: 창고 A->창고 B]). 바뀐 것이 없으면 [정보 갱신]으로 적어 줘.
등록 때처럼 요청 번호를 받아서, 같은 요청이 두 번 와도 한 번만 고쳐지게 해 줘.
```
확인: 아직 화면이 없으므로 서버만 다시 켜 둔다. 다음 단계에서 화면으로 확인한다.

## 3-11. 저장소 사진 출처 지키기 (서버)
```text
저장소 사진으로 등록한 사건은 메모 끝에 사진 출처가 붙어 있어. 정보 수정으로 이 출처를 바꾸거나 지우지 못하게 해 줘.
수정 요청의 메모에서는 출처 앞부분만 쓰고, 저장되어 있던 출처를 글자 그대로 다시 뒤에 붙여 줘.
이력에 메모의 이전 값과 새 값을 적을 때도 출처를 뺀 메모만 비교하고 적어 줘. 출처만 같고 메모가 그대로면 메모는 바뀐 것으로 치지 마.
```
확인: 서버를 다시 켠다. 다음 단계에서 저장소 사진 사건의 메모를 고쳐도 "사진 출처"가 그대로 남는지 본다.

## 3-12. 정보 수정 화면
```text
상세 화면 제목 아래 분류·등록 시각 옆에 "정보 수정" 링크를 두고, #records/사건번호/edit 수정 화면으로 가게 해 줘.
수정 화면 제목은 "사건 정보 수정 · 사건번호"로 하고, 현재 버전과 저장하면 될 버전(v1이면 v2)을 보여 줘. 화면 위에는 "← 사건 상세" 링크를 둬 줘.
장소, 분류, 현장 메모 칸에 지금 값을 채워 두고, 메모 칸에는 사진 출처를 빼고 보여 줘. 출처는 칸 아래 "사진 출처"로 읽기만 하게 해 줘.
"수정 내용 저장" 단추와 "취소하고 상세로 복귀" 단추를 둬 줘. 저장 동작은 다음 단계에서 만들고, 지금은 눌러도 화면이 다시 읽히지 않게만 해 줘.
```
확인: 상세의 "정보 수정"을 누르면 지금 값이 채워진 수정 화면이 열린다. 저장소 사진 사건은 메모 칸에 출처가 없고 아래 "사진 출처"에 있다. "취소하고 상세로 복귀"를 누르면 상세로 돌아간다.

## 3-13. 정보 수정 저장하기
판단·조치 화면도 이 단계와 같은 방식으로 저장합니다.
```text
"수정 내용 저장"을 누르면 3-10의 API로 저장하고 상세 화면으로 돌아가 줘. 저장하는 동안은 단추를 꺼서 두 번 눌러도 한 번만 저장되게 해 줘.
저장한 뒤에는 사건 목록도 서버에서 다시 불러와서, 새로 고침하지 않아도 목록과 홈 숫자가 바로 바뀌게 해 줘.
상세 화면으로 돌아간 뒤 화면 위에 "사건 정보가 수정되었습니다 (v2)"를 문구로 보여 줘(브라우저 팝업 창은 쓰지 마). 실패하면 수정 화면에 남아 "수정 실패:"와 서버 오류 문구를 화면에 보여 줘.
```
확인: 장소를 바꿔 저장하면 상세 제목이 새 장소로 바뀌고 화면 위에 수정 문구가 보인다. 새로 고침 없이 사건 목록 버전 칸이 v2이고, 이력에 "정보 수정" 줄이 생긴다. 장소를 비우고 저장하면 "장소를 입력해 주세요."가 나온다.

## 3-14. 판단 저장 API (서버)
```text
판단을 저장하는 API(POST /api/records/사건번호/review)를 만들어 줘. 판정 결과, 판단 근거, 후속 확인 메모, 검토자를 받아.
판정 결과는 "위험 확인", "기준 충족", "판단 보류", "해당 없음" 넷 중 하나만 받고, 판단 근거가 비면 "판단 근거를 입력해 주세요."로 거절해 줘.
판단은 덮어쓰지 말고 차례로 쌓아 두고, 사건 불러오기(3-1)에서는 가장 마지막 판단을 돌려줘.
이력에 "사람 최종 판정" 한 줄을 남겨 줘. 내용은 "판정 결과 (판단 근거)", 작업자는 검토자 이름이야. 같은 요청이 두 번 와도 한 번만 저장해 줘.
```
확인: 서버를 다시 켜 둔다. 다음 단계에서 화면으로 확인한다.

## 3-15. 내 판단 남기기 화면
```text
"판단 기록하기"를 누르면 열리는 #records/사건번호/review 화면을 만들어 줘. 제목은 "내 판단 남기기", 위에 "← 사건 상세" 링크를 둬 줘.
양식 위에는 그 사건의 첫 사진 작게, 장소, 지금 판단(없으면 "아직 판단을 남기지 않았습니다.")을 보여 줘.
칸은 판정 결과(네 가지 중 선택, 처음엔 "직접 확인한 판단을 선택해 주세요"), 판단 근거(필수), 후속 확인 메모, 검토자(기본 "물류창고 담당자")야. 이전 판단이 있으면 그 값을 채워 둬.
"판단 기록 저장"은 정보 수정 저장(3-13)과 같은 방식으로 저장하고, 상세로 돌아간 뒤 화면 위에 "판단 기록이 저장되었습니다."를 문구로 보여 줘. "취소하고 상세로 복귀" 단추도 둬 줘.
```
확인: 판정 결과를 고르고 근거를 써서 저장하면 상세 화면으로 돌아오고 화면 위에 저장 문구가 보이며, 이력에 "내 판단" 줄이 생긴다. 근거를 비우면 저장되지 않는다.

## 3-16. 상세에 내 판단 보여 주기
```text
상세 화면의 "2. 내 판단 남기기" 칸에 마지막 판단이 있으면 판정 결과를 굵게, 그 아래 판단 근거를 보여 줘.
판단이 있으면 단추 이름을 "판단 다시 기록하기"로 바꿔 줘. 판정이 "판단 보류"면 "추가 확인: 후속 확인 메모(없으면 판단 근거)"를 한 줄 더 보여 줘.
```
확인: 판단을 남긴 사건의 상세 화면에 판정 결과와 근거가 보이고 단추가 "판단 다시 기록하기"로 바뀐다.

## 3-17. 사건 상태 계산 (서버)
판단에 따라 사건이 어느 대기열(큐)에 들어가는지 서버가 정합니다.
```text
사건 목록 API와 사건 불러오기 API에서 사건마다 상태(큐)를 계산해 같이 돌려줘. 마지막 판단 기준으로 정해 줘.
판단이 없으면 "검토 대기", "판단 보류"면 "추가 확인", "위험 확인"이면 "대응 필요"야. "기준 충족"과 "해당 없음"은 어느 큐에도 넣지 마(확인 완료).
사건 목록 API에는 세 큐(추가 확인, 검토 대기, 대응 필요)의 사건 수도 같이 돌려줘.
```
확인: 서버를 다시 켜고 `http://127.0.0.1:8765/api/records`를 열면 세 큐의 숫자가 보이고, 판단 보류한 사건은 추가 확인 쪽에 세어진다.

## 3-18. 상태 배지
```text
사건 목록의 상태 칸과 상세 화면 제목 아래에 사건 상태 배지를 보여 줘. 상세에서는 "상태: 배지" 형식으로 써 줘.
큐에 있으면 "추가 확인", "검토 대기", "대응 필요"로 보여 줘. 큐에 없으면 판정 결과 이름("기준 충족", "해당 없음")을 보여 줘.
```
확인: 판정을 "위험 확인"으로 남긴 사건은 목록과 상세에서 "대응 필요", "기준 충족"으로 남긴 사건은 "기준 충족"으로 보인다.

## 3-19. 확인 이유
```text
상세 화면의 상태 배지 옆 괄호 안에 확인 이유를 보여 줘.
검토 대기는 "사진과 사건 정보를 확인하고 판단을 남겨주세요", 대응 필요는 "확인된 위험의 대응 기록을 확인하세요"야.
추가 확인(판단 보류)은 판단 근거(없으면 후속 확인 메모), 큐에 없는 사건은 판단 근거(없으면 "확인이 완료된 사건입니다")를 보여 줘.
```
확인: 판단하지 않은 사건 상세에 "(사진과 사건 정보를 확인하고 판단을 남겨주세요)"가 보인다.

## 3-20. 홈의 큐 단추 세 개
```text
홈의 "확인이 필요한 현장"에 큐 단추를 "추가 확인", "검토 대기", "대응 필요" 세 개로 두고 각 사건 수를 보여 줘.
아무 단추도 누르지 않았을 때는 세 큐의 사건을 모두 보여 주고, 추가 확인, 검토 대기, 대응 필요 순서로, 같은 큐 안에서는 먼저 등록한 사건이 앞에 오게 해 줘.
단추를 누르면 그 큐만 보이고, 같은 단추를 다시 누르면 다시 전체로 돌아가게 해 줘. 판단이 끝난 사건(큐 없음)은 카드에 나오지 않아.
```
확인: 판단하지 않은 사건 하나를 "위험 확인"으로 판단하면 홈의 검토 대기 숫자가 1 줄고 대응 필요가 1 는다. "대응 필요"를 누르면 대응 필요 사건만 보이고(3-18에서 만든 사건까지 2건일 수 있다), 한 번 더 누르면 전체로 돌아온다.

## 3-21. 홈 카드에서 상세로 가기
홈 카드에서 상세 화면으로 가는 단추를 만듭니다.
```text
홈 카드에는 등록 시각 대신 "확인 이유:" 줄을 두고 3-19와 같은 확인 이유를 보여 줘.
카드 아래에 그 사건의 상세 화면으로 가는 단추를 둬 줘. 이름은 판단이 없으면 "확인 시작", 대응 필요면 "조치 기록", 판단이 있는데 추가 확인이면 "이어서 확인"이야.
```
확인: 홈 카드의 단추를 누르면 그 사건 상세가 열린다. 판단하지 않은 사건 카드의 단추는 "확인 시작"이다.

## 3-22. 홈의 최근 확인한 사건
```text
홈 아래쪽에 "최근 확인한 사건" 표를 보여 줘. "최근 등록한 사건" 표가 있으면 이 표로 바꿔 줘.
큐에 없는(확인을 마친) 사건 중 가장 최근에 판단(또는 조치 완료)한 것 3건까지 보여 줘.
칸은 사건 번호(누르면 상세로), 장소, 분류, 최종 상태(상태 배지), 이동("확인" 단추)이야. 그런 사건이 없으면 표를 숨겨 줘.
```
확인: "기준 충족"으로 판단한 사건이 홈 아래 "최근 확인한 사건"에 나오고, 사건 번호를 누르면 상세가 열린다.

## 3-23. 조치 저장 API (서버)
```text
조치를 저장하는 API(POST /api/records/사건번호/actions)를 만들어 줘. 조치 유형, 조치 내용, 완료 증빙 메모, 담당자(기본 "현장 담당자")를 받아.
조치 유형은 "조치 요청"과 "조치 완료" 둘만 받고, 조치 내용이 비면 "조치 내용을 입력해 주세요."로 거절해 줘.
"조치 완료"인데 완료 증빙 메모가 비면 "조치 완료를 기록하려면 완료 증빙 메모를 입력해 주세요."로 거절해 줘.
조치는 차례로 쌓고, 이력에 "조치 요청" 또는 "조치 완료" 한 줄을 남겨 줘. 내용은 "조치 내용 (완료근거: 증빙 메모, 없으면 미등록)"이야. 같은 요청이 두 번 와도 한 번만 저장해 줘.
```
확인: 서버를 다시 켜 둔다. 다음 단계에서 화면으로 확인한다.

## 3-24. 조치 기록 화면
```text
#records/사건번호/action 조치 기록 화면을 만들어 줘. 제목은 "조치 기록", 위에 "← 사건 상세" 링크와 3-15처럼 사건 사진·장소·지금 판단을 보여 줘.
칸은 조치 유형(조치 요청/조치 완료), 조치 내용(필수), 완료 증빙 메모(완료 시 필수), 담당자(기본 "현장 담당자")야.
"요청을 전달한 것만으로 완료 처리하지 말고, 후속 확인 사진이나 담당자 서명 같은 증빙을 남겨야 한다"는 주의 문구를 넣어 줘.
"조치 기록 저장"은 3-13과 같은 방식으로 저장하고, 상세로 돌아간 뒤 화면 위에 "조치 기록이 저장되었습니다."를 문구로 보여 줘. 조치 완료인데 증빙이 비면 보내지 말고 화면에 문구로 알려 줘.
```
확인: 다음 단계에서 상세의 단추로 들어와 확인한다.

## 3-25. 상세의 조치 단추와 최근 조치
```text
상세 화면 "2. 내 판단 남기기" 칸에서, 상태가 대응 필요면 "조치 기록하기" 단추를, 아니고 조치 기록이 있으면 "조치 추가 기록" 단추를 보여 줘. 둘 다 조치 기록 화면으로 가.
조치 기록이 있으면 "최근 조치" 제목 아래 마지막 조치 내용을 보여 줘.
"이전 기록과 사건 정보" 안에는 조치가 2건 이상일 때 "전체 대응 조치 이력" 표(유형, 내용, 완료 증빙, 담당자, 일시)를 보여 줘.
```
확인: "대응 필요" 사건 상세에서 "조치 기록하기"를 눌러 "조치 요청"을 저장하면 최근 조치에 그 내용이 보이고, 이력에 "조치 기록" 줄이 생긴다.

## 3-26. 조치 완료하면 확인 완료로 (서버)
```text
상태 계산에 규칙을 더해 줘. "위험 확인" 판단 뒤에 완료 증빙이 있는 "조치 완료"를 기록하면 그 사건은 큐에서 빠져(확인 완료).
"조치 요청"만 있거나, 조치 완료가 판단보다 먼저였거나, 시각을 비교할 수 없으면 확인 완료로 치지 마. 시각을 비교할 수 없을 때는 "추가 확인"으로 둬 줘.
화면의 상태 배지는 이렇게 끝난 사건을 "완료 기록 있음"으로, 확인 이유는 "대응 조치 완료가 확인된 사건입니다"로 보여 줘.
```
확인: 대응 필요 사건에 "조치 완료"를 증빙과 함께 저장하면 홈의 대응 필요 숫자가 1 줄고, 그 사건이 "최근 확인한 사건"에 "완료 기록 있음"으로 나온다.

## 3-27. 판단 뒤에 정보를 고치면 다시 확인
```text
판단이나 조치를 남긴 뒤에 사건 정보를 고치면(버전이 오르면) 그 사건을 "추가 확인"으로 보내 줘. 확인 이유는 "판단 후 정보가 바뀌어 다시 확인해야 합니다"야.
이때 상세 화면 위에 "정보가 수정됐습니다. 현재 사진과 내용을 다시 확인해 주세요." 경고 문구를 보여 주고, 판단 칸에는 "수정 전 결과입니다. 현재 사진과 내용을 다시 확인해 주세요."를 보여 줘.
수정 시각보다 나중에 판단을 다시 남기면 그 새 판단으로 상태를 정해 줘. 버전이 2 이상인데 수정 시각을 알 수 없으면 "추가 확인"으로 둬 줘.
```
확인: "기준 충족"으로 판단한 사건의 장소를 고치면 홈 추가 확인 숫자가 1 늘고 상세에 경고가 보인다. "판단 다시 기록하기"로 다시 저장하면 경고가 사라진다.

## 3-28. 상태에 맞는 안내 문구
```text
상세 화면 확인 순서 아래 안내 문구를 상태에 따라 바꿔 줘.
대응 필요면 "어떤 조치를 했는지 기록해 주세요.", 판단이 끝났고 추가 확인이 아니면 "판단이 저장됐습니다. 기록을 다시 확인할 수 있습니다."를 보여 줘. 그 밖에는 지금 문구 그대로야.
대응 필요나 판단이 끝난 상태에서는 확인 순서의 "2. 내 판단 남기기"를 강조하지 마.
```
확인: 대응 필요 사건 상세에 "어떤 조치를 했는지 기록해 주세요."가, 기준 충족 사건 상세에 "판단이 저장됐습니다."가 보인다.

## 3-29. 연동 상태 줄
```text
서버를 켜면 "현장 리스크 대시보드: http://127.0.0.1:8765" 다음 줄에 "연동 상태: 저장소 로컬 저장"을 찍어 줘.
/api/health 응답에도 이 줄을 같이 넣어 줘. 화면은 시작할 때 /api/health를 읽어 이 줄을 받아 와.
머리말의 "데이터 연결됨" 표시는 그대로 두고, 화면 본문 맨 위 알림 자리에 처리 중이나 오류가 없을 때 "연동 상태: 저장소 로컬 저장"을 보여 줘.
```
확인: 서버를 다시 켜면 터미널에 "연동 상태: 저장소 로컬 저장"이 나오고, 화면 본문 위에도 같은 글이 보인다. 머리말에는 "데이터 연결됨"이 그대로 있다.

## 3-30. 처음부터 끝까지 확인 (직접 하기)
서버를 다시 켜고 아래를 차례로 해 봅니다.
1. 새 사건을 등록하면 상세가 열리고 상태가 "검토 대기"인지 봅니다.
2. "판단 보류"로 판단하면 "추가 확인", 다시 "위험 확인"으로 판단하면 "대응 필요"가 되는지 봅니다.
3. "조치 요청"을 저장해도 "대응 필요"로 남고, "조치 완료"를 증빙과 함께 저장하면 "완료 기록 있음"이 되는지 봅니다.
4. 장소를 고치면 버전이 오르고 "추가 확인"과 경고가 보이는지, 이력에 사진 등록·내 판단·조치 기록·정보 수정 줄이 모두 남았는지 봅니다.
확인: 단계마다 홈의 세 숫자가 상태에 맞게 바뀐다. 서버를 껐다 켜도 판단·조치·이력이 그대로 있다.

## 회차 끝 확인
- [ ] 사건 목록의 사건 번호, 홈 카드 단추, 등록 성공 뒤 이동으로 사건 상세가 열린다.
- [ ] 상세에서 사진(여러 장이면 작은 사진으로 바꾸기), 메모, 사진 출처, 확인 순서 "1. 사진 / 2. 내 판단 남기기"가 보인다.
- [ ] 정보 수정으로 장소·분류·메모를 고치면 버전이 오르고 사진 출처는 그대로 남는다.
