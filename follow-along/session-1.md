# 1회차: 준비와 화면 틀, 확인 기준 목록

- 시작 상태: 수업 저장소의 `milestone-0` 브랜치에서 시작합니다. 안내 파일, 강사가 준 자료(`materials` 폴더), 프로젝트 규칙(`AGENTS.md`), 1회차 보충 문서(`docs/guide` 폴더)만 있고 코드는 하나도 없습니다.
- 끝나면 되는 것: `npm.cmd start`로 서버를 켜면 브라우저에 화면 틀(머리말, 홈, 확인 기준 화면)이 보이고, 확인 기준 화면에 기준 9개가 표로 나옵니다. 만든 코드는 내 작업 브랜치(`my-work`)에 저장합니다.
- 준비물: 인터넷이 되는 Windows 10·11 PC, 수업에 쓸 Google 계정 1개. 프로그램은 아래 "시작 전에"에서 설치합니다.

## 먼저 알아 둘 말

- **AI**: 프롬프트를 붙여 넣는 AI 도구입니다. 이 파일에서는 그냥 "AI"라고 부릅니다.
- **서버**: 앱 뒤에서 일하는 프로그램입니다. 서버를 켜 두면 Chrome에서 http://127.0.0.1:8765 주소로 앱을 엽니다.
- **터미널**: 명령을 치는 검은 창입니다. 이 수업에서는 시작 메뉴에서 여는 PowerShell 창을 씁니다.
- **서버 창**: 서버를 켜 두는 PowerShell 창입니다. 1-3에서 하나 정하고, 수업 내내 서버는 이 창에서만 켜고 끕니다. 다른 명령은 서버 창이 아닌 터미널에서 칩니다.
- **프로젝트 폴더**: `C:\vision-ai\vision-risk-dashboard-student`입니다. AI 도구에서 이 폴더를 열어 두고 작업합니다.
- **지침**: AI가 일하는 방식을 적은 `AGENTS.md` 파일입니다. 수업 저장소에 이미 들어 있고, 1-1에서 AI에게 이 지침을 따르게 합니다.
- **보충 문서**: 주소, 화면 문구, 거절 규칙처럼 세부 조건을 적은 문서입니다. `docs/guide` 폴더에 있습니다. 프롬프트는 무엇을 만들지 큰 그림만 말하고, 세부 조건은 AI가 이 문서를 찾아 따릅니다. 사람은 읽지 않아도 따라 할 수 있습니다.

## 시작 전에 (프롬프트 없이 직접 합니다)

1. 프로그램 설치: 아래를 모두 기본값으로 설치합니다.
   - Chrome
   - Node.js: nodejs.org에서 Node.js 24 LTS의 Windows 설치 파일(.msi)을 받아 설치합니다. 22.9 이상이면 됩니다.
   - Git for Windows: git-scm.com/download/win 에서 받아 설치합니다.
   - AI 도구: 강사가 안내한 AI 도구를 설치하고 로그인합니다.
   - 탐색기 보기 메뉴에서 "파일 확장명"을 켭니다.
2. 설치 확인: 열려 있던 터미널과 AI 도구를 모두 닫습니다. 시작 메뉴에서 새 PowerShell을 열고 `node -v`와 `git --version`을 차례로 칩니다. `v24.`처럼 22.9 이상인 번호와 `git version`으로 시작하는 줄이 나와야 합니다. "인식되지 않습니다"가 나오면 PowerShell을 닫고 다시 엽니다.
3. 수업 저장소 받기: 같은 PowerShell에서 아래를 한 줄씩 칩니다. 바탕 화면이나 문서 폴더(OneDrive가 동기화하는 곳), 한글이 든 경로는 쓰지 않습니다. 마지막 두 줄은 출발점 브랜치로 옮긴 뒤 내 작업 브랜치(`my-work`)를 만듭니다.

```powershell
mkdir C:\vision-ai
cd C:\vision-ai
git clone https://github.com/startup-life/vision-risk-dashboard-student.git
cd vision-risk-dashboard-student
git switch milestone-0
git switch -c my-work
```

   다 치고 `dir`을 치면 `AGENTS.md`, `README.md`, `docs`, `materials`가 보여야 합니다.
4. AI 도구로 폴더 열기: AI 도구에서 프로젝트 폴더 `C:\vision-ai\vision-risk-dashboard-student`를 엽니다. 폴더를 신뢰할지 물으면 신뢰합니다. AI가 명령을 실행하기 전에 내 승인을 받게 합니다(도구마다 메뉴가 다릅니다). 그다음 새 대화를 시작합니다.
5. 탐색기로 폴더 열기: 탐색기에서도 프로젝트 폴더를 열어 둡니다. 파일이 생겼는지는 이 창에서 봅니다. `AGENTS.md`, `README.md`, `docs`, `materials`가 보이면 됩니다.

## 진행 방법

- 프롬프트 상자 하나를 통째로 복사해 AI에게 붙여 넣습니다. 앞 번호가 끝난 뒤에 다음 번호를 보냅니다.
- AI가 파일을 만들거나 명령을 실행해도 되는지 물으면 승인합니다. 서버를 켜겠다고 하면 거절합니다. `Set-ExecutionPolicy`, `npm audit fix`처럼 컴퓨터 설정이나 프로그램 버전을 바꾸는 명령은 승인하지 말고 강사에게 알립니다.
- "직접 하기"는 AI에게 보내지 않고 내가 직접 합니다.
- 서버를 켠 뒤로는 번호가 끝날 때마다 서버 창에서 Ctrl+C로 끄고(물으면 `Y`) `npm.cmd start`로 다시 켠 다음, 브라우저를 새로고침(F5)하고 "확인"을 봅니다.
- "확인"과 다르게 나오면 화면의 글이나 서버 창의 빨간 줄을 그대로 복사해 "이렇게 나와요. 고쳐 주세요."와 함께 AI에게 붙여 넣습니다.
- 답이 이상해지면 새 대화를 열고 1-1의 프롬프트를 다시 보낸 뒤, 하던 번호부터 이어 갑니다.
- 화면 색과 배치는 예시와 달라도 됩니다. "확인"에 적힌 글과 동작만 같으면 됩니다.

## 1-1. 지침 세팅

```text
이 프로젝트의 AGENTS.md를 작업 지침으로 삼아 주세요. 프롬프트에 없는 세부 조건(주소, 화면 문구, 파일 이름, 거절 규칙)은 docs/guide의 회차 문서에서 찾아 따릅니다.
지금은 AGENTS.md와 docs/guide/session-1.md를 읽기만 하고, 읽은 파일 이름만 한 줄로 알려 주세요.
```
- 확인: AI 답에 `AGENTS.md`와 `session-1.md`가 나옵니다. 새 대화를 열 때마다 이 프롬프트를 먼저 보냅니다.

## 1-2. 앱 뼈대

```text
"현장 리스크 대시보드" 웹앱의 뼈대를 만들어 주세요. `npm.cmd start`로 켜는 8765번 서버와, 머리말·홈·확인 기준 화면이 있는 한 페이지 화면입니다.
머리말에는 강사가 준 로고와 앱 이름을 두고, 홈의 "확인 기준 보기" 단추를 누르면 확인 기준 화면으로 갑니다. 확인 기준 표는 다음 번호에서 만듭니다.
자세한 내용은 docs/guide/session-1.md를 참고해 주세요.
```
- 확인: 프로젝트 폴더에 `package.json`, `server` 폴더, `public` 폴더가 생기고, AI가 서버를 켜지 않고 켜는 명령만 알려 줍니다.

## 1-3. 서버 켜고 화면 보기 (직접 하기)

프롬프트는 없습니다.
- 직접 하기: 시작 메뉴에서 PowerShell 창을 새로 열고 아래를 칩니다. 이 창이 서버 창입니다.

```powershell
cd C:\vision-ai\vision-risk-dashboard-student
npm.cmd start
```

- 직접 하기: Chrome에서 http://127.0.0.1:8765 를 엽니다.
- 확인: 서버 창에 `현장 리스크 대시보드: http://127.0.0.1:8765`가 나오고, 탭 제목이 "Vision QC", 머리말에 로고와 "현장 리스크 대시보드", 홈에 "현장 리스크 확인"과 "확인 기준 보기" 단추가 보입니다.
- 확인: "확인 기준 보기"를 누르면 "확인 기준" 화면이 나오고, "← 홈으로"나 로고를 누르면 홈으로 돌아옵니다.

## 1-4. 확인 기준 표

```text
강사가 준 확인 기준 9개를 서버가 돌려주게 하고, 확인 기준 화면에 표로 보여 주세요.
머리말 오른쪽에는 서버 연결 상태를, 화면 내용 위에는 처리 중이나 오류를 알리는 줄을 둡니다.
자세한 내용은 docs/guide/session-1.md를 참고해 주세요.
```
- 확인: 확인 기준 화면에 "택배 발송·산업안전 기준" 상자와 표가 보이고, 항목 칸이 "C-01 · 머리 보호구"부터 "C-09 · 배송 라벨·주문 대조"까지 9줄 나옵니다. 머리말 오른쪽에 "데이터 연결됨"이 보입니다.

## 1-5. 설정 파일 읽기


## 1-6. 내 코드 남겨 두기 (직접 하기)

프롬프트는 없습니다.
- 직접 하기: 서버를 끄고 터미널에서 아래를 한 줄씩 칩니다. 앞의 두 줄은 처음 한 번만 치고, 따옴표 안에 내 이름과 메일 주소를 넣습니다. 이 두 줄은 이 프로젝트에만 적용됩니다.

```powershell
git config user.name "내 이름"
git config user.email "내 메일 주소"
git add -A
git commit -m "1회차 화면 틀과 확인 기준"
```

- 확인: `git status`를 치면 "nothing to commit"이 나옵니다.

- [ ] http://127.0.0.1:8765 의 머리말에 로고, "현장 리스크 대시보드", "데이터 연결됨"이 보인다.
- [ ] 홈의 "확인 기준 보기"를 누르면 확인 기준 화면으로 가고, 표에 C-01~C-09 기준 9개가 나온다.
- [ ] 1-6에서 내 코드를 커밋했다.

다 끝내지 못했으면 2회차 전에 서버를 끄고 터미널에서 아래를 한 줄씩 칩니다. 내가 만든 코드는 `my-work` 브랜치에 남고, 완료 브랜치 `milestone-1`로 옮겨 갑니다. 이 브랜치에는 `AGENTS.md`와 2회차 보충 문서까지 들어 있으니, 2회차 "시작 전에"의 문서 받기는 건너뜁니다. 1-6을 하지 못했으면 아래 `cd` 줄을 친 다음 1-6의 앞 두 줄(`git config`)을 치고 이어 갑니다. `git commit`에서 "nothing to commit"이 나와도 그대로 다음 줄을 칩니다.

```powershell
cd C:\vision-ai\vision-risk-dashboard-student
git add -A
git commit -m "1회차 내 작업"
git fetch origin
git switch milestone-1
npm.cmd install
```
