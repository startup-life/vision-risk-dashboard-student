# 1회차: 준비와 화면 틀, 확인 기준 목록

- 시작 상태: 수업 저장소의 `milestone-0` 브랜치에서 시작합니다. 안내 파일, 강사가 준 자료(`materials` 폴더), 프로젝트 규칙(`AGENTS.md`), 1회차 보충 문서(`docs/guide` 폴더)만 있고 코드는 하나도 없습니다.
- 끝나면 되는 것: `npm.cmd start`로 서버를 켜면 브라우저에 화면 틀(머리말, 홈, 확인 기준 화면)이 보이고, 확인 기준 화면에 기준 9개가 표로 나옵니다. 만든 코드는 내 작업 브랜치(`my-work`)에 저장합니다.
- 준비물: 인터넷이 되는 Windows 10·11 PC, 수업에 쓸 Google 계정 1개. 프로그램은 아래 "시작 전에"에서 설치합니다.

## 먼저 알아 둘 말

- **AI**: 프롬프트를 붙여 넣는 AI 도구입니다. 이 파일에서는 그냥 "AI"라고 부릅니다.
- **서버**: 앱 뒤에서 일하는 프로그램입니다. 서버를 켜 두면 Chrome에서 http://127.0.0.1:8765 주소로 앱을 엽니다.
- **터미널**: 명령을 치는 검은 창입니다. 이 수업에서는 시작 메뉴에서 여는 PowerShell 창을 씁니다.
- **서버 창**: 서버를 켜 두는 PowerShell 창입니다. 1-6에서 하나 정하고, 수업 내내 서버는 이 창에서만 켜고 끕니다. 다른 명령은 서버 창이 아닌 터미널에서 칩니다.
- **프로젝트 폴더**: `C:\vision-ai\vision-risk-dashboard-student`입니다. AI 도구에서 이 폴더를 열어 두고 작업합니다.
- **프로젝트 규칙**: AI가 일하는 방식을 적은 `AGENTS.md` 파일입니다. 수업 저장소에 이미 들어 있습니다. 새 대화를 시작할 때 AI에게 읽으라고 알립니다.
- **보충 문서**: 주소, 화면 문구처럼 프롬프트에 없는 내용을 적은 문서입니다. `docs/guide` 폴더에 있고, AI가 읽고 그대로 만듭니다. 사람이 읽어도 되지만 읽지 않아도 따라 할 수 있습니다.

## 시작 전에 (프롬프트 없이 직접 합니다)

1. 프로그램 설치: 아래를 모두 기본값으로 설치합니다.
   - Chrome
   - Node.js: nodejs.org에서 Node.js 24 LTS의 Windows 설치 파일(.msi)을 받아 설치합니다. 22.9 이상이면 됩니다.
   - Git for Windows: git-scm.com/download/win 에서 받아 설치합니다.
   - AI 도구: 강사가 안내한 AI 도구를 설치하고 로그인합니다.
   - 탐색기 보기 메뉴에서 "파일 확장명"을 켭니다.
2. 설치 확인: 열려 있던 터미널과 AI 도구를 모두 닫습니다. 시작 메뉴에서 새 PowerShell을 열고 `node -v`와 `git --version`을 차례로 칩니다. `v24.`처럼 22.9 이상인 번호와 `git version`으로 시작하는 줄이 나와야 합니다. "인식되지 않습니다"가 나오면 PowerShell을 닫고 다시 엽니다.
3. 수업 저장소 받기: 같은 PowerShell에서 아래를 한 줄씩 칩니다. 바탕 화면이나 문서 폴더(OneDrive가 동기화하는 곳), 한글이 든 경로는 쓰지 않습니다. 마지막 두 줄은 출발점 브랜치로 옮긴 뒤 내 작업 브랜치(`my-work`)를 만듭니다.

```powershell
mkdir C:\vision-ai
cd C:\vision-ai
git clone https://github.com/startup-life/vision-risk-dashboard-student.git
cd vision-risk-dashboard-student
git switch milestone-0
git switch -c my-work
```

   다 치고 `dir`을 치면 `AGENTS.md`, `README.md`, `docs`, `materials`가 보여야 합니다.
4. AI 도구로 폴더 열기: AI 도구에서 프로젝트 폴더 `C:\vision-ai\vision-risk-dashboard-student`를 엽니다. 폴더를 신뢰할지 물으면 신뢰합니다. AI가 명령을 실행하기 전에 내 승인을 받게 합니다(도구마다 메뉴가 다릅니다). 그다음 새 대화를 시작합니다. 새 대화에는 아래 "새 대화를 시작할 때"의 프롬프트를 먼저 보냅니다.
5. 탐색기로 폴더 열기: 탐색기에서도 프로젝트 폴더를 열어 둡니다. 파일이 생겼는지는 이 창에서 봅니다. `AGENTS.md`, `README.md`, `docs`, `materials`가 보이면 됩니다.

## 새 대화를 시작할 때

회차를 시작할 때와 새 대화를 열 때마다, 번호가 있는 프롬프트보다 먼저 아래를 한 번 보냅니다. 도구에 따라 이 파일을 저절로 읽지 않을 수 있어서입니다.

```text
AGENTS.md를 읽고 그 안내대로 보충 문서도 읽어 주세요. 읽은 파일 이름만 한 줄로 알려 주세요.
```
- 확인: AI 답에 `AGENTS.md`와 `session-1.md`가 나오고, 2회차부터는 이번 회차 문서 이름도 나옵니다. 앞 회차 문서 이름이 더 나와도 됩니다.

## 진행 방법

- 프롬프트 상자 하나를 통째로 복사해 AI에게 붙여 넣습니다. 앞 번호가 끝난 뒤에 다음 번호를 보냅니다.
- AI가 "이미 되어 있습니다"라고 답하면 그 번호의 "확인"만 해 보고 다음 번호로 넘어갑니다. 보충 문서에 미리 적힌 내용이라 앞 번호에서 먼저 만들어졌을 수 있습니다.
- AI가 파일을 만들거나 명령을 실행해도 되는지 물으면, 보낸 프롬프트와 관계있는 일인지 보고 승인합니다. 서버를 켜겠다고 하면 거절합니다. `Set-ExecutionPolicy`, `npm audit fix`처럼 컴퓨터 설정이나 프로그램 버전을 바꾸는 명령도 승인하지 말고 강사에게 알립니다.
- "직접 하기"는 AI에게 보내지 않고 내가 직접 합니다.
- 서버 끄기: 서버 창에서 Ctrl+C를 누릅니다. "일괄 작업을 끝내시겠습니까 (Y/N)?"가 나오면 `Y`를 칩니다.
- 1-6에서 서버를 처음 켠 뒤로는, 단계가 끝날 때마다 서버를 껐다 켜고(Ctrl+C, 그다음 `npm.cmd start`) 브라우저를 새로고침한 뒤 "확인"을 봅니다. 주소 끝의 # 뒤만 바꿔 화면을 옮기면 새로 고친 화면이 실리지 않으니, 꼭 새로고침(F5)합니다.
- "확인"과 다르게 나오면 화면의 글이나 서버 창의 빨간 줄을 그대로 복사해 "이렇게 나와요. 고쳐 주세요."와 함께 AI에게 붙여 넣습니다.
- 1회차는 한 대화로 이어 가도 됩니다. 답이 이상해지면 새 대화를 엽니다. 새 대화를 열면 위 "새 대화를 시작할 때"의 프롬프트를 먼저 보내고, 그 번호의 프롬프트부터 다시 보냅니다.
- 화면 색과 배치는 예시와 달라도 됩니다. "확인"에 적힌 글과 동작만 같으면 됩니다.

## 1-6. 처음 서버 켜기 (직접 하기)

프롬프트는 없습니다.
- 직접 하기: 시작 메뉴에서 PowerShell 창을 새로 열고 아래를 칩니다. 이 창이 서버 창입니다.

```powershell
cd C:\vision-ai\vision-risk-dashboard-student
npm.cmd start
```

- 직접 하기: Chrome에서 http://127.0.0.1:8765 를 엽니다.
- 확인: 서버 창에 `현장 리스크 대시보드: http://127.0.0.1:8765`가 나오고, Chrome 탭 제목이 "Vision QC", 화면에 "현장 리스크 대시보드"가 보입니다.
- 직접 하기: 서버를 켜 둔 채로 시작 메뉴에서 PowerShell 창을 하나 더 열고, 위 두 줄을 그 창에서 똑같이 칩니다.
- 확인: 새 창에 "8765번 포트를 이미 쓰고 있습니다"로 시작하는 안내가 나오고 끝납니다. 확인했으면 그 새 창은 닫습니다.

## 1-7. 없는 파일과 보내면 안 되는 파일

```text
보충 문서의 "화면 파일 보내기" 절에 적힌 대로, 없는 파일은 "Not found"로 답하고 화면 폴더 밖의 파일, 숨김 파일, 비밀 설정 파일은 거절해 주세요.
풀 수 없는 주소와 널 문자가 든 주소도 그 절에 적힌 대로 답하고 서버는 꺼지지 않게 합니다.
```
- 직접 하기: Chrome에서 http://127.0.0.1:8765/nothing.html 을 엽니다.
- 확인: 화면에 "Not found"가 보입니다.
- 직접 하기: Chrome에서 http://127.0.0.1:8765/%2e%2e%2fpackage.json 을 엽니다.
- 확인: `package.json` 내용(중괄호로 시작하는 글)이 보이지 않고 "Forbidden", "HTTP ERROR 403", "Not found" 같은 짧은 글이 보이면 됩니다.
- 직접 하기: Chrome에서 http://127.0.0.1:8765/%00 을 엽니다.
- 확인: `Malformed URI encoding`, "HTTP ERROR 400", "Not found" 같은 짧은 글이 보이고 서버 창의 서버가 꺼지지 않습니다. 이어서 http://127.0.0.1:8765 를 열면 화면이 그대로 나옵니다.

## 1-8. 다른 사이트 요청 막기와 옛 화면 지우기

```text
보충 문서의 "화면 파일 보내기" 절에 적힌 대로 다른 사이트에서 온 요청은 거절하고, 브라우저가 옛 화면을 기억하지 않게 해 주세요.
파일을 보내는 주소가 받는 요청 방식도 그 절에 적힌 대로 합니다. 이미 된 것은 그대로 둡니다.
```
- 직접 하기: Chrome에서 http://127.0.0.1:8765 를 열고 새로고침합니다.
- 확인: 화면은 그대로 보입니다. 다른 사이트 요청 거절과 옛 화면 지우기는 화면으로 볼 수 없습니다. AI 답에 이 둘을 했다는 말이나 이미 되어 있다는 말이 나오는지 봅니다. 말이 없으면 "이 둘이 되어 있는지 알려 주세요."라고 보냅니다.

## 1-15. 확인 기준 설명


- 확인: 확인 기준 제목 아래에 "물류창고에서"로 시작하고 "확정하지 않습니다."로 끝나는 설명 두 문장이 보입니다.

## 1-16. 제목 옆 홈 단추

## 1-17. 공통 요청 함수와 기준 목록 받아 두기

## 1-18. 확인 기준 표

```text

열 이름과 칸의 글 모양은 보충 문서의 "확인 기준 표" 절에 적힌 대로 합니다.
```

- 확인: 확인 기준 화면을 맨 아래까지 내린 뒤(내려가지 않으면 Chrome 창 높이를 더 줄입니다) 뒤로 가기로 홈에 갔다가 "확인 기준 보기"를 다시 누르면, 화면 맨 위의 길잡이 줄과 제목이 보입니다.

## 1-19. 표 자리의 문구

## 1-24. 설정 파일 시험해 보기 (직접 하기)

프롬프트는 없습니다. 바꿀 때마다 메모장에서 저장하고 서버를 다시 켭니다.
- 직접 하기: 탐색기에서 `config` 폴더의 `local-connection.example.json`을 같은 폴더에 복사하고, 복사본 이름을 `local-connection.json`으로 바꿉니다. 메모장으로 열어 내용을 `{ "TEST_KEY": "abc" }`로 바꿉니다.
- 확인: 서버 창에 `TEST_KEY` 이름만 든 설정 경고가 나오고 `abc`는 나오지 않습니다.
- 직접 하기: 내용을 `{ "TEST_KEY": "abc", }`(끝에 쉼표)로 바꿉니다.
- 확인: 서버 창에 몇 행 몇 열이 틀렸는지 나오고 서버가 켜지지 않습니다.
- 직접 하기: 내용을 `{}`로 되돌립니다.
- 확인: 경고 없이 서버가 켜집니다.
