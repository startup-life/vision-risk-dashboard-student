# 1회차 목표: 준비와 화면 틀, 확인 기준 목록

현장 리스크 대시보드의 화면 틀을 만들고 확인 기준 9개를 표로 보여 줍니다.
빈 폴더에 만든 내 저장소에서 코드 없이 시작하고, 1-2에서 AI가 수업 저장소의 `milestone-0` 브랜치에서 강사가 준 자료(`materials` 폴더), 프로젝트 규칙(`AGENTS.md`), 1회차 보충 문서(`docs/guide` 폴더)를 가져옵니다.
1-4에서 AI가 서버를 켜면 ego 브라우저에 화면 틀(머리말, 홈, 확인 기준 화면)이 보이고, 확인 기준 화면에 기준 9개가 표로 나옵니다. 만든 코드는 내 저장소에 커밋해 둡니다.

## 시작 전에

빈 폴더 `C:\vision-ai\vision-risk-dashboard`에서 시작합니다. 코드는 하나도 없습니다.

준비물: 인터넷이 되는 Windows 10·11 PC, ego 브라우저, 수업에 쓸 Google 계정 1개, 강사에게 초대받은 GitHub 계정(초대 메일의 수락까지 해 둡니다). Node.js와 Git은 1-1에서 AI가 설치합니다. 4회차의 NotebookLM 로그인 명령은 Chrome 창을 열어 로그인하므로 Chrome도 설치해 둡니다.

아래는 직접 합니다.

1. AI 도구: 강사가 안내한 AI 도구를 설치하고 로그인합니다. ego 브라우저와 Chrome도 있어야 합니다.
2. 프로젝트 폴더 만들기: 탐색기에서 `C:\vision-ai\vision-risk-dashboard` 폴더를 만듭니다. 바탕 화면, 문서 폴더, 한글이 든 경로는 쓰지 않습니다.
3. AI 도구로 폴더 열기: AI 도구에서 이 폴더를 엽니다. 폴더를 신뢰할지 물으면 신뢰하고, AI가 명령을 실행하기 전에 내 승인을 받게 합니다(도구마다 메뉴가 다릅니다). 그다음 새 대화를 시작합니다.

## 먼저 알아 둘 말

- **AI**: 프롬프트를 붙여 넣는 AI 도구입니다. 이 파일에서는 그냥 "AI"라고 부릅니다.
- **서버**: 앱 뒤에서 일하는 프로그램입니다. 서버를 켜 두면 ego 브라우저에서 http://127.0.0.1:8765 주소로 앱을 엽니다.
- **터미널**: 명령을 치는 검은 창입니다. 이 수업에서는 시작 메뉴에서 여는 PowerShell 창을 씁니다.
- **서버 창**: AI가 새로 열어 서버를 켠 PowerShell 창입니다. 1-4에서 처음 열립니다. AI가 서버를 다시 켤 때마다 새 서버 창이 열리고, 서버가 꺼진 예전 창은 닫아도 됩니다. 내가 치는 명령은 서버 창이 아닌 터미널에서 칩니다.
- **프로젝트 폴더**: `C:\vision-ai\vision-risk-dashboard`입니다. "시작 전에"에서 빈 폴더로 만들고, AI 도구에서 이 폴더를 열어 두고 작업합니다.
- **수업 저장소**: 강사가 GitHub에 둔 비공개 저장소입니다. 지침, 보충 문서, 강사 자료와 회차별 완료 코드가 들어 있고, 초대받은 GitHub 계정으로만 받을 수 있습니다. 이 프로젝트에서는 `class`라는 이름으로 부릅니다.
- **지침**: AI가 일하는 방식을 적은 `AGENTS.md` 파일입니다. 1-2에서 AI가 수업 저장소에서 가져와 이 지침을 따르게 합니다.
- **보충 문서**: 주소, 화면 문구, 거절 규칙처럼 세부 조건을 적은 문서입니다. `docs/guide` 폴더에 있습니다. 프롬프트는 무엇을 위해 어디에 어떤 기능을 더할지만 말하고, 세부 조건은 AI가 이 문서와 회차 완료 브랜치(1회차는 수업 저장소의 `milestone-1`)의 코드를 찾아 따릅니다. 사람은 읽지 않아도 따라 할 수 있습니다.
- **하는 일·목표·완료 기준**: 단계마다 프롬프트 상자(직접 하는 단계는 번호 매긴 할 일) 아래에 붙은 세 줄입니다. 하는 일은 그 번호로 화면이나 파일에 생기는 것, 목표는 그 번호가 필요한 까닭, 완료 기준은 그 번호가 잘 됐는지 화면이나 PowerShell 창에서 보는 방법입니다.

## 진행 방법

- 프롬프트 상자 하나를 통째로 복사해 AI에게 붙여 넣습니다. 앞 번호가 끝난 뒤에 다음 번호를 보냅니다.
- AI가 "이미 되어 있습니다"라고 답하면 그 번호의 "완료 기준"대로 확인만 해 보고 다음 번호로 넘어갑니다. 앞 번호에서 먼저 만들어졌을 수 있습니다.
- AI가 파일을 만들거나 명령을 실행해도 되는지 물으면 승인합니다. 1-1의 프로그램 설치 말고, `Set-ExecutionPolicy`, `npm audit fix`처럼 컴퓨터 설정이나 프로그램 버전을 바꾸는 명령은 승인하지 말고 강사에게 알립니다.
- "직접 하기"와 직접 하는 단계의 번호 매긴 할 일은 AI에게 보내지 않고 내가 직접 합니다.
- 키, Google 웹앱 주소, 노트북 ID 같은 비밀 값은 설정 파일(`config/local-connection.json`)에만 둡니다. 화면 공유, 메신저, 문서에 옮기지 않습니다. 설정 파일은 Git에 올라가지 않습니다.
- 서버 쪽 파일(server 폴더, package.json, 설정 파일)을 고친 번호는 AI가 마치기 전에 서버를 새 서버 창에서 다시 켭니다. 화면 파일만 바뀐 번호는 서버를 다시 켜지 않습니다. 어느 쪽이든 ego 브라우저에서 새로고침(F5)한 뒤 "완료 기준"을 봅니다. AI가 서버를 다시 켜지 않았는데 완료 기준대로 보이지 않으면 AI에게 "서버를 다시 켜 주세요."라고 보냅니다.
- 서버를 끌 때는 서버 창을 닫거나 그 창에서 Ctrl+C를 누릅니다. "일괄 작업을 끝내시겠습니까 (Y/N)?"가 나오면 `Y`를 칩니다. 다시 켤 때는 AI에게 "서버를 켜 주세요."라고 보냅니다.
- "완료 기준"과 다르게 나오면 화면의 글이나 서버 창의 빨간 줄을 그대로 복사해 "이렇게 나와요. 고쳐 주세요."와 함께 AI에게 붙여 넣습니다.
- 화면이 멈추거나 단추를 눌러도 아무 일이 없으면 ego 브라우저에서 F12를 눌러 Console 탭의 빨간 글을 복사하고, "이렇게 나와요. 고쳐 주세요." 다음에 붙여 AI에게 보냅니다.
- 답이 이상해지면 새 대화를 열고 1-2의 프롬프트를 다시 보낸 뒤, 하던 번호부터 이어 갑니다.
- 화면 색과 배치는 예시와 달라도 됩니다. "완료 기준"에 적힌 글과 동작만 같으면 됩니다.

## 1-1. 작업 준비

```text
이 폴더에서 웹앱을 만들 준비를 하기 위해, 이 PC에 Node.js(22.9 이상, 없으면 24 LTS)와 Git이 있는지 확인하고 없으면 설치해 주세요.
그다음 이 폴더를 내 git 저장소로 만들어 주세요. 끝나면 Node.js와 Git의 버전만 한 줄로 알려 주세요.
```

- 하는 일: AI가 이 PC의 Node.js와 Git을 찾아보고 없으면 설치한 뒤, 프로젝트 폴더를 내 git 저장소로 만듭니다.
- 목표: Node.js는 1-4부터 서버를 켜는 데, Git은 1-2에서 수업 자료를 받고 1-12에서 내 코드를 커밋하는 데 씁니다.
- 직접 하기: AI가 프로그램을 새로 설치했으면 AI 도구를 닫았다가 다시 열고, 같은 폴더에서 새 대화를 시작합니다.
- 완료 기준:
  - AI 답에 `v24.`처럼 22.9 이상인 Node.js 버전과 Git 버전이 나옵니다.
  - 시작 메뉴에서 PowerShell 창을 새로 열고 `cd C:\vision-ai\vision-risk-dashboard`를 친 뒤 `git status`를 치면 "No commits yet"이 나옵니다. "not a git repository"가 나오면 1-1을 다시 보냅니다.

## 1-2. 지침 세팅

```text
수업 자료를 이 프로젝트로 가져오기 위해, 수업 저장소 https://github.com/startup-life/vision-risk-dashboard-student 를 이 프로젝트에 class라는 이름의 원격 저장소로 더해 받아 오고, class/milestone-0의 AGENTS.md, docs/guide, materials를 이 프로젝트로 가져와 주세요(브랜치는 옮기지 않습니다).
그다음 AGENTS.md를 작업 지침으로 삼아 주세요. 프롬프트에 없는 상세 구현(주소, 화면 문구, 파일 이름, 거절 규칙)은 docs/guide의 회차 문서와 그 회차 완료 브랜치 코드(class/milestone-1)에서 확인합니다.
지금은 AGENTS.md와 docs/guide/session-1.md를 읽기만 하고, 읽은 파일 이름만 한 줄로 알려 주세요.
```

- 하는 일: 수업 저장소의 `milestone-0` 브랜치에서 강사가 준 자료(`materials` 폴더), 지침(`AGENTS.md`), 1회차 보충 문서(`docs/guide` 폴더)를 프로젝트 폴더로 가져오고, AI가 지침과 1회차 보충 문서를 읽어 둡니다.
- 목표: 프롬프트에 없는 주소, 화면 문구, 거절 규칙은 AI가 지침과 보충 문서, 완료 브랜치 코드에서 찾아 따르므로 앱을 만드는 1-3보다 먼저 보냅니다.
- 직접 하기: 수업 저장소를 처음 받을 때 GitHub 로그인 창이 뜨면 강사에게 초대받은 GitHub 계정으로 로그인합니다.
- 완료 기준: 탐색기의 프로젝트 폴더에 `AGENTS.md`, `docs`, `materials`가 생기고, AI 답에 `AGENTS.md`와 `session-1.md`가 나옵니다. 새 대화를 열 때마다 이 프롬프트를 먼저 보냅니다.
- 알아 두기: GitHub 로그인이 기본 브라우저로 열리는데 그 브라우저가 ego 브라우저가 아니면, 열린 창 주소창의 주소를 복사해 ego 브라우저에서 엽니다.

## 1-3. 앱 뼈대

```text
현장 사진으로 리스크를 확인하는 "현장 리스크 대시보드" 웹앱을 만들기 위해, 프로젝트 폴더에 `npm.cmd start`로 켜는 8765번 서버와 머리말·홈·확인 기준 화면만 있는 한 페이지 화면 틀을 추가해 주세요.
머리말에는 강사가 준 로고와 앱 이름을 두고, 홈의 "확인 기준 보기" 단추를 누르면 확인 기준 화면으로 갑니다. 데이터 주소, 연결 표시, 알림 줄, 확인 기준 화면의 설명과 제목 옆 홈 단추, 확인 기준 표, 설정 파일은 뒤 번호에서 만들고, 서버는 다음 번호에서 켭니다.
고친 화면이 새로고침하면 바로 보이도록 브라우저가 옛 화면을 기억하지 않게 합니다.
자세한 내용은 docs/guide/session-1.md를 참고해 주세요.
```

- 하는 일: 프로젝트 폴더에 프로젝트 설정 파일, Git에 올리지 않을 파일 목록, 서버 파일, 화면 파일(한 페이지와 그 코드·모양 파일)이 생깁니다.
- 목표: 1-4에서 켤 서버와, 1-5부터 데이터 주소와 연결 표시, 알림 줄, 확인 기준 표를 채워 넣을 화면 틀을 먼저 마련합니다.
- 완료 기준: 프로젝트 폴더에 `package.json`, `.gitignore`, `server` 폴더, `public` 폴더가 생깁니다. AI가 서버를 켜지 않습니다. 화면은 1-4에서 봅니다.

## 1-4. 서버 켜기

```text
만든 화면을 ego 브라우저에서 보기 위해, 새 PowerShell 창을 열어 서버를 켜 주세요.
자세한 내용은 docs/guide/session-1.md의 "서버 켜기"를 참고해 주세요.
```

- 하는 일: AI가 새 PowerShell 창(서버 창)을 열어 그 창에서 서버를 켜고, 나는 ego 브라우저에서 1-3에서 만든 화면 틀을 열어 봅니다.
- 목표: 화면을 보려면 서버가 켜져 있어야 합니다. 이 뒤로 서버 쪽 파일을 고친 번호는 AI가 마치기 전에 서버를 다시 켜고, 화면 파일만 바뀐 번호는 새로고침(F5)만 합니다.
- 직접 하기: AI가 연 서버 창은 닫지 않고 켜 둡니다. ego 브라우저에서 http://127.0.0.1:8765 를 엽니다.
- 완료 기준:
  - AI가 연 서버 창에 `현장 리스크 대시보드: http://127.0.0.1:8765`가 나오고, 탭 제목이 "Vision QC", 머리말에 로고와 "현장 리스크 대시보드", 홈에 "현장 리스크 확인"과 "확인 기준 보기" 단추가 보입니다.
  - "확인 기준 보기"를 누르면 "확인 기준" 화면이 나오고, "← 홈으로"나 로고, 브라우저 뒤로 가기를 누르면 홈으로 돌아옵니다.
- 막히면: 서버 창에 `EADDRINUSE`나 빨간 줄이 나오면 그 줄을 복사해 "이렇게 나와요. 고쳐 주세요."와 함께 AI에게 붙여 넣습니다.
- 알아 두기: AI가 "이미 켜져 있습니다"라고 답하면 앞서 켠 서버 창이 있는 것입니다. 새 창을 기다리지 않고 ego 브라우저에서 주소만 엽니다.

## 1-5. 서버 상태 확인 주소

```text
서버가 켜져 있는지 브라우저로 바로 보기 위해, 서버에 상태 확인용 데이터 주소를 추가해 주세요.
없는 데이터 주소를 물으면 찾을 수 없다는 오류를 돌려줍니다.
자세한 내용은 docs/guide/session-1.md의 "데이터 주소"를 참고해 주세요.
```

- 하는 일: 서버에 상태 확인 주소(`/api/health`)가 생기고, `/api/`로 시작하는데 없는 주소에는 오류 글이 돌아갑니다.
- 목표: 화면 없이 주소 하나로 서버가 켜져 있는지 볼 수 있습니다. 뒤 회차에서 연동 상태를 볼 때도 이 주소를 엽니다.
- 완료 기준: ego 브라우저에서 http://127.0.0.1:8765/api/health 를 열면 `{"status":"ok"}`가 보이고, http://127.0.0.1:8765/api/abc 를 열면 "없는 데이터 주소입니다."가 든 짧은 글이 보입니다.

## 1-6. 확인 기준 데이터 주소

```text
화면이 확인 기준 목록을 받아 갈 수 있도록, 서버에 강사가 준 확인 기준 목록을 그대로 돌려주는 데이터 주소를 추가해 주세요. 화면에 보여 주는 일은 뒤 번호에서 합니다.
자세한 내용은 docs/guide/session-1.md의 "데이터 주소"를 참고해 주세요.
```

- 하는 일: 서버에 `materials` 폴더의 확인 기준 목록을 돌려주는 주소(`/api/standards`)가 생깁니다.
- 목표: 1-7에서 화면이 앱을 처음 열 때 이 주소에서 확인 기준 목록을 받아 기억해 두고, 1-10에서 그 목록을 표로 보여 줍니다.
- 완료 기준: ego 브라우저에서 http://127.0.0.1:8765/api/standards 를 열면 `C-01`과 `머리 보호구`가 든 긴 글이 보입니다.

## 1-7. 연결 표시

```text
서버와 연결됐는지 늘 볼 수 있도록, 머리말 오른쪽에 연결 상태 표시를 추가해 주세요.
화면이 서버에 보내는 요청은 모두 한 곳을 거치게 하고, 앱을 처음 열 때 확인 기준 목록을 서버에서 한 번 가져와 기억해 둡니다.
자세한 내용은 docs/guide/session-1.md의 "서버에 요청하기"와 "연결 표시"를 참고해 주세요.
```

- 하는 일: 머리말 오른쪽에 연결 상태 글이 생기고, 화면이 앱을 처음 열 때 확인 기준 목록을 서버에서 받아 둡니다.
- 목표: 1-8의 알림 줄도 요청이 모두 거치는 이 한 곳의 상태를 쓰고, 1-10의 확인 기준 표는 여기서 받아 둔 목록을 씁니다.
- 완료 기준: 머리말 오른쪽에 "데이터 연결됨"이 보이고, 홈과 확인 기준 화면을 오가도 그대로입니다.

## 1-8. 알림 줄

```text
요청을 처리하는 중인지, 오류가 났는지 사용자가 알 수 있도록, 화면 내용 바로 위에 알림 줄을 추가해 주세요.
자세한 내용은 docs/guide/session-1.md의 "알림 줄"을 참고해 주세요.
```

- 하는 일: 본문의 길잡이 줄과 화면 내용 사이에 요청 상태를 글로 알리는 줄이 생깁니다.
- 목표: 서버에 닿지 못하거나 서버가 오류로 답하면 그 이유를 화면에서 바로 읽을 수 있습니다. 뒤 회차에서 더하는 요청도 이 줄로 처리 중인지 오류가 났는지 알립니다.
- 완료 기준: 평소에는 알림 줄이 비어 있습니다. "처리 중..."과 "오류: (이유)"는 아주 잠깐이거나 실패할 때만 보여서, AI 답에 두 문구를 알림 줄에 넣었다는 말이 나오는지 봅니다. 말이 없으면 "두 문구를 넣었는지 알려 주세요."라고 보냅니다.

## 1-9. 확인 기준 화면의 설명과 홈 단추

```text
확인 기준 화면이 무엇을 보는 곳인지 알리고 홈으로 쉽게 돌아가도록, 확인 기준 화면의 제목 아래에 설명 글을, 제목 오른쪽에 "← 홈으로" 단추를 추가해 주세요.
위쪽 길잡이 줄은 그대로 두고, 확인 기준 표는 다음 번호에서 만듭니다.
자세한 내용은 docs/guide/session-1.md의 "확인 기준 화면"을 참고해 주세요.
```

- 하는 일: 확인 기준 화면의 제목 아래에 이 화면이 다루는 기준을 알리는 글이, 제목 오른쪽에 홈으로 가는 단추가 생깁니다.
- 목표: 사진만으로 주문 일치나 배송 완료를 확정하지 않는다는 이 앱의 원칙을 기준 표보다 먼저 알립니다.
- 완료 기준: 제목 아래에 "물류창고에서"로 시작하는 설명이 보이고, 제목 오른쪽의 "← 홈으로" 단추를 누르면 홈으로 갑니다. 위쪽 길잡이 줄도 그대로 있습니다.

## 1-10. 확인 기준 표

```text
사진을 볼 때 어떤 기준으로 확인하는지 한눈에 보도록, 확인 기준 화면에 "택배 발송·산업안전 기준" 상자를 추가하고 1-7에서 가져와 둔 확인 기준 목록을 그 안에 표로 보여 주세요.
자세한 내용은 docs/guide/session-1.md의 "확인 기준 목록"과 "확인 기준 표"를 참고해 주세요.
```

- 하는 일: 확인 기준 화면에 항목, 분류, 추가 확인 조건, 판단 보류 조건, 원문 인용 열로 된 기준 표가 생깁니다.
- 목표: 사진을 보고 판단할 때 기대는 기준입니다. 4회차에는 사건 상세에서 이 기준 가운데 하나를 골라 NotebookLM에 확인을 맡깁니다.
- 완료 기준:
  - 표가 9줄이고 항목 칸이 "C-01 · 머리 보호구"부터 "C-09 · 배송 라벨·주문 대조"까지 나옵니다. 분류 칸은 위 네 줄이 "산업안전", 아래 다섯 줄이 "택배 발송 확인"입니다.
  - 확인 기준 화면을 맨 아래까지 내린 뒤 뒤로 가기로 홈에 갔다가 "확인 기준 보기"를 다시 누르면, 화면 맨 위의 길잡이 줄과 제목이 보입니다.

## 1-11. 설정 파일 읽기

```text
뒤 회차에서 키와 연결 정보를 코드에 적지 않고 따로 넣기 위해, 서버에 설정 파일을 읽는 기능을 추가해 주세요. 설정 예시 파일도 만들어 주세요.
형식이 틀렸거나 모르는 설정 이름이 있으면 서버 창에 알립니다. 이 회차에는 쓰는 키가 없습니다.
설정 값은 서버 창과 대화 어디에도 보여 주지 마세요.
자세한 내용은 docs/guide/session-1.md의 "설정 파일"을 참고해 주세요.
```

- 하는 일: 서버가 켜질 때 설정 파일(`config/local-connection.json`)을 읽게 되고, `config` 폴더에 설정 예시 파일이 생깁니다.
- 목표: 4회차의 NotebookLM 설정과 5회차의 Google 웹앱 주소를 코드에 적지 않고 이 설정 파일에만 넣습니다.
- 완료 기준: 프로젝트 폴더의 `config` 폴더에 `local-connection.example.json`이 생기고, AI가 다시 켠 새 서버 창에 경고 없이 `현장 리스크 대시보드: http://127.0.0.1:8765`가 나옵니다.
