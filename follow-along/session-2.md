# 2회차: 사건 등록과 목록, 내 컴퓨터 저장

- 시작 상태: 1회차를 끝낸 프로젝트 폴더 `C:\vision-ai\vision-risk-dashboard`에서 시작합니다.
- 끝나면 되는 것: 사진 파일을 올리거나 사진 저장소의 사진을 골라 사건을 등록하면, 사건 목록과 홈의 "확인이 필요한 현장"에 "검토 대기"로 나옵니다. 기록과 사진은 이 PC의 `runtime` 폴더에 저장되어 서버를 껐다 켜도 남습니다.
- 준비물: AI 도구에서 연 프로젝트 폴더, 서버 창(서버를 켜 두는 PowerShell 창), 프로젝트 폴더 옆에 받은 사진 저장소(`C:\vision-ai\vision-risk-student-images`, 아래 "시작 전에"에서 받습니다).

## 먼저 알아 둘 말

- **사건**: 현장 사진 1~5장과 장소, 분류, 메모를 묶은 기록 하나입니다. 서버가 `R-101`, `R-102`처럼 번호를 붙입니다.
- **사진 저장소**: 강사가 공개한 연습용 현장 사진 모음입니다. 프로젝트 폴더 옆 `vision-risk-student-images` 폴더에 받아 두고 읽기만 합니다.
- **검토 대기**: 등록만 하고 아직 판단을 남기지 않은 사건의 상태입니다. 3회차에서 판단을 남기면 바뀝니다.

## 시작 전에 (프롬프트 없이 직접 합니다)

1. 서버 켜 보기: 서버 창에서 `npm.cmd start`를 치고 Chrome에서 http://127.0.0.1:8765 를 엽니다. 서버 창이 없으면 시작 메뉴에서 PowerShell 창을 새로 열고 `cd C:\vision-ai\vision-risk-dashboard`를 친 뒤 그 창을 서버 창으로 씁니다. 1회차 홈과 "확인 기준 보기" 단추가 보이면 됩니다.
2. 사진 저장소 받기: `C:\vision-ai` 안에 `vision-risk-student-images` 폴더가 이미 있으면 건너뜁니다. 없으면 서버 창이 아닌 PowerShell 창에서 아래 두 줄을 한 줄씩 칩니다. ZIP으로 받으면 쓰지 못하니 꼭 이 명령으로 받고, 폴더 이름은 바꾸지 않습니다.

```powershell
cd C:\vision-ai
git clone https://github.com/startup-life/vision-risk-student-images.git
```

3. 사진 수 확인: 서버 창이 아닌 PowerShell 창에서 아래 한 줄을 칩니다. `210`이 나와야 합니다.

```powershell
(Get-ChildItem C:\vision-ai\vision-risk-student-images\assets\dataset\images -Filter *.png).Count
```

## 진행 방법

- 프롬프트 상자 하나를 통째로 복사해 AI에게 붙여 넣습니다. 앞 번호가 끝난 뒤에 다음 번호를 보냅니다.
- AI가 파일을 만들거나 명령을 실행해도 되는지 물으면 승인합니다. 서버를 켜겠다고 하면 거절합니다. `Set-ExecutionPolicy`, `npm audit fix`처럼 컴퓨터 설정이나 프로그램 버전을 바꾸는 명령은 승인하지 말고 강사에게 알립니다.
- "직접 하기"는 AI에게 보내지 않고 내가 직접 합니다.
- 번호가 끝날 때마다 서버 창에서 Ctrl+C로 끄고(물으면 `Y`) `npm.cmd start`로 다시 켠 다음, 브라우저를 새로고침(F5)하고 "확인"을 봅니다.
- "확인"과 다르게 나오면 화면의 글이나 서버 창의 빨간 줄을 그대로 복사해 "이렇게 나와요. 고쳐 주세요."와 함께 AI에게 붙여 넣습니다.
- AI가 "이미 되어 있습니다"라고 답하면 그 번호의 "확인"만 해 보고 다음 번호로 넘어갑니다.
- 답이 이상해지면 새 대화를 열고 2-1의 프롬프트를 다시 보낸 뒤, 하던 번호부터 이어 갑니다.
- 사진을 고를 때는 사진 고르는 창에서 `C:\vision-ai\vision-risk-student-images\assets\dataset\images` 폴더로 가서 PNG 파일을 고릅니다. 여러 장은 Ctrl을 누른 채 차례로 누릅니다.
- 확인에 적힌 사건 번호(`R-101`, `R-102`, `R-103`)는 적힌 대로 등록했을 때의 값입니다. 사건을 더 등록해 보았으면 번호가 더 커도 됩니다.
- 화면 색과 배치는 예시와 달라도 됩니다. "확인"에 적힌 글과 동작만 같으면 됩니다.

## 2-16. 등록 화면: 두 탭

```text
저장소 사진과 내 사진 파일 가운데 하나를 골라 등록하도록, 등록 화면에 "저장소 사진 선택"과 "직접 파일 업로드" 두 탭을 추가해 주세요.
지금까지 만든 사진 칸은 직접 파일 업로드 탭으로 옮깁니다. 저장소 사진 탭 안의 사진 고르기는 다음 번호에서 만듭니다.
자세한 내용은 docs/guide/session-2.md의 "두 탭"을 참고해 주세요.
```
- 확인: 등록 화면을 열면 "저장소 사진 선택 (1~5장)" 탭이 먼저 골라져 있고 다른 탭과 색이 달라 눈에 띕니다. 장소를 고친 뒤 "직접 파일 업로드 (1~5장)" 탭으로 바꾸면 사진 칸이 보이고 고친 장소가 그대로 있습니다.

## 2-17. 등록 화면: 저장소 사진 고르기

```text
사진 저장소에서 등록할 사진을 고르기 위해, 등록 화면의 저장소 사진 탭에 사진을 12장씩 보여 주고 체크해 고르는 기능과 "사진 더보기" 단추를 추가해 주세요.
분류 거르기, 고르는 규칙, 저장소 사진으로 등록하는 것은 뒤 번호에서 만듭니다.
자세한 내용은 docs/guide/session-2.md의 "저장소 사진 고르기"를 참고해 주세요.
```
- 확인: 저장소 사진 탭에 사진 12장이 보이고, 하나를 체크하면 "선택된 사진: 1 / 5장"이 됩니다. "사진 더보기"를 누르면 단추 글이 "사진 더보기 (24 / 180)"으로 바뀝니다. 사진이 늦게 뜰 수 있으니 잠시 기다립니다.

## 2-18. 등록 화면: 분류 거르기

```text
많은 사진 가운데 원하는 분류만 보기 위해, 저장소 사진 탭 위에 분류 거르기 단추(전체 / 산업안전 / 택배 발송 확인)를 추가해 주세요.
거르기를 바꿔도 이미 고른 사진과 입력 중인 값은 그대로 둡니다.
자세한 내용은 docs/guide/session-2.md의 "저장소 사진 고르기"를 참고해 주세요.
```
- 확인: 사진 하나를 체크한 뒤 "산업안전"을 누르면 `S-IND` 사진만 남고 단추 글이 "사진 더보기 (12 / 90)"이 됩니다. "선택된 사진: 1 / 5장"은 그대로입니다.

## 2-19. 등록 화면: 고르는 규칙

```text
한 사건에 맞는 사진만 고르도록, 저장소 사진 탭에 5장까지만, 같은 분류 사진끼리만 고르게 하는 기능을 추가해 주세요.
사진을 고르면 분류 칸도 그 사진의 분류로 바꿉니다.
자세한 내용은 docs/guide/session-2.md의 "저장소 사진 고르기"와 "화면 공통"을 참고해 주세요.
```
- 확인: 새로고침한 뒤 택배 발송 확인 사진(`Q-IND`)을 하나 고르면 분류 칸이 "택배 발송 확인"으로 바뀝니다. "산업안전" 거르기로 바꿔 사진을 하나 더 고르면 "한 사건에는 같은 분류의 사진만 고를 수 있습니다"가 보이고 그 체크가 풀립니다.

## 2-20. 저장소 사진으로 사건 등록

```text
연습용 사진으로 사건을 남기기 위해, 등록 화면과 서버에 저장소 사진 탭에서 고른 사진으로 사건을 등록하는 기능을 추가해 주세요.
서버는 사진 저장소에서 그 사진을 꺼내 저장하고 메모 끝에 사진 출처를 붙이며, 화면의 현장 메모에는 출처를 빼고 보여 줍니다.
저장소 사진 거절 규칙은 다음 번호에서 만듭니다.
자세한 내용은 docs/guide/session-2.md의 "POST /api/records: 사건 등록"과 "저장소 사진의 출처"를 참고해 주세요.
```
- 직접 하기: 같은 분류 저장소 사진 2장을 고르고 메모에 "저장소 사진 사건"이라고 적은 뒤 "사건 등록"을 누릅니다. 그다음 Chrome에서 http://127.0.0.1:8765/api/records 를 엽니다.
- 확인: "사건이 등록되었습니다: R-103"이 보이고 사건 목록 맨 위에 `R-103`이 사진 수 "2장"으로 나옵니다. 데이터 주소의 맨 앞 사건 메모에는 `Repository Images`와 사진 번호가 보이고, 홈의 그 사건 카드에는 "현장 메모: 저장소 사진 사건"만 보입니다.

## 2-21. 저장소 사진 등록 규칙

```text
잘못 고른 저장소 사진이 저장되지 않도록, 등록 화면과 서버에 저장소 사진 등록이 규칙에 맞지 않으면 거절하는 기능을 추가해 주세요. 거절하면 이유를 보여 주고 입력한 값은 그대로 둡니다.
자세한 내용은 docs/guide/session-2.md의 "등록 규칙"을 참고해 주세요.
```
- 직접 하기: 새로고침한 뒤 "택배 발송 확인" 거르기에서 `Q-IND-001`, `Q-IND-002`, `Q-IND-003` 세 장을 체크하고 "사건 등록"을 누릅니다.
- 확인: 등록되지 않고 "고른 저장소 사진의 합계가 3MB보다 큽니다. 사진 수를 줄여 합계 3MB 이하로 골라 주세요."가 보입니다. 5회차 판독이 이 합계 한도에 기댑니다.

## 2-22. 홈: 등록할 사진 찾기

```text
등록할 사진을 홈에서 바로 둘러보기 위해, 홈 아래쪽에 접었다 펴는 "등록할 사진 찾기" 칸을 추가해 주세요. 펴면 분류마다 저장소 사진 3장씩 보여 줍니다.
"사진 선택" 단추는 다음 번호에서 만듭니다.
자세한 내용은 docs/guide/session-2.md의 "등록할 사진 찾기"를 참고해 주세요.
```
- 확인: 홈 아래쪽 "등록할 사진 찾기"를 누르면 사진 6장(택배 발송 확인 3장, 산업안전 3장)이 펼쳐집니다.

## 2-23. 홈: 사진 선택 단추

```text
홈에서 고른 사진으로 바로 등록을 시작하기 위해, "등록할 사진 찾기"의 사진마다 "사진 선택" 단추를 추가해 주세요. 누르면 그 사진이 골라진 등록 화면으로 갑니다.
자세한 내용은 docs/guide/session-2.md의 "등록할 사진 찾기"를 참고해 주세요.
```
- 확인: 산업안전 사진의 "사진 선택"을 누르면 등록 화면에서 그 사진이 체크되어 있고, 분류 칸과 분류 거르기가 "산업안전"입니다.

## 2-24. 내 코드 남겨 두기 (직접 하기)

프롬프트는 없습니다.
- 직접 하기: 서버를 끄고 서버 창에서 아래를 한 줄씩 칩니다.

```powershell
git add -A
git commit -m "2회차 사건 등록과 목록"
```

- 확인: `git status`를 치면 "nothing to commit"이 나오고 `runtime`은 보이지 않습니다. 2-1에서 가져온 보충 문서도 이 커밋에 함께 저장됩니다.

## 2회차 끝 확인

- [ ] 서버를 켜면 서버 창에 "사진 저장소: 사진 180장을 읽었습니다."가 나온다.
- [ ] 사진 파일을 올려 등록한 사건과 저장소 사진을 골라 등록한 사건이 모두 사건 목록에 "검토 대기"로 나온다.
- [ ] 홈 "확인이 필요한 현장"에 검토 대기 사건이 사진 카드로 나오고, "검토 대기" 단추의 숫자가 사건 수와 같다.
- [ ] 홈 "등록할 사진 찾기"의 "사진 선택"을 누르면 그 사진이 골라진 등록 화면이 열린다.
- [ ] 서버를 껐다 켜도 사건과 사진이 그대로 있다.
- [ ] 2-24에서 내 코드를 커밋했다.
