# 2회차 목표: 사건 등록과 목록, 내 컴퓨터 저장

현장 사진으로 사건을 등록하고 사건 목록과 홈에서 모아 봅니다.
사진 파일을 올리거나 사진 저장소의 사진을 골라 사건을 등록하면, 사건 목록과 홈의 "확인이 필요한 현장"에 "검토 대기"로 나옵니다.
기록과 사진은 이 PC의 `runtime` 폴더에 저장되어 서버를 껐다 켜도 남고, 만든 코드는 내 저장소에 커밋해 둡니다.

## 시작 전에

1회차를 끝낸 프로젝트 폴더 `C:\vision-ai\vision-risk-dashboard`에서 이어서 합니다. 아래 1~3을 먼저 합니다.

준비물: AI 도구에서 연 프로젝트 폴더, 서버 창(AI가 열어 서버를 켠 PowerShell 창), ego 브라우저, 프로젝트 폴더 옆에 받은 사진 저장소(`C:\vision-ai\vision-risk-student-images`, 아래 2에서 받습니다).

1. 서버 켜 보기: 서버 창(서버가 켜진 창)이 있으면 ego 브라우저에서 http://127.0.0.1:8765 를 엽니다. 서버 창이 없으면 아래 2-1을 먼저 보내고, 답이 오면 AI에게 "서버를 켜 주세요."라고 보낸 뒤 같은 주소를 엽니다. 이때는 아래 2~3을 마친 뒤 2-2부터 이어 갑니다. 1회차 홈과 "확인 기준 보기" 단추가 보이면 됩니다.
2. 사진 저장소 받기: 사진 저장소는 강사가 공개한 연습용 현장 사진 모음이고, 프로젝트 폴더 옆 `vision-risk-student-images` 폴더에 받아 두고 읽기만 합니다. `C:\vision-ai` 안에 `vision-risk-student-images` 폴더가 이미 있으면 건너뜁니다. 없으면 서버 창이 아닌 PowerShell 창에서 아래 두 줄을 한 줄씩 칩니다. ZIP으로 받으면 쓰지 못하니 꼭 이 명령으로 받고, 폴더 이름은 바꾸지 않습니다.

```powershell
cd C:\vision-ai
git clone https://github.com/startup-life/vision-risk-student-images.git
```

3. 사진 수 확인: 서버 창이 아닌 PowerShell 창에서 아래 한 줄을 칩니다. `210`이 나와야 합니다.

```powershell
(Get-ChildItem C:\vision-ai\vision-risk-student-images\assets\dataset\images -Filter *.png).Count
```

이번 회차에 알아 둘 것은 아래와 같습니다.

- 사진을 고를 때는 사진 고르는 창에서 `C:\vision-ai\vision-risk-student-images\assets\dataset\images` 폴더로 가서 PNG 파일을 고릅니다. 여러 장은 Ctrl을 누른 채 차례로 누릅니다.
- 완료 기준에 적힌 사건 번호(`R-101`, `R-102`, `R-103`)는 적힌 대로 등록했을 때의 값입니다. 사건을 더 등록해 보았으면 번호가 더 커도 됩니다.

화면이 멈추거나 단추를 눌러도 아무 일이 없으면 ego 브라우저에서 F12를 눌러 Console 탭의 빨간 글을 복사하고, "이렇게 나와요. 고쳐 주세요." 다음에 붙여 AI에게 보냅니다. 나머지 진행 방법은 1회차와 같습니다.

## 2-1. 지침 세팅

```text
이번 회차 문서를 이 프로젝트로 가져오기 위해, 수업 저장소(class)를 다시 받아 class/milestone-1의 docs/guide와 AGENTS.md를 이 프로젝트로 가져와 주세요(브랜치는 옮기지 않습니다).
그다음 AGENTS.md를 작업 지침으로 삼아 주세요. 프롬프트에 없는 상세 구현(주소, 화면 문구, 파일 이름, 거절 규칙)은 docs/guide의 회차 문서와 그 회차 완료 브랜치 코드(class/milestone-2)에서 확인합니다.
지금은 AGENTS.md, docs/guide/session-1.md, docs/guide/session-2.md를 읽기만 하고, 읽은 파일 이름만 한 줄로 알려 주세요.
```
- 하는 일: 수업 저장소 `milestone-1`에서 규칙 파일과 보충 문서를 프로젝트 폴더로 가져오고, AI가 1~2회차 문서를 읽어 둡니다. `docs\guide`에 2회차 보충 문서가 새로 생깁니다.
- 목표: 2회차의 자세한 약속(주소, 화면 문구, 파일 이름, 거절 규칙)은 2회차 보충 문서와 완료 브랜치 `milestone-2` 코드에 있으므로, 이 프롬프트를 다른 번호보다 먼저 보냅니다.
- 완료 기준: 탐색기에서 `docs\guide` 폴더에 `session-2.md`가 있고, AI 답에 `AGENTS.md`, `session-1.md`, `session-2.md`가 나옵니다. 새 대화를 열 때마다 이 프롬프트를 먼저 보냅니다.

## 2-2. 사진 저장소 읽기

```text
사건 등록에 연습용 현장 사진을 쓰기 위해, 서버가 켜질 때 옆 폴더 사진 저장소에서 쓸 수 있는 사진 목록을 읽고 읽은 장수를 서버 창에 알리는 기능을 서버에 추가해 주세요.
못 읽어도 서버는 켜고, 왜 못 읽었는지 서버 창에 한 줄로 알려 줍니다.
자세한 내용은 docs/guide/session-2.md의 "사진 저장소(vision-risk-student-images)"를 참고해 주세요.
```
- 하는 일: 서버가 켜질 때 프로젝트 폴더 옆 `vision-risk-student-images`에서 사진 목록을 읽고, 서버 창에 읽은 장수가 한 줄로 나옵니다.
- 목표: 뒤 번호의 저장소 사진 주소와 등록 화면, 홈 "등록할 사진 찾기"가 모두 이 목록을 씁니다. 못 읽어도 서버가 켜져 사진 파일 등록은 할 수 있습니다.
- 완료 기준: AI가 연 새 서버 창에 `[RepositoryImages]`로 시작하는 줄 없이 "사진 저장소: 사진 180장을 읽었습니다."가 나옵니다. 210장 가운데 수업에 쓰는 180장만 읽습니다.

## 2-3. 저장소 사진 목록 주소

```text
등록 화면이 저장소 사진을 보여 줄 수 있도록, 서버에 저장소 사진 목록을 돌려주는 데이터 주소를 추가해 주세요. 분류로 걸러 받을 수도 있게 합니다.
자세한 내용은 docs/guide/session-2.md의 "GET /api/repository-images: 저장소 사진 목록"을 참고해 주세요.
```
- 하는 일: 저장소 사진의 번호, 분류, 사진 주소를 돌려주는 `/api/repository-images` 주소가 생기고, `?track=`을 붙이면 한 분류만 돌려줍니다.
- 목표: 2-16의 등록 화면 사진 고르기와 2-21의 홈 "등록할 사진 찾기"가 이 주소로 사진 목록을 받습니다.
- 직접 하기: ego 브라우저에서 http://127.0.0.1:8765/api/repository-images 를 열고, 그다음 http://127.0.0.1:8765/api/repository-images?track=safety 를 엽니다.
- 완료 기준: 처음 주소에는 `"total":180`과 `Q-IND-001`이 보이고, 두 번째 주소에는 `"total":90`과 `S-IND`로 시작하는 번호만 보입니다.

## 2-5. 사건 저장 자리와 사건 목록 주소

```text
서버를 껐다 켜도 사건이 남도록, 서버에 사건과 사진을 프로젝트 폴더 안 runtime 폴더에 저장할 자리와 사건 목록을 돌려주는 데이터 주소를 추가해 주세요.
runtime 폴더는 git에 올리지 않습니다. 사건 등록은 뒤 번호에서 만듭니다.
자세한 내용은 docs/guide/session-2.md의 "사건 기록 저장"과 "GET /api/records: 사건 목록"을 참고해 주세요.
```
- 하는 일: 서버가 쓰는 `runtime` 폴더 자리가 정해지고 `.gitignore`에 들어갑니다. `/api/records` 주소가 아직 빈 사건 목록을 돌려줍니다.
- 목표: 2-8부터 등록한 사건과 사진이 이 폴더에 저장되어 서버를 다시 켜도 남고, 사건 목록 화면과 홈이 이 주소로 사건을 받습니다.
- 직접 하기: ego 브라우저에서 http://127.0.0.1:8765/api/records 를 엽니다.
- 완료 기준: `"success":true`와 빈 목록 `"records":[]`가 보입니다.
- 알아 두기: 사건은 현장 사진 1~5장과 장소, 분류, 메모를 묶은 기록 하나입니다. 서버가 `R-101`, `R-102`처럼 번호를 붙입니다.

## 2-6. 사건 목록 화면

```text
등록한 사건을 한곳에서 모아 보기 위해, 사건을 표로 보여 주는 사건 목록 화면을 추가해 주세요. 홈 제목 옆 "전체 사건" 단추를 누르면 이 화면으로 갑니다.
홈의 "확인 기준 보기" 단추는 링크로 바꿔 홈 맨 아래로 옮기고, 등록 화면은 다음 번호에서 만듭니다.
자세한 내용은 docs/guide/session-2.md의 "사건 목록 화면"과 "화면 공통"을 참고해 주세요.
```
- 하는 일: 홈 제목 옆에 "전체 사건" 단추가, 주소 `#records`에 사건 목록 화면이 생기고, "확인 기준 보기"는 링크로 바뀌어 홈 맨 아래로 옮겨집니다.
- 목표: 등록한 사건을 이 표에서 상태, 장소, 사진 수와 함께 확인합니다. 2-8부터 등록이 끝나면 이 화면으로 옵니다.
- 완료 기준:
  - 홈에서 "전체 사건"을 누르면 주소 끝이 `#records`가 되고 "등록된 사건이 없습니다. 새 사건을 등록하세요."가 보입니다. "← 홈으로"를 누르면 홈으로 갑니다.
  - 홈 맨 아래의 "확인 기준 보기"를 누르면 확인 기준 화면이 열립니다.

## 2-7. 사건 등록 화면

```text
현장 사건을 입력받기 위해, 장소·분류·현장 메모 칸과 사진 파일 칸이 있는 사건 등록 화면을 추가해 주세요. 홈 제목 옆 "사진 등록"과 사건 목록의 "+ 새 사건 등록" 단추로 이 화면에 갑니다.
아직 "사건 등록"을 눌러도 저장하지 않습니다. 저장은 다음 번호에서, 두 탭과 저장소 사진 고르기는 뒤 번호에서 만듭니다.
자세한 내용은 docs/guide/session-2.md의 "입력 칸과 단추"와 "화면 공통"을 참고해 주세요.
```
- 하는 일: "현장 사건 등록" 화면에 입력 칸과 "사건 등록"·"목록가기" 단추가 생기고, 홈 제목 옆에 "사진 등록" 단추가 더해집니다. 아직 저장은 하지 않습니다.
- 목표: 2-8에서 이 화면에서 사건을 저장하고, 2-15~2-19에서 저장소 사진 탭을 더합니다.
- 완료 기준:
  - 홈의 "사진 등록"과 사건 목록의 "+ 새 사건 등록" 모두 "현장 사건 등록" 화면을 열고, 장소 칸에 "물류창고 A"가 들어 있습니다. "목록가기"를 누르면 사건 목록으로 갑니다.
  - 홈 제목 옆에는 "사진 등록"과 "전체 사건" 단추만 있습니다.

## 2-8. 사진 파일로 사건 등록

```text
내 PC의 사진으로 사건을 남기기 위해, 등록 화면과 서버에 고른 사진 파일로 사건을 등록하는 기능을 추가해 주세요. 서버는 사건 번호를 붙여 기록과 사진을 runtime 폴더에 저장합니다.
등록되면 사건 목록으로 가서 안내를 보여 주고, 실패하면 입력한 값을 그대로 둡니다. 거절 규칙과 저장소 사진 등록은 뒤 번호에서 만듭니다.
자세한 내용은 docs/guide/session-2.md를 참고해 주세요.
```
- 하는 일: "사건 등록"을 누르면 사건에 `R-101`부터 번호가 붙고 기록과 사진이 `runtime` 폴더에 저장되며, 사건 목록 화면으로 가서 등록 안내가 보입니다.
- 목표: 사건 등록의 기본 흐름을 만듭니다. 2-19의 저장소 사진 등록과 3회차의 판단 남기기가 이렇게 저장한 사건 기록을 이어서 씁니다.
- 직접 하기: 등록 화면에서 PNG 한 장을 고르고 메모에 "첫 사건"이라고 적은 뒤 "사건 등록"을 누릅니다.
- 완료 기준: 사건 목록 화면으로 바뀌며 "사건이 등록되었습니다: R-101"이 보이고, 표에 `R-101`이 상태 "검토 대기", 장소 "물류창고 A", 사진 수 "1장"으로 나옵니다.
- 알아 두기: "검토 대기"는 등록만 하고 아직 판단을 남기지 않은 사건의 상태입니다. 3회차에서 판단을 남기면 바뀝니다.

## 2-9. 사진 파일 등록 규칙

```text
잘못된 사건이 저장되지 않도록, 등록 화면과 서버에 사진 파일 등록이 규칙에 맞지 않으면 거절하는 기능을 추가해 주세요. 거절하면 이유를 보여 주고 입력한 값은 그대로 둡니다.
저장소 사진 규칙은 뒤 번호에서 만듭니다.
자세한 내용은 docs/guide/session-2.md의 "등록 규칙"을 참고해 주세요.
```
- 하는 일: 장소가 비었거나 사진 파일의 장수, 크기, 형식이 규칙에 맞지 않으면 등록되지 않고 이유가 보이며, 입력한 값은 그대로 남습니다.
- 목표: 화면을 거치지 않은 요청도 서버가 같은 규칙으로 다시 검사해, 잘못된 기록이 `runtime` 폴더에 남지 않게 합니다.
- 완료 기준: 장소 칸을 지우고 띄어쓰기만 넣은 뒤 사진 한 장으로 "사건 등록"을 누르면 등록되지 않고 "장소를 입력해 주세요."가 보이며, 메모와 고른 사진은 남아 있습니다.

## 2-10. 등록한 사진 보기 주소

```text
홈 카드에 사건 사진을 띄울 수 있도록, 서버에 등록한 사진을 사건 번호와 순서로 찾아 돌려주는 데이터 주소를 추가해 주세요.
자세한 내용은 docs/guide/session-2.md의 "GET /api/records/(사건 번호)/images/(순서): 등록한 사진 한 장"을 참고해 주세요.
```

