# 1회차 보충 문서: 준비와 화면 틀, 확인 기준 목록

이 회차는 빈 폴더에서 시작해 서버와 화면 틀을 만들고, 강사가 준 확인 기준 9개를 표로 보여 줍니다. 앞 회차가 없고, 이 문서가 앱 전체의 기본 약속입니다. 뒤 회차 문서는 여기에 기능을 더하거나, 달라지는 부분만 따로 적습니다. 문서에 적힌 문구에서 (이유)처럼 값의 이름을 괄호로 쓴 부분의 뜻은 프로젝트 규칙 파일에 있습니다.

## 앱과 폴더

- 물류창고 현장 사진으로 택배 발송·산업안전 리스크를 확인하고 판단·조치를 기록하는 "현장 리스크 대시보드" 웹앱입니다. 이 PC에서만 씁니다.
- 서버는 Node.js로 server 폴더에 두고, 시작 파일은 server/server.js입니다. 웹 프레임워크 없이 Node.js 기본 기능으로 만듭니다.
- 화면은 HTML·CSS·JavaScript로 public 폴더에 둡니다. public/index.html 한 페이지이고, 화면을 그리는 코드는 js 파일(public/app.js)에, 모양은 css 파일(public/style.css)에 따로 둡니다.
- public/index.html은 문서 언어를 한국어(lang="ko")로 하고, 화면 내용은 본문의 빈 자리(id가 app인 div) 안에 코드로 그립니다.
- 완료 브랜치처럼 코드가 이미 있으면 서버와 화면 파일의 위치는 그 코드의 폴더 구조를 따릅니다.
- npm.cmd start를 치면 server/server.js가 켜집니다(package.json의 start).
- package.json에는 이름 vision-risk-dashboard, private true, type commonjs, scripts의 start "node server/server.js", engines의 node ">=22.9.0"을 적습니다. 더할 패키지가 없으므로 dependencies는 비워 둡니다.
- git에 올리지 않는 파일은 node_modules 폴더, .env, config/local-connection.json입니다(.gitignore). 예시 파일 config/local-connection.example.json은 git에 올립니다.

## 서버 켜기

- 서버는 이 PC 안(127.0.0.1)에서만 열리고 포트는 8765입니다.
- 서버가 켜지면 터미널에 "현장 리스크 대시보드: http://127.0.0.1:8765" 한 줄을 보여 줍니다.
- 8765번 포트를 이미 쓰고 있으면 "8765번 포트를 이미 쓰고 있습니다. 먼저 켠 서버 창에서 Ctrl+C로 끈 뒤 다시 켜세요."를 보여 주고 서버를 켜지 않고 끝냅니다(종료 코드 1). 포트가 이미 쓰이면 Node.js가 EADDRINUSE 오류를 냅니다. 같은 포트에 서버가 두 개 뜨는 일을 막기 위해서입니다.

## 화면 파일 보내기

- 서버는 public 폴더의 파일만 브라우저에 보냅니다. 주소 /는 public/index.html입니다.
- 주소는 퍼센트 인코딩을 푼 뒤에 판단합니다. /%2e%2e%2fpackage.json 같은 주소도 public 폴더 밖 파일로 보고 거절합니다. 풀 수 없는 주소는 400으로 답합니다.
- 파일을 보낼 때 종류를 알려 줍니다. html은 text/html, css는 text/css, js는 text/javascript, png는 image/png, jpg와 jpeg는 image/jpeg, json은 application/json이고 글자 파일에는 charset=utf-8을 붙입니다. 그 밖은 application/octet-stream입니다.
- 파일을 보내는 주소는 GET과 HEAD만 받고, 다른 방식의 요청은 405로 답합니다.
- public 폴더에 없는 파일은 404와 "Not found" 글로 답합니다.
- public 폴더 밖의 파일, 이름이 점(.)으로 시작하는 파일, 이름에 .env가 들어간 파일은 보내지 않고 403과 "Forbidden" 글로 거절합니다.
- 다른 사이트 주소에서 온 요청은 403으로 거절합니다. 요청에 Origin 헤더가 있는데 127.0.0.1이나 localhost가 아니면 다른 사이트로 봅니다. Origin 헤더가 없는 요청은 받습니다. 이 검사는 파일과 데이터 주소를 처리하기 전에 먼저 하고, 거절 답은 `{"error": "Forbidden: invalid origin"}`입니다.
- 브라우저가 옛 화면을 기억하지 않게 모든 답에 캐시를 끕니다(Cache-Control: no-store).

## 데이터 주소

- 화면이 쓰는 데이터 주소는 /api/ 로 시작하고 JSON으로 답합니다.
- 오류는 `{"error": "한국어 문장"}` 모양으로 답합니다. 뒤 회차 문서가 오류에 다른 항목을 더할 수 있습니다.
- /api/ 로 시작하는데 없는 주소는 404와 `{"error": "없는 데이터 주소입니다."}`로 답합니다. 있는 주소라도 정해진 방식(GET 등)이 아니면 같습니다.
- 데이터 주소를 처리하다 예상하지 못한 오류가 나면(예: 기준 목록 파일의 JSON이 틀림) 500과 `{"error": "(오류 문장)"}`로 답합니다.
- GET /api/health: 서버가 켜져 있는지 봅니다. `{"status": "ok"}`로 답합니다. 뒤 회차 문서가 항목을 더할 수 있습니다.
- GET /api/standards: materials/standards.json 내용을 그대로 돌려줍니다. 파일이 없으면 `{"standards": []}`로 답합니다.

## 확인 기준 목록

확인 기준 목록은 지급 자료 materials/standards.json에 있습니다.

- standards 목록의 한 줄이 기준 하나입니다.
- id는 번호(C-01~C-09), name은 이름, category는 분류, hazard_condition은 추가 확인 조건, hold_condition은 판단 보류 조건, canonical_quote는 원문 인용, notes는 참고입니다.
- category가 quality면 화면에 "택배 발송 확인", safety면 "산업안전"으로 보입니다.

## 화면 공통

### 화면 바꾸기

- 화면 글은 모두 한국어입니다. 브라우저 탭 제목은 "Vision QC"입니다.
- 화면은 주소 끝 # 뒤 이름으로 바꿉니다. #dashboard와 # 없음은 홈, #models는 확인 기준 화면이고, 모르는 이름은 홈을 보여 줍니다. 뒤 회차 문서가 화면을 더합니다.
- 주소 끝이 바뀌면 화면을 다시 그립니다. 화면이 바뀌면 맨 위로 올라갑니다. 같은 화면을 다시 그릴 때(예: 데이터를 받은 뒤)는 올라가지 않습니다. 브라우저 뒤로 가기를 누르면 앞 화면으로 돌아갑니다.

### 서버에 요청하기

- 화면의 모든 요청은 공통 함수 하나를 거칩니다. 이 함수가 연결 표시와 알림 줄이 쓰는 상태(요청 중, 연결됨, 오류)를 바꿉니다.
- 요청이 여러 개면 모두 끝나야 요청 중이 끝납니다.
- 요청이 성공하면 오류 상태를 지우고 연결됨으로 둡니다.
- 서버에 닿지 못했거나 500번대로 답하면 오류 상태에 이유를 넣습니다. 500번대면 연결됨도 풉니다.
- 400번대로 답하면 오류 상태를 바꾸지 않습니다. 이유는 그 요청을 보낸 화면이 자기 자리에 보여 줍니다.

### 머리말과 본문

- 모든 화면 맨 위에 머리말이 있습니다. 왼쪽은 로고 그림과 "현장 리스크 대시보드"이고 누르면 홈으로 갑니다. 오른쪽은 연결 표시입니다.
- 로고 그림은 materials/factory-logo.png를 public 폴더 안 assets 폴더로 복사해서 씁니다(public/assets/factory-logo.png). 화면에는 가로세로 44로 보입니다.
- 머리말 아래가 화면마다 바뀌는 본문입니다. 본문은 위에서부터 길잡이 줄, 알림 줄, 화면 내용 순서입니다.
- 홈이 아닌 화면은 "← 홈으로 / (화면 이름)" 같은 길잡이 줄을 두고, 앞부분을 누르면 그 화면으로 갑니다. 홈에는 길잡이 줄이 없습니다.

### 연결 표시

- 처음엔 "연결 대기", 서버에 요청하는 중이면 "연결 확인 중...", 답을 받으면 "데이터 연결됨", 실패하면 "조회 실패 ((이유))"입니다. 네 가지 글 중 하나만 보입니다.
- 위에서부터 차례로 따져 정합니다. 요청 중이고 아직 연결되지 않았으면 "연결 확인 중...", 오류 상태가 있으면 "조회 실패 ((이유))", 연결됐으면 "데이터 연결됨", 모두 아니면 "연결 대기"입니다.
- 한 번 연결된 뒤에는 요청 중에도 "데이터 연결됨"을 유지합니다.
- 서버가 400번대 오류로 답한 것은 연결 실패로 치지 않고 연결 표시를 그대로 둡니다(아직 연결된 적이 없으면 "연결 대기"). 서버가 잘못된 요청이라고 답한 것은 서버가 정상으로 답한 것이기 때문입니다.
- 실패한 뒤 다음 요청이 성공하면 다시 "데이터 연결됨"이 됩니다.

### 알림 줄

- 요청 중이면 "처리 중...", 오류가 있으면 "오류: (이유)"를 보여 주고, 둘 다 아니면 비워 둡니다. 요청 중인지를 먼저 봅니다.
- 오류 이유는 서버가 보낸 error 문장을 그대로 씁니다.
- 여기서 오류는 위 "서버에 요청하기"의 오류 상태입니다. 400번대 답은 알림 줄에 저절로 나오지 않습니다.
- 서버에 닿지 못해 실패하면 이유는 "로컬 서버에 연결하지 못했습니다. 터미널에서 npm.cmd start(macOS: npm start)가 켜져 있는지 확인하세요."입니다. 브라우저의 영어 오류 문장을 그대로 보여 주지 않기 위해서입니다.

### 화면 그리기

- 서버에서 받은 글은 화면에 글자 그대로 넣습니다. HTML로 넣지 않습니다.
- 화면 틀은 데이터를 받기 전에 먼저 보여 줍니다. 확인 기준 목록은 앱을 처음 열 때 한 번 받아 두고, 확인 기준 화면은 그 목록을 씁니다.

- 제목은 "확인 기준"이고, 제목 아래 설명은 "물류창고에서 구매자에게 택배를 보내기 전 확인할 발송·산업안전 기준입니다. 사진만으로 주문 일치나 배송 완료를 확정하지 않습니다."입니다.
- 위쪽 길잡이 줄은 "← 홈으로 / 확인 기준"이고, "← 홈으로"를 누르면 홈으로 갑니다.
- 제목 오른쪽에도 "← 홈으로" 단추가 있고, 누르면 홈으로 갑니다. 길잡이 줄과 함께 둡니다.

### 확인 기준 표

- 열은 항목, 분류, 추가 확인 조건, 판단 보류 조건, 원문 인용입니다.
- 항목 칸은 "C-01 · 머리 보호구"처럼 번호와 이름을 " · "로 이어 씁니다.
- 분류 칸은 위 "확인 기준 목록"에 적은 대로 "택배 발송 확인" 또는 "산업안전"입니다.
- 원문 인용 칸은 글을 큰따옴표로 감쌉니다.
- 표 한 줄이 기준 하나이고, 지급 자료대로라면 9줄입니다.

### 표 자리의 문구

- 기준을 받는 동안 표 자리에 "확인 기준을 불러오고 있어요."를 보여 줍니다.
- 기준을 불러오지 못하면 표 자리에 "기준 조회 실패: (이유)"를 보여 줍니다. 이유는 서버가 보낸 error 문장이거나, 서버에 닿지 못했을 때의 문장입니다.

## 설정 파일

설정 파일 config/local-connection.json은 키와 연결 정보를 넣는 JSON 파일입니다.

- 서버가 켜질 때 한 번 읽습니다. 파일이 없으면 그대로 켭니다. 파일 맨 앞에 메모장이 붙이는 표시(BOM)가 있으면 지우고 읽습니다.
- JSON 형식이 틀리면 오류 원문은 보여 주지 말고 "설정 파일의 JSON 형식이 올바르지 않습니다: 3행 5열"처럼 몇 행 몇 열인지만 알립니다(모르면 "설정 파일의 JSON 형식이 올바르지 않습니다: 문법 오류"). 그리고 서버를 켜지 않고 끝냅니다. 오류 원문에는 파일 내용이 들어갈 수 있어서 위치만 알립니다. 행과 열은 1부터 세고, JSON.parse 오류 문장에 든 위치 값으로 계산합니다.
- JSON이 맞아도 `{ }`로 감싼 모양이 아니면 "설정 파일은 { } 로 감싼 JSON 객체여야 한다."를 보여 주고 서버를 켜지 않고 끝냅니다.
- 쓰는 키는 회차 문서에 적힌 것뿐입니다. 그 밖의 키는 "설정 경고: 알 수 없는 설정 키 (키 이름)는 무시한다." 한 줄로 이름만 알리고 넘어갑니다. 예: 설정 경고: 알 수 없는 설정 키 TEST_KEY는 무시한다.
- 키 이름은 대문자·숫자·밑줄로 쓰고 40자까지입니다. 이 모양이 아닌 키는 값을 잘못 붙여 넣은 것일 수 있어 이름도 보여 주지 않고, 개수만 "설정 경고: 형식이 맞지 않는 키 (개수)개는 무시한다. 키 이름은 대문자·숫자·밑줄로 쓴다."로 알립니다.
- 값은 모두 따옴표로 감싼 글자입니다. 쓰는 키의 값이 글자가 아니면 "설정 경고: (키 이름) 값은 문자열이어야 한다. 이 값은 무시한다."로 알립니다. 값은 터미널, 화면, 대화 답에 절대 보여 주지 않습니다.
- 예시 파일 config/local-connection.example.json에는 쓰는 키를 모두 빈 값("")으로 적습니다. 키가 없으면 `{ }`입니다. 뒤 회차 문서가 키를 더하면 예시 파일에도 더합니다.

이 회차에는 쓰는 키가 없습니다.
