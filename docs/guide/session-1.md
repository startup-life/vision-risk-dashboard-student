# 1회차 보충 문서: 준비와 화면 틀, 확인 기준 목록

이 회차는 빈 폴더에서 시작해 서버와 화면 틀을 만들고 강사가 준 확인 기준 9개를 표로 보여 줍니다. 앞 회차가 없고 이 문서가 웹 서비스 전체의 기본 약속입니다. 뒤 회차 문서는 여기에 기능을 더하거나 달라지는 부분만 따로 적습니다. 문서에 적힌 문구에서 (이유)처럼 값의 이름을 괄호로 쓴 부분의 뜻은 프로젝트 규칙 파일에 있습니다.

## 웹 서비스와 폴더

- 물류창고 현장 사진으로 택배 발송·산업안전 리스크를 확인하고 판단·조치를 기록하는 "현장 리스크 대시보드" 웹 서비스입니다. 이 PC에서만 씁니다.
- 서버는 Node.js로 server 폴더에 두고 시작 파일은 server/server.js입니다. 웹 프레임워크 없이 Node.js 기본 기능으로 만듭니다.
- 화면은 HTML·CSS·JavaScript로 public 폴더에 둡니다. public/index.html 한 페이지이고 화면을 그리는 코드는 js 파일(public/app.js)에, 모양은 css 파일(public/style.css)에 따로 둡니다.
- public/index.html은 문서 언어를 한국어(lang="ko")로 하고 화면 내용은 본문의 빈 자리(id가 app인 div) 안에 코드로 그립니다.
- 내 프로젝트에 코드가 이미 있으면 서버와 화면 파일의 위치는 그 코드의 폴더 구조를 따릅니다. 완료 브랜치 코드는 courses/vision-96h-v2 폴더 아래(서버는 tools, 화면은 preview)에 있어 이 구조와 다릅니다. 완료 브랜치 코드는 동작을 참고하고, 파일은 내 프로젝트의 폴더 구조에 둡니다.
- npm.cmd start를 치면 server/server.js가 켜집니다(package.json의 start). node --watch로 켜서 server 폴더의 파일이 바뀌면 같은 창에서 서버가 알아서 다시 켜집니다. 다시 켤 때 서버 창의 앞 줄은 지워지고 새로 찍힙니다. 서버 창의 시작 줄("현장 리스크 대시보드: …")은 이 시작 파일에서 찍습니다. 완료 브랜치 코드에서는 courses/vision-96h-v2/tools/run-local.cjs가 시작 파일입니다.
- package.json에는 이름 vision-risk-dashboard, private true, type commonjs, scripts의 start "node --watch server/server.js", engines의 node ">=22.9.0"을 적습니다. 더할 패키지가 없으므로 dependencies는 비워 둡니다.

## 서버 켜기

- 서버는 이 PC 안(127.0.0.1)에서만 열리고 포트는 8765입니다.
- 서버가 켜지면 터미널에 "현장 리스크 대시보드: http://127.0.0.1:8765" 한 줄을 보여 줍니다.
- 8765번 포트를 이미 쓰고 있으면 "8765번 포트를 이미 쓰고 있습니다. 먼저 켠 서버 창에서 Ctrl+C로 끈 뒤 다시 켜세요."를 보여 주고 서버를 켜지 않고 끝냅니다(종료 코드 1). 포트가 이미 쓰이면 Node.js가 EADDRINUSE 오류를 냅니다. 같은 포트에 서버가 두 개 뜨는 일을 막기 위해서입니다.

### AI가 서버를 켜는 순서

서버는 프롬프트나 사용자가 켜 달라고 할 때 AI가 켭니다. 따로 부탁이 없으면 AI의 터미널이 아니라 새 PowerShell 창을 열어 그 창에서 켭니다. 이 새 창이 서버 창입니다. 사용자는 이 창에서 서버가 보여 주는 줄과 빨간 오류 줄을 봅니다. 사용자가 AI의 터미널에서 켜 달라고 하면, AI 도구에 따라 그 터미널은 30초가 지나면 서버를 끌 수 있다고 한 줄 알린 뒤 부탁대로 합니다. 2회차부터 회차를 시작할 때 사용자가 "서버를 켜 주세요."라고 보내면 같은 순서로 켭니다.

서버는 node --watch로 켭니다("웹 서비스와 폴더"의 package.json). server 폴더의 파일이 바뀌면 서버가 같은 창에서 알아서 다시 켜지므로, 다시 켤 때는 따로 부탁이 없으면 서버를 끄거나 새 창을 열지 않고 서버 창은 하나만 둡니다.

**켜기 전 확인.** 먼저 package.json의 start가 "웹 서비스와 폴더"의 값(`node --watch server/server.js`)인지 봅니다. 다르면 그 값으로 고치고 고쳤다고 한 줄로 알려 줍니다. 사용자가 바꾼 값을 쓰겠다고 하면 그 값으로 둡니다. 그다음 8765번 포트를 듣는 프로세스가 있는지 봅니다.

```powershell
$p = Get-NetTCPConnection -LocalPort 8765 -State Listen -ErrorAction SilentlyContinue | Select-Object -ExpandProperty OwningProcess -Unique; if ($p) { $p } else { '듣는 프로세스 없음' }
```

- 프로세스 번호가 나오면 아래 명령으로 그 번호의 명령 줄을 봅니다. 명령 줄에 package.json의 start에 적힌 시작 파일(이 문서의 구조면 `server/server.js`)이 있으면 서버가 이미 켜져 있는 것입니다. 새로 켜지 않고 "이미 켜져 있습니다"라고 알립니다. 이때 "감시 확인"에 아무것도 나오지 않으면 `--watch` 없이 켠 예전 방식 서버이니 "다시 켤 때"의 마지막 항목대로 합니다.
- 그 시작 파일이 없으면 다른 프로그램이 8765번 포트를 쓰고 있는 것입니다. 서버를 켜지 않고, 어떤 프로그램이 8765번 포트를 쓰고 있는지 사용자에게 알립니다. 사용자가 그 프로그램을 꺼 달라고 하면 끄고, 포트가 빈 것을 확인한 뒤 "새 창에서 켜기"로 켭니다.
- "듣는 프로세스 없음"이 나오면 "감시 확인"을 합니다. 줄이 나오면 서버 창이 열려 있고, 서버가 오류로 멈춘 채 파일이 바뀌기를 기다리는 중입니다. 따로 부탁이 없으면 새 창을 열지 않고 이 창을 씁니다. 서버 코드와 설정 파일을 읽어 원인을 찾아 고친 뒤 "다시 켤 때"대로 같은 창에서 다시 켭니다. 고칠 곳을 찾지 못하면 "다시 켤 때"대로 한 번 다시 켜 보고, 그래도 포트가 비어 있으면 서버 창의 빨간 줄을 복사해 붙여 넣어 달라고 합니다. 감시 확인에도 아무것도 나오지 않으면 아래 "새 창에서 켜기"로 켭니다.

```powershell
Get-CimInstance Win32_Process -Filter "ProcessId=(프로세스 번호)" | Select-Object -ExpandProperty CommandLine
```

**감시 확인.** 서버 창에서 `--watch`로 도는 Node 프로세스가 있는지 봅니다. 포트를 듣는 것은 이 프로세스가 띄운 서버이고, 이 프로세스는 서버가 오류로 멈춰도 창과 함께 남아 있습니다.

```powershell
Get-CimInstance Win32_Process -Filter "Name='node.exe'" | Where-Object { $_.CommandLine -like '* --watch *server/server.js*' } | Select-Object ProcessId, CommandLine
```

**새 창에서 켜기.** 아래 명령으로 새 PowerShell 창을 열고 그 창에서 서버를 켭니다. 프로젝트 폴더가 `C:\vision-ai\vision-risk-dashboard`가 아니면 아래 명령의 경로를 프로젝트 폴더 경로로 바꿉니다. 서버가 꺼진 예전 서버 창이 남아 있으면 사용자에게 알리고, 닫아 달라고 하면 AI가 닫습니다. 명령 앞부분은 프로그램 찾는 경로(PATH)를 다시 읽는 줄입니다. AI 도구를 켠 뒤에 설치한 프로그램(1회차의 Node.js, 4회차의 nlm 등)도 서버 창에서 찾게 합니다.

```powershell
Start-Process powershell -ArgumentList '-NoExit','-Command','$env:Path = [Environment]::GetEnvironmentVariable(''Path'',''Machine'') + '';'' + [Environment]::GetEnvironmentVariable(''Path'',''User''); cd C:\vision-ai\vision-risk-dashboard; npm.cmd start'
```

- 몇 초 뒤 "켜기 전 확인"의 포트 명령으로 8765번 포트를 듣는 프로세스가 생겼는지 봅니다.
- 생겼으면 새 PowerShell 창에서 서버를 켰다고 알리고 주소 http://127.0.0.1:8765 를 알려 줍니다. 사용자가 화면을 열어 달라고 하면 AI가 ego 브라우저로 엽니다.
- 생기지 않았으면 "감시 확인"을 합니다. 줄이 나오면 새 창을 더 열지 않고 원인을 찾아 고친 뒤 "다시 켤 때"대로 같은 창에서 다시 켭니다. 줄이 나오지 않으면(경로가 틀려 서버 창에서 npm.cmd start가 시작되지 않은 경우 등) 원인을 고친 뒤 "새 창에서 켜기"로 다시 켭니다. 원인을 찾지 못하면 서버 창에 나온 빨간 줄을 복사해 붙여 넣어 달라고 합니다.

**다시 켤 때.** 따로 부탁이 없으면 서버를 끄거나 새 창을 열지 않고 같은 창에서 다시 켭니다. 사용자가 끄고 새 창에서 켜 달라고 하면 "끄기"대로 끈 뒤 "새 창에서 켜기"로 켭니다.

- server 폴더의 .js 파일을 고쳤으면 서버가 같은 창에서 알아서 다시 켜집니다. 서버 창에 `Restarting`으로 시작하는 줄과 시작 줄이 다시 나옵니다. 화면 파일(public 폴더)만 고쳤으면 서버는 그대로이고, 서버가 캐시를 끄므로 ego 브라우저에서 새로고침(F5)만 하면 바뀐 화면이 보입니다.
- server 폴더 밖의 파일(package.json, .env, 설정 파일)을 고쳤거나 파일을 고치지 않고 다시 켜야 하면(사용자가 다시 켜 달라고 할 때 등) 시작 파일의 수정 시각만 바꿉니다. 서버가 파일이 바뀐 것으로 보고 같은 창에서 다시 켜집니다. 프로젝트 폴더가 다르면 경로를 바꿉니다.

```powershell
(Get-Item -LiteralPath 'C:\vision-ai\vision-risk-dashboard\server\server.js').LastWriteTime = Get-Date
```

- 다시 켜기 전에 8765번 포트를 듣는 프로세스 번호를 봐 둡니다. 다시 켠 뒤 몇 초 기다렸다가 그 번호가 바뀌었는지 봅니다. 바뀌었으면 다시 켜진 것입니다. 포트가 비어 있으면 원인을 찾아 고친 뒤 위 순서로 다시 켜고, 원인을 찾지 못하면 서버 창의 빨간 줄을 복사해 붙여 넣어 달라고 합니다.
- 포트를 듣는 서버는 있는데 "감시 확인"에 아무것도 나오지 않으면 `--watch` 없이 켠 예전 방식 서버라 알아서 다시 켜지지 않습니다. 이때는 "켜기 전 확인"대로 package.json을 고치고, 8765번 포트를 듣는 프로세스를 끝낸 뒤 포트가 빈 것을 확인하고 "새 창에서 켜기"로 켭니다.
- 프로그램을 새로 설치한 뒤(4회차의 nlm 등) 서버가 그 프로그램을 써야 하면, 같은 창에서 다시 켜는 서버는 설치 전의 경로(PATH)를 그대로 써서 그 프로그램을 찾지 못합니다. 이때는 "끄기"대로 끈 뒤 "새 창에서 켜기"로 켭니다. 새 창 명령이 경로를 다시 읽습니다.

**끄기.** 서버 창을 닫거나 그 창에서 Ctrl+C를 누르면 꺼집니다. "일괄 작업을 끝내시겠습니까 (Y/N)?"가 나오면 `Y`를 칩니다. 사용자가 꺼 달라고 하면 AI가 "감시 확인"에 나온 --watch 프로세스와 8765번 포트를 듣는 프로세스를 끝냅니다.

## 오래 걸리는 명령

AI 도구에 따라서는 AI가 실행하는 명령에 아래 제한이 있습니다. 이 절의 방법은 어느 AI 도구에서나 그대로 씁니다.

- 명령 하나가 30초를 넘으면 그 명령과 그 명령이 띄운 프로그램을 함께 강제로 끝냅니다. 그때까지 나온 글은 AI에게 가지 않고 시간 초과 오류만 갑니다.
- 명령마다 새 PowerShell이 뜹니다. 앞 명령의 `cd`, `$env:Path`, 변수는 다음 명령에 남지 않습니다. 한 번에 여러 명령을 보내면 동시에 실행됩니다.
- 명령에는 입력을 넣을 수 없습니다. y/n이나 값을 묻는 질문에 답하지 못합니다.
- 프로그램 경로는 AI 도구를 켤 때 정해집니다. 그 뒤에 설치한 프로그램은 경로를 다시 읽어야 찾을 수 있습니다.
- AI에게는 명령 결과 하나마다 앞뒤를 합쳐 8,000자쯤(앞 4,000자, 뒤 4,000자쯤)만 가고 가운데는 빠집니다.
- `Start-Process`로 새 창을 띄우고 바로 끝나는 명령은 30초 제한에 걸리지 않고, 새 창은 그대로 남습니다. 같은 명령 안에서 새 창을 기다리면 30초에 새 창까지 함께 꺼집니다. 서버를 켜는 명령(이 문서의 서버 켜기 절)이 새 창을 띄우고 바로 끝나는 것도 이 때문입니다.
- 실행 중인 명령을 떼어 계속 돌리는 단추가 AI 도구에 있어도 사용자에게 누르라고 하지 않고, 이 절의 새 창 방식으로 합니다.

### 한 명령에 담기

- 명령은 한 번에 하나씩 보냅니다. 순서가 있는 명령은 한 명령 안에 `;`로 잇습니다. `&&`는 PowerShell 판에 따라 문법 오류가 나므로 쓰지 않습니다. 이어 쓴 명령이 합쳐서 30초를 넘길 수 있으면 하나씩 따로 보내거나 아래 "새 창에서 실행하기"로 합니다.
- `;`로 이은 뒤 명령은 앞 명령이 실패해도 실행됩니다. 앞 명령이 성공해야 하는 명령(올리기 뒤 배포 등)은 잇지 않고 따로 보내, 결과를 본 뒤 다음을 보냅니다.
- 다른 폴더에서 할 명령은 그 명령 앞에 `cd '(폴더 전체 경로)';`를 둡니다. 따로 보낸 `cd`는 다음 명령에 남지 않습니다.
- 경로 다시 읽기: `ego-browser`를 부르는 명령과 이 대화에서 설치한 프로그램을 부르는 명령에는 늘 맨 앞에 아래 줄을 붙이고 `<명령>` 자리에 부를 명령을 넣습니다. 그 밖의 명령도 찾지 못하면 이 줄을 붙여 다시 실행합니다. 이 줄만 따로 실행하면 다음 명령에 남지 않습니다. 그래도 찾지 못하면 그 프로그램 실행 파일의 전체 경로로 부릅니다.

```powershell
$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User'); <명령>
```

- 외부 프로그램에 넘기는 글: `curl.exe`, `git`, `ego-browser` 같은 외부 프로그램의 인자 안에 큰따옴표를 넣지 않습니다. PowerShell 판에 따라 큰따옴표가 사라집니다. 외부 프로그램에 파이프(`|`)로 한글을 넘기지도 않습니다. 판에 따라 `?`로 바뀝니다. 큰따옴표가 든 글(JSON 본문 등)과 브라우저 스크립트는 AI 도구의 파일 쓰기로 파일에 저장한 뒤 파일로 넘깁니다. 예: `curl.exe`의 본문은 `--data-binary '@(파일 전체 경로)'`, 브라우저 스크립트는 아래 "ego 브라우저"의 꼴. `npm.cmd`처럼 `.cmd`로 설치된 명령도 같습니다. 작은따옴표로 감싼 인자 속 한글(예: `git commit -m '고친 내용'`)은 이 규칙에 들지 않습니다.
- 묻는 명령: 묻지 않게 하는 옵션을 붙입니다. 예: `npx --yes`, `Remove-Item -Force`, `winget install (이름) --accept-source-agreements --accept-package-agreements`.
- `2>&1`: `git`, `npm.cmd` 같은 프로그램의 출력에 `2>&1`이나 `2>(파일)`을 붙이면 경고 한 줄에도 명령이 멈출 수 있습니다. 붙여야 하면 같은 명령 맨 앞에 `$ErrorActionPreference='Continue';`를 둡니다.
- 출력 줄이기: 출력이 길 것 같으면 `| Select-Object -Last 40`이나 `| Select-String '(찾을 글)'`을 붙여 필요한 줄만 봅니다. 파일 전체를 봐야 하면 아래 "긴 출력 읽기"대로 합니다.

### 새 창에서 실행하기

아래 명령은 새 창에서 실행합니다. 빌드나 확인처럼 몇 초면 끝나는 명령만 AI가 명령을 실행하는 터미널에서 합니다. 서버를 켜는 일은 이 절이 아니라 이 문서의 서버 켜기 절을 따릅니다.

- 설치: 프로그램 설치, `npm.cmd install`, `npx`로 패키지를 처음 내려받는 명령. 설치는 늘 새 창에서 합니다.
- 30초를 넘길 수 있는 그 밖의 명령: 큰 저장소의 clone이나 첫 fetch, 회차 문서가 새 창에서 하라고 한 명령
- 로그인이 끝날 때까지 기다리는 명령: `gas:login` 같은 로그인 명령, `git push`(처음 올릴 때 Git 로그인 창이 뜨고 기다립니다)
- AI가 명령을 실행하는 터미널에서 30초에 끊긴 적이 있는 명령

`<명령>` 자리에 그 명령을 넣어(꺾쇠도 지웁니다) 실행합니다.

```powershell
Remove-Item $env:TEMP\ai-cmd.log -ErrorAction SilentlyContinue; (Start-Process powershell -PassThru -WorkingDirectory (Get-Location).Path -ArgumentList '-Command','$env:Path = [Environment]::GetEnvironmentVariable(''Path'',''Machine'') + '';'' + [Environment]::GetEnvironmentVariable(''Path'',''User''); [Console]::OutputEncoding = [Text.Encoding]::UTF8; & { <명령> 2>&1; ''AI-CMD-END:'' + $LASTEXITCODE } | ForEach-Object ToString | Tee-Object -FilePath $env:TEMP\ai-cmd.log').Id
```

- 이 명령은 이전 출력 파일을 지우고 새 창을 연 뒤 그 창의 프로세스 번호만 보여 주고 바로 끝납니다. 그래서 이 명령에는 기다리기나 확인을 붙이지 않습니다. 보여 준 번호는 끝났는지 볼 때 씁니다.
- 새 창은 경로를 다시 읽은 뒤 명령을 실행하므로, AI 도구를 연 뒤 설치한 프로그램도 찾습니다.
- `<명령>`에 든 따옴표는 큰따옴표든 작은따옴표든 모두 작은따옴표 두 개(`''`)로 바꿔 씁니다. 큰따옴표를 그대로 두면 새 창에 닿기 전에 사라집니다. 예: uv 설치는 `powershell -ExecutionPolicy ByPass -c ''irm https://astral.sh/uv/install.ps1 | iex''`입니다.
- `<명령>`에 `$env:…`를 넣지 말고, 그 값을 먼저 실행해 얻은 뒤 풀어 적습니다.
- 새 창은 이 명령을 실행한 폴더에서 시작합니다. 다른 폴더에서 실행해야 하면 `(Get-Location).Path`를 `'(폴더 전체 경로)'`로 바꿉니다.
- 환경 변수가 필요하면 같은 줄의 `Start-Process` 앞에 `$env:이름='값';`으로 둡니다.
- 새 창은 명령이 끝나면 저절로 닫힙니다. 출력은 `$env:TEMP\ai-cmd.log`에 남고, 마지막 줄에 `AI-CMD-END:(종료 코드)` 줄이 찍힙니다.
- 새 창에서 실행하는 명령은 한 번에 하나만 띄웁니다. 같은 출력 파일을 쓰므로, 앞 명령의 `AI-CMD-END` 줄을 본 뒤 다음 명령을 띄웁니다.

### 끝났는지 보기

아래 명령으로 15초 기다린 뒤 출력 파일의 끝 30줄을 봅니다. 한 번에 20초를 넘지 않으므로 `AI-CMD-END` 줄이 나올 때까지 이 명령을 되풀이합니다.

```powershell
Start-Sleep -Seconds 15; if (Test-Path $env:TEMP\ai-cmd.log) { Get-Content $env:TEMP\ai-cmd.log -Tail 30 } else { '아직 출력 파일이 없습니다' }
```

- `ai-cmd.log`는 AI 도구의 파일 읽기로 열지 않고 위 명령의 `Get-Content`로만 봅니다. 더 보려면 `-Tail` 숫자를 늘립니다.
- 마지막 줄이 `AI-CMD-END:0`이면 명령이 끝난 것입니다. 성공했는지는 그 위 글을 그 명령의 성공 기준과 맞춰 봅니다. 회차 문서에 성공 기준이 있으면 그 기준을 씁니다.
- `AI-CMD-END:` 뒤가 0이 아닌 숫자면 실패입니다. 그 위 글로 원인을 봅니다.
- `AI-CMD-END:` 뒤가 비어 있으면 종료 코드를 남기지 않는 PowerShell 명령입니다. 그 위 글로 성공했는지 봅니다.
- `AI-CMD-END` 줄이 없으면 새 창을 열 때 나온 번호로 아래 명령을 실행합니다. "실행 중"이면(출력 파일이 아직 없어도 첫 출력 전입니다) 새 창을 다시 띄우지 않고 위 확인을 되풀이합니다. "창이 닫혔습니다"면 창이 중간에 닫힌 것입니다. 그 위 글을 보고, 아래 "시간 초과로 끊겼을 때"처럼 결과가 이미 생겼는지 먼저 본 뒤 필요할 때만 다시 실행합니다.

```powershell
if (Get-Process -Id (번호) -ErrorAction SilentlyContinue) { '실행 중' } else { '창이 닫혔습니다' }
```

- 로그인을 기다리는 명령이 아닌데 10번(약 3분) 확인해도 로그 끝이 그대로면, 새 창이 무엇을 묻고 멈췄을 수 있습니다. 새 창에 보이는 글을 알려 달라고 하고 답을 끝냅니다.
- 로그인을 기다리는 명령은 아래 "사용자에게 넘기는 일"대로 합니다.

### 기다리기

- 문서나 따라하기에 "1분 기다린다"처럼 긴 기다림이 있으면 `Start-Sleep -Seconds 20` 이하로 나눠 여러 번 실행합니다. 기다린 뒤 확인까지 한 명령에 담으면 합쳐서 20초 이하로 합니다. 예: `Start-Sleep -Seconds 15; (확인 명령)`.
- 무엇이 생길 때까지 되풀이하는 고리(`while` 등)를 한 명령에 쓰지 않습니다. 확인 명령을 여러 번 보냅니다.

### 시간 초과로 끊겼을 때

- 30초에 끊긴 명령은 시간 초과 오류만 남고 출력은 오지 않습니다. 실패가 아니라 어디까지 됐는지 모르는 상태입니다.
- 다시 실행하기 전에 그 명령의 결과가 이미 생겼는지 먼저 봅니다. 예: 만들어진 파일이나 폴더, 설치된 명령의 버전, Google 쪽 배포 목록, 시트의 끝 줄.
- 결과가 생겼으면 다시 실행하지 않습니다. 생기지 않았으면 "새 창에서 실행하기"로 다시 실행합니다. 설치가 중간에 끊겼으면 새 창에서 같은 설치를 다시 실행합니다.
- ego 브라우저에서 단추를 누르는 실행이 끊겼을 때도 같습니다. 같은 단추를 다시 누르기 전에 결과가 생겼는지 먼저 봅니다.

### 긴 출력 읽기

- 출력이 8,000자를 넘을 것 같으면(긴 파일을 `git --no-pager show`로 읽을 때 등) 파일로 저장합니다. 마지막 부분은 저장한 파일의 전체 경로를 보여 줍니다.

```powershell
[Console]::OutputEncoding = [Text.Encoding]::UTF8; <명령> | Out-File -Encoding utf8 -FilePath "$env:TEMP\ai-out.txt"; "$env:TEMP\ai-out.txt"
```

- 저장한 파일은 AI 도구의 파일 읽기로, 위 명령이 보여 준 전체 경로를 열어 읽습니다. 한 번에 다 나오지 않으면 나눠 읽습니다.
- 파일 읽기로 열지 못하면 아래 명령으로 7,000자씩 읽습니다. 처음에는 `$s = 0`이고, 다음 조각은 `7000`, `14000`처럼 7,000씩 늘립니다.

```powershell
$s = 0; $t = Get-Content -Raw -Encoding UTF8 "$env:TEMP\ai-out.txt"; $t.Substring($s, [Math]::Min(7000, $t.Length - $s))
```

### ego 브라우저

- 이 대화에서 ego 브라우저를 처음 쓸 때 아래 명령으로 사용법 안내를 파일로 저장하고, "긴 출력 읽기"대로 첫 줄부터 `[ego-browser:skill] end of guide`로 시작하는 끝 줄까지 읽습니다. 안내를 명령 출력으로 바로 보면 가운데가 빠져도 끝 줄은 남아서 다 읽은 것처럼 보이므로, 꼭 파일로 읽습니다. 이 대화에서 이미 읽었으면 다시 읽지 않습니다.

```powershell
$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User'); [Console]::OutputEncoding = [Text.Encoding]::UTF8; ego-browser skill | Out-File -Encoding utf8 -FilePath "$env:TEMP\ego-browser-skill.md"; "$env:TEMP\ego-browser-skill.md"
```

- 스크립트는 파일로 넘깁니다. `-e`로 인자에 넣거나 파이프(`|`)로 넘기지 않습니다. 먼저 `$env:TEMP`를 실행해 임시 폴더의 전체 경로를 보고, AI 도구의 파일 쓰기로 `(그 전체 경로)\ego-script.js`에 UTF-8로 저장합니다. 파일 쓰기에 `$env:TEMP`나 `%TEMP%`를 글자 그대로 쓰지 않습니다. 그 글자 이름의 폴더가 작업 폴더 안에 생깁니다.
- 첫 실행은 아래처럼 작업 공간(TaskSpace)을 만들고 그 번호를 찍습니다. 다음 실행부터는 `taskSpace("(작업 이름)")` 대신 찍힌 번호로 `await taskSpace((번호))`를 씁니다. 다음 답에서 같은 일을 이어 갈 때는 사용법 안내의 "Starting and ending a reply"대로 그 번호로 잇습니다.

```javascript
const task = await taskSpace("(작업 이름)");
const page = task.page("p1");
await page.goto("(주소)", { timeout: 15000 });
console.log({ taskSpaceId: task.spaceId });
console.log(String(await page.snapshot()).slice(0, 7000));
```

- 그다음 아래 명령으로 실행합니다. 실행이 끝나면 스크립트 파일을 지우고 ego 브라우저의 종료 코드를 찍습니다. 스크립트를 바꿀 때마다 파일을 다시 저장하고 이 명령을 다시 실행합니다.

```powershell
$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User'); [Console]::OutputEncoding = [Text.Encoding]::UTF8; cmd /c "ego-browser nodejs < %TEMP%\ego-script.js"; $c = $LASTEXITCODE; Remove-Item $env:TEMP\ego-script.js; "ego-browser 종료 코드: $c"
```

- 한 번 실행은 20초 안에 끝나게 합니다. 한 실행에는 동작 하나와 짧은 확인만 담고, 한 실행 안의 `timeout`을 모두 더해 15초(15000) 이하로 줍니다.
- 찍는 글도 8,000자를 넘으면 가운데가 빠집니다. 위 예처럼 `.slice(0, 7000)`으로 자르고, 더 봐야 하면 `.slice(7000, 14000)`처럼 다음 실행에서 이어서 찍습니다.
- 몇 분 걸리는 일(처리 결과 기다리기, 학습 등)은 단추를 누르는 실행과 결과를 보는 실행을 나누고, 결과 보기를 20초 이하로 여러 번 합니다.
- 사람이 브라우저에서 해야 하는 순간이 오면 `await task.handOff()` 뒤 그 실행을 끝내고, 무엇을 하면 되는지 한 줄로 알린 뒤 답을 끝냅니다. `waitForControl()`로 같은 실행 안에서 기다리지 않습니다. 사용자가 마쳤다고 하면 `const task = await takeOverTaskSpace((번호));`로 같은 작업 공간을 이어받고, `task.userPage()`로 사용자가 보던 페이지를 씁니다.

### 사용자에게 넘기는 일

- 사람이 해야 하는 순간의 예: 비밀번호와 본인 확인 같은 로그인 단계, 설치 승인 창(사용자 계정 컨트롤), Git 로그인 창이나 로그인 명령이 연 Chrome 창처럼 AI가 누를 수 없는 창.
- 로그인 명령의 출력("끝났는지 보기" 명령으로 본 글)에 로그인 주소가 나오면 그 주소를 ego 브라우저에서 열어 AI가 할 수 있는 데까지 합니다. 비밀번호, 본인 확인, AI가 누를 수 없는 창에서만 할 일을 알리고 답을 끝냅니다.
- 그 순간을 만드는 명령은 "새 창에서 실행하기"로 띄우고, 브라우저 안의 일은 `task.handOff()`로 넘깁니다. 그다음 무엇을 하면 되는지 한 줄로 알리고 답을 끝냅니다. 한 명령 안에서 사람이 마치기를 기다리지 않습니다.
- 사용자가 마쳤다고 하면 "끝났는지 보기"나 그 일의 확인 명령으로 보고 이어서 합니다.

## 화면 파일 보내기

- 서버는 public 폴더의 파일만 브라우저에 보냅니다. 주소 /는 public/index.html입니다.
- 파일을 보낼 때 종류를 알려 줍니다. html은 text/html, css는 text/css, js는 text/javascript, png는 image/png, jpg와 jpeg는 image/jpeg, json은 application/json이고 글자 파일에는 charset=utf-8을 붙입니다. 그 밖은 application/octet-stream입니다.
- public 폴더에 없는 파일은 404와 "Not found" 글로 답합니다.
- 브라우저가 옛 화면을 기억하지 않게 모든 답에서 캐시를 사용하지 않습니다(Cache-Control: no-store).

## 데이터 주소

- 화면이 쓰는 데이터 주소는 /api/ 로 시작하고 JSON으로 답합니다. 답의 Content-Type은 `application/json; charset=utf-8`입니다.
- 오류는 `{"error": "한국어 문장"}` 모양으로 답합니다. 뒤 회차 문서가 오류에 다른 항목을 더할 수 있습니다.
- /api/ 로 시작하는데 없는 주소는 404와 `{"error": "없는 데이터 주소입니다."}`로 답합니다. 있는 주소라도 정해진 방식(GET 등)이 아니면 같습니다.
- 데이터 주소를 처리하다 예상하지 못한 오류가 나면(예: 기준 목록 파일의 JSON이 틀림) 500과 `{"error": "(오류 문장)"}`로 답합니다.
- GET /api/health: 서버가 켜져 있는지 봅니다. `{"status": "ok"}`로 답합니다. 뒤 회차 문서가 항목을 더할 수 있습니다.
- GET /api/standards: materials/standards.json 내용을 그대로 돌려줍니다. 파일이 없으면 `{"standards": []}`로 답합니다.

## 확인 기준 목록

확인 기준 목록은 지급 자료 materials/standards.json에 있습니다.

- standards 목록의 한 줄이 기준 하나입니다.
- id는 번호(C-01~C-09), name은 이름, category는 분류, hazard_condition은 추가 확인 조건, hold_condition은 판단 보류 조건, canonical_quote는 원문 인용, notes는 참고입니다.
- category가 quality면 화면에 "택배 발송 확인", safety면 "산업안전"으로 보입니다.

## 화면 공통

### 화면 바꾸기

- 화면 글은 모두 한국어입니다. 브라우저 탭 제목은 "Vision QC"입니다.
- 화면은 주소 끝 # 뒤 이름으로 바꿉니다. #dashboard와 # 없음은 홈, #models는 확인 기준 화면이고 모르는 이름이면 홈을 보여 줍니다. 뒤 회차 문서가 화면을 더합니다.
- 주소 끝이 바뀌면 화면을 다시 그립니다. 화면이 바뀌면 맨 위로 올라갑니다. 같은 화면을 다시 그릴 때(예: 데이터를 받은 뒤)는 올라가지 않습니다. 브라우저 뒤로 가기를 누르면 앞 화면으로 돌아갑니다.

### 서버에 요청하기

- 화면의 모든 요청은 공통 함수 하나를 거칩니다. 이 함수가 연결 표시와 알림 줄이 쓰는 상태(요청 중, 연결됨, 오류)를 바꿉니다.
- 요청이 여러 개면 모두 끝나야 요청 중 상태가 끝납니다.
- 요청을 시작할 때와 끝날 때마다 연결 표시와 알림 줄을 다시 그립니다. 알림 줄은 프롬프트가 요청할 때 만들고, 그 전에는 연결 표시만 다시 그립니다. 화면 전체를 다시 그리지 않아도 됩니다.
- 요청이 성공하면 오류 상태를 지우고 연결됨으로 둡니다.
- 서버에 연결하지 못했거나 500번대로 답하면 오류 상태에 이유를 넣습니다. 500번대면 연결됨도 풉니다.
- 400번대로 답하면 오류 상태를 바꾸지 않습니다. 이유는 그 요청을 보낸 화면이 자기 자리에 보여 줍니다.

### 머리말과 본문

- 모든 화면 맨 위에 머리말이 있습니다. 왼쪽은 로고 그림과 "현장 리스크 대시보드"이고 누르면 홈으로 갑니다. 오른쪽은 연결 표시입니다.
- 로고 그림은 materials/factory-logo.png를 public 폴더 안 assets 폴더로 복사해서 씁니다(public/assets/factory-logo.png). 화면에는 가로세로 44로 보입니다.
- 머리말 아래가 화면마다 바뀌는 본문입니다. 본문은 위에서부터 길잡이 줄, 알림 줄, 화면 내용 순서입니다.
- 홈이 아닌 화면은 "← 홈으로 / (화면 이름)" 같은 길잡이 줄을 두고 앞부분을 누르면 그 화면으로 갑니다. 홈에는 길잡이 줄이 없습니다.

### 연결 표시

- 처음엔 "연결 대기", 서버에 요청하는 중이면 "연결 확인 중...", 답을 받으면 "데이터 연결됨", 실패하면 "조회 실패 ((이유))"입니다. 네 가지 글 중 하나만 보입니다.
- 위에서부터 차례로 따져 정합니다. 요청 중이고 아직 연결되지 않았으면 "연결 확인 중...", 오류 상태가 있으면 "조회 실패 ((이유))", 연결됐으면 "데이터 연결됨", 모두 아니면 "연결 대기"입니다.
- 한 번 연결된 뒤에는 요청 중에도 "데이터 연결됨"을 유지합니다.
- 서버가 400번대 오류로 답한 것은 연결 실패로 치지 않고 연결 표시를 그대로 둡니다(아직 연결된 적이 없으면 "연결 대기"). 서버가 잘못된 요청이라고 답한 것은 서버가 정상으로 답한 것이기 때문입니다.
- 실패한 뒤 다음 요청이 성공하면 다시 "데이터 연결됨"이 됩니다.

### 알림 줄

- 요청 중이면 "처리 중...", 오류가 있으면 "오류: (이유)"를 보여 주고 둘 다 아니면 비워 둡니다. 요청 중인지를 먼저 봅니다.
- 오류 이유는 서버가 보낸 error 문장을 그대로 씁니다.
- 여기서 오류는 위 "서버에 요청하기"의 오류 상태입니다. 400번대 답은 알림 줄에 저절로 나오지 않습니다.
- 서버에 연결하지 못해 실패하면 이유는 "로컬 서버에 연결하지 못했습니다. 터미널에서 npm.cmd start(macOS: npm start)가 켜져 있는지 확인하세요."입니다. 브라우저의 영어 오류 문장을 그대로 보여 주지 않기 위해서입니다.

### 화면 그리기

- 서버에서 받은 글은 화면에 글자 그대로 넣습니다. HTML로 넣지 않습니다.
- 화면 틀은 데이터를 받기 전에 먼저 보여 줍니다. 확인 기준 목록은 웹 서비스를 처음 열 때 한 번 받아 두고 확인 기준 화면은 그 목록을 씁니다.

## 홈 화면

- 제목은 "현장 리스크 확인"입니다.
- "확인 기준 보기" 단추를 누르면 확인 기준 화면(#models)으로 갑니다.

## 확인 기준 화면

- 제목은 "확인 기준"이고 제목 아래 설명은 "물류창고에서 구매자에게 택배를 보내기 전 확인할 발송·산업안전 기준입니다. 사진만으로 주문 일치나 배송 완료를 확정하지 않습니다."입니다.
- 위쪽 길잡이 줄은 "← 홈으로 / 확인 기준"이고 "← 홈으로"를 누르면 홈으로 갑니다.
- 제목 오른쪽에도 "← 홈으로" 단추가 있고 누르면 홈으로 갑니다. 길잡이 줄과 함께 둡니다.
- 제목 아래에 "택배 발송·산업안전 기준" 상자가 있고 그 안에 확인 기준 목록을 표로 보여 줍니다.

### 확인 기준 표

- 열은 항목, 분류, 추가 확인 조건, 판단 보류 조건, 원문 인용입니다.
- 항목 칸은 "C-01 · 머리 보호구"처럼 번호와 이름을 " · "로 이어 씁니다.
- 분류 칸은 위 "확인 기준 목록"에 적은 대로 "택배 발송 확인" 또는 "산업안전"입니다.
- 원문 인용 칸은 글을 큰따옴표로 감쌉니다.
- 표 한 줄이 기준 하나이고 지급 자료대로라면 9줄입니다.

## 설정 파일

설정 파일 config/local-connection.json은 키와 연결 정보를 넣는 JSON 파일입니다.

- 서버가 켜질 때 한 번 읽습니다. 파일이 없으면 그대로 켭니다. 파일 맨 앞에 메모장이 붙이는 표시(BOM)가 있으면 지우고 읽습니다.
- JSON 형식이 틀리면 오류 원문은 보여 주지 말고 "설정 파일의 JSON 형식이 올바르지 않습니다: 3행 5열"처럼 몇 행 몇 열인지만 알립니다(모르면 "설정 파일의 JSON 형식이 올바르지 않습니다: 문법 오류"). 그리고 서버를 켜지 않고 끝냅니다. 오류 원문에는 파일 내용이 들어갈 수 있어서 위치만 알립니다. 행과 열은 1부터 세고 JSON.parse 오류 문장에 든 위치 값으로 계산합니다.
- JSON이 맞아도 `{ }`로 감싼 모양이 아니면 "설정 파일은 { } 로 감싼 JSON 객체여야 한다."를 보여 주고 서버를 켜지 않고 끝냅니다.
- 쓰는 키는 회차 문서에 적힌 것뿐입니다. 그 밖의 키는 "설정 경고: 알 수 없는 설정 키 (키 이름)는 무시한다." 한 줄로 이름만 알리고 넘어갑니다. 예: 설정 경고: 알 수 없는 설정 키 TEST_KEY는 무시한다.
- 키 이름은 대문자·숫자·밑줄로 쓰고 40자까지입니다. 이 모양이 아닌 키는 값을 잘못 붙여 넣은 것일 수 있어 이름도 보여 주지 않고 개수만 "설정 경고: 형식이 맞지 않는 키 (개수)개는 무시한다. 키 이름은 대문자·숫자·밑줄로 쓴다."로 알립니다.
- 값은 모두 따옴표로 감싼 글자입니다. 쓰는 키의 값이 글자가 아니면 "설정 경고: (키 이름) 값은 문자열이어야 한다. 이 값은 무시한다."로 알립니다. 서버는 키의 값을 서버 창과 웹 서비스 화면에 찍지 않습니다.
- 예시 파일 config/local-connection.example.json에는 쓰는 키를 모두 빈 값("")으로 적습니다. 키가 없으면 `{ }`입니다. 뒤 회차 문서가 키를 더하면 예시 파일에도 더합니다.

이 회차에는 쓰는 키가 없습니다.

## 지급 자료

materials 폴더는 강사가 준 원문 자료입니다.

- 확인 기준 목록 standards.json, 로고 factory-logo.png, 기준 원문 factory-criteria-v1.txt, Gemini 지시문 gemini-prompt.txt, 안내 README.md가 들어 있습니다.
- 프롬프트를 따를 때는 이 폴더의 파일을 고치거나 옮기지 않고, 필요하면 읽거나 다른 폴더로 복사해서 씁니다. 사용자가 고쳐 달라고 하면 고치고, 1회차 첫 프롬프트를 다시 보내 수업 저장소에서 가져오면 덮어써진다고 한 줄로 알려 줍니다.

## 만들지 않는 것

- 퍼센트 인코딩 주소 검사와 풀 수 없는 주소의 400(Malformed URI encoding) 답: 혼자 쓰는 연습용 웹 서비스라 만들지 않습니다.
- 화면 파일 주소에 GET·HEAD가 아닌 요청을 405로 거절하는 검사: 혼자 쓰는 연습용 웹 서비스라 만들지 않습니다.
- public 폴더 밖 파일, 이름이 점(.)으로 시작하는 파일, 이름에 .env가 든 파일을 403으로 거절하는 검사: 혼자 쓰는 연습용 웹 서비스라 만들지 않습니다.
- 다른 사이트에서 온 요청(Origin 헤더) 거절: 혼자 쓰는 연습용 웹 서비스라 만들지 않습니다.
- 확인 기준 표 자리의 "불러오는 중"·"조회 실패" 문구: 기준은 금방 받아지고 실패하면 알림 줄과 연결 표시에 나오므로 만들지 않습니다.
