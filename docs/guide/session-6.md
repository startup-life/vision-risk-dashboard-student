# 6회차 보충 문서: Teachable Machine 모델 학습과 모델 예측

이 회차는 앱에 모델 학습 화면을 더하고 학습한 모델의 예측을 사건 상세에 넣습니다. 사용자가 제공 사진을 직접 분류해 브라우저 안에서 모델을 학습하고 검증과 비교, 적용까지 이 화면에서 합니다. 5회차까지 네 단계였던 사건 상세는 다섯 단계가 되고 새 3단계의 모델 예측이 관련 기준 확인과 판단 화면의 참고 칸에도 들어갑니다. 앞 회차 문서와 다른 부분은 이 문서를 따릅니다.

## 학습 준비: 패키지와 준비 명령

학습에는 패키지 세 개와 준비 명령 하나가 필요합니다. 이 문서에서 "화면 폴더"는 1회차 문서의 public 폴더입니다. 이미 있는 코드가 화면 파일을 다른 폴더에 두면 index.html이 있는 그 폴더를 화면 폴더로 읽고 새 public 폴더를 만들지 않습니다.

- 학습용 패키지는 @teachablemachine/image 0.8.5, @tensorflow/tfjs 1.3.1, esbuild 0.25.10 세 개입니다. package.json에 버전 앞 ^ 없이 이 버전 그대로 적고 "overrides": { "node-fetch": "2.7.0" }도 넣습니다. 설치는 npm.cmd install로 하고 이미 있는 패키지는 바꾸지 않습니다.
- 준비 명령은 npm.cmd run setup:tm입니다(package.json의 setup:tm). 사용자가 서버 창이 아닌 터미널에서 한 번 실행합니다. 인터넷이 필요합니다.
- 준비 명령의 첫째 일: esbuild로 @tensorflow/tfjs와 @teachablemachine/image를 한 파일로 묶어 화면 폴더의 vendor/tm/runtime.js로 저장합니다. 브라우저에서 이 파일을 불러오면 window.tf와 window.tmImage로 쓸 수 있어야 합니다. 묶는 입구 파일은 import * as tf from '@tensorflow/tfjs', import * as tmImage from '@teachablemachine/image'로 불러와 window.tf와 window.tmImage에 넣는 네 줄이고 esbuild 설정은 bundle: true, minify: true, platform: 'browser'입니다.
- 준비 명령의 둘째 일: 기초 모델 MobileNet v2(0.35)를 https://storage.googleapis.com/teachable-machine-models/mobilenet_v2_weights_tf_dim_ordering_tf_kernels_0.35_224_no_top/ 에서 받아 화면 폴더의 vendor/tm-v2/에 같은 이름으로 저장합니다. 그 주소의 model.json을 읽고 거기 적힌 가중치 파일(weightsManifest 안의 paths)을 모두 받은 뒤 model.json을 마지막에 저장합니다. 받다가 실패하면 어느 파일이 실패했는지 알리고 멈춥니다.
- 화면 폴더의 vendor 폴더는 git에 올리지 않습니다(.gitignore). 브라우저는 /vendor/tm/runtime.js, /vendor/tm-v2/model.json 주소로 엽니다.

## 학습 자료 저장

학습 사진과 모델은 이 PC에만 저장합니다.

- 설정 키 VISION_TM_ROOT: 학습 자료를 저장할 폴더입니다. 비어 있으면 사건 기록 위치와 상관없이 프로젝트 맨 위 runtime 폴더 안의 teachable 폴더(runtime/teachable)를 씁니다. runtime 폴더는 2회차 문서대로 git에 올리지 않고 브라우저에도 보내지 않습니다. 이 키는 설정 파일에서 쓰는 키 목록과 예시 파일에 더합니다.
- 그 폴더 안에 프로젝트(projects), 사진 파일(images, 파일 이름은 사진 해시), 모델 버전(versions/버전 ID 폴더), 적용 모델(active.json), 사건별 모델 예측(predictions/사건 번호.json)을 둡니다.
- 사진 해시는 사진 파일 내용의 SHA-256(소문자 16진수 64자)입니다.
- 학습 데이터 주소(/api/tm/ 로 시작)는 요청 하나를 20MB까지 받습니다. 사진과 모델을 base64 글자로 보내기 때문입니다.
- 프로젝트, 사진 항목, 모델 버전의 id는 모두 무작위 ID(crypto.randomUUID)입니다.
- 학습 데이터 주소의 POST는 201로 답합니다. 이미 있는 것을 그대로 돌려줄 때도 201이고 적용 모델 저장(POST /api/tm/active)만 200입니다. 아래 문구로 막을 때는 따로 적지 않았으면 400이고 답 모양은 1회차 문서의 오류 모양과 같습니다.
- 서버의 학습 데이터 코드와 화면의 학습 코드는 기존 파일에 섞지 않고 각각 새 파일 하나에 둡니다. 파일 이름은 정해져 있지 않습니다. 화면의 학습 코드를 새 파일에 두면 기존 화면 파일 안에서만 선언한 함수는 부를 수 없습니다. 서버에서 받은 글자를 화면에 넣을 때는 textContent로 넣거나 HTML 이스케이프 함수를 그 파일 안에 따로 둡니다.

## 학습 프로젝트

프로젝트는 분류 하나의 사진과 모델 버전을 묶어 둔 것입니다. 종류(track)는 택배 발송(quality)과 산업안전(safety)입니다.

- 프로젝트 저장 항목: id(무작위 ID), track, name("택배 발송 모델" 또는 "산업안전 모델"), classes(유형 목록), samples(사진 목록, 처음엔 빈 목록), versions(모델 버전 목록, 처음엔 빈 목록), created_at(만든 시각).
- 유형 목록은 이 순서 그대로입니다. 택배 발송: 정상, 찌그러짐, 찢어짐, 오염, 라벨 누락, 마개 누락. 산업안전: 안전, 보호구 미착용, 위험선 침범, 통로 적치, 미끄럼 위험.
- GET /api/tm/projects: 프로젝트 목록(배열)입니다. 없으면 []입니다.
- POST /api/tm/projects: {"track": "quality"}처럼 받아 새 프로젝트를 만들어 돌려줍니다. track이 quality나 safety가 아니면 "품질 또는 산업안전을 선택해 주세요."입니다.
- GET /api/tm/projects/(프로젝트 ID): 프로젝트 하나입니다. 없으면 404와 "프로젝트를 찾을 수 없습니다."입니다.

## 제공 사진

제공 사진은 옆 폴더 사진 저장소의 학습용 사진입니다. 2회차에 저장소 사진 목록을 읽은 방식 그대로(같은 목록 파일, 같은 해시 대조) 읽습니다. 목록 파일은 사진 저장소 origin/main 커밋에 든 metadata/generation_manifest.csv입니다.

- 쓰는 사진은 상태(status)가 accepted, 시퀀스 ID(sequence_id)가 빈칸, 용도(split)가 train 또는 val, 분류(track)가 quality 또는 safety인 것뿐입니다. image_id는 Q-IND-042, S-IND-042 모양입니다.
- 제공 사진에는 정답 유형이 없습니다. 유형은 사용자가 사진을 보고 직접 고릅니다. 목록에 유형(subtype 등)을 넣지 않습니다.
- GET /api/tm/catalog: {"images": [{"image_id", "track", "split", "sha256"}, …], "error": 오류 문구 또는 null}입니다. 사진은 해시 순서로 정렬합니다. 사진 저장소를 읽지 못하면 images는 빈 목록이고 error에 이유를 넣되 내 PC 경로는 넣지 않습니다.
- 사진 목록 파일에서 용도가 test인 사진은 파일 없이 해시만 있습니다. 이 해시들을 기억해 두고 학습에 넣지 못하게 막습니다.
- GET /api/tm/images/(사진 해시): 제공 사진이나 프로젝트에 넣은 사진(버전에 남긴 사진 기록 포함)의 파일을 보냅니다. 답의 Content-Type은 그 사진의 형식입니다. 1회차 문서의 캐시 끄기는 이 주소에서 Cache-Control: private, max-age=3600으로 바꿔 브라우저가 기억해도 되게 합니다. 없으면 404입니다.

## 사진 넣기와 빼기

POST /api/tm/projects/(프로젝트 ID)/samples: 제공 사진은 {"pack_id": 사진 번호, "label": 유형, "split": "train" 또는 "val"}, 직접 올린 사진은 {"label", "split", "filename", "base64"}로 받습니다. 사진 파일을 저장 폴더에 두고 프로젝트 사진 목록에 {id, sha256, mime, label, split, source}를 더해 돌려줍니다.

값의 뜻은 이렇습니다.

- 사진 번호(pack_id)는 제공 사진 목록의 image_id(예: Q-IND-042)입니다. 화면의 "제공 사진 3"에 쓰는 3은 목록 안의 순서일 뿐 이 값이 아닙니다.
- mime은 image/png 또는 image/jpeg이고 제공 사진은 image/png입니다.
- source는 제공 사진이면 {"id": image_id, "commit": 사진 저장소 커밋, "asset_version": "v0.95"}, 직접 올린 사진이면 {"uploaded": true, "filename": 파일 이름 앞 120자}입니다.

아래 경우에는 넣지 않습니다. 문구는 항목마다 적었습니다.

- 프로젝트에 없는 유형: "사진의 유형을 선택해 주세요."
- 용도가 train·val이 아님: "학습 또는 검증 용도를 선택해 주세요."
- 제공 사진인데 이 프로젝트 분류의 제공 목록에 없거나 용도가 제공 목록과 다름: "제공 데이터의 분류·분할을 바꿀 수 없습니다."
- 직접 올린 사진의 파일 내용이 PNG·JPG가 아님(파일 이름이 아니라 파일 앞부분으로 봅니다): "JPG·PNG 사진만 사용할 수 있습니다." 2MB 초과: "사진 크기가 올바르지 않습니다."
- 해시가 test 사진의 해시와 같음: "제공 Test 사진은 학습·Val에 추가할 수 없습니다."
- 같은 사진(같은 해시)을 다른 유형이나 다른 용도로 또 넣기: "같은 사진을 다른 유형이나 학습·검증에 중복 배치할 수 없습니다." 같은 유형·용도로 다시 넣으면 있는 것을 그대로 돌려줍니다.
- 프로젝트 사진 1000장 초과: "프로젝트 사진은 최대 1000장입니다."

DELETE /api/tm/projects/(프로젝트 ID)/samples/(사진 항목 id): 프로젝트 사진 목록에서만 빼고 사진 파일은 지우지 않습니다. 바뀐 프로젝트를 돌려줍니다. 이전 버전의 사진 기록이 그 파일을 계속 쓰기 때문입니다.

## 모델 학습 화면(#training)

1회차 문서의 화면 목록에 #training 화면을 더합니다.

- 홈 제목 옆 단추 줄("사진 등록", "전체 사건" 옆)에 "모델 학습" 단추를 두고 누르면 #training 화면으로 갑니다. 길잡이 줄은 "← 홈으로 / 모델 학습"입니다.
- 위에서부터 제목 "모델 학습", "학습 프로젝트" 고르기 칸과 "택배 발송 프로젝트 만들기"·"산업안전 프로젝트 만들기" 단추, 안내 줄, 구역 "1. 사진 준비", "2. 학습·검증", "3. 모델 비교·적용", "모델 가져오기" 순서입니다. 네 구역은 프로젝트를 골랐을 때만 보입니다.
- 고르기 칸의 첫 줄은 "프로젝트 선택"이고 프로젝트는 "택배 발송 모델 · 1a2b3c4d"처럼 이름과 ID 앞 8자리로 보입니다. 만들기를 누르면 새 프로젝트를 만들어 바로 고르고 안내 줄에 "사진을 준비해 주세요."를 보여 줍니다. 있는 프로젝트를 고르기만 하면 안내 줄은 그대로 둡니다. 고른 프로젝트는 브라우저 메모리에만 두므로 새로고침하면 "프로젝트 선택"으로 돌아갑니다.
- 안내 줄의 처음 문구는 "프로젝트를 선택하거나 새로 만들어 주세요."입니다. 학습 화면의 진행과 결과, 오류는 팝업 창 대신 이 줄에 보여 줍니다. 오류는 "완료하지 못했습니다. (이유)"이고 서버에 닿지 못했을 때 이유는 1회차 문서의 서버 연결 안내 문장입니다. 작업 안에서 난 오류는 이 문서의 문구 앞에 모두 "완료하지 못했습니다. "를 붙여 보여 줍니다. 예: "완료하지 못했습니다. 모든 유형에 Train 사진을 최소 2장씩 준비해 주세요." 학습 설정 범위 문구만 작업을 시작하기 전에 보여 주므로 앞말을 붙이지 않습니다.
- 작업(만들기, 넣기, 빼기, 학습, 검증, 적용, 가져오기)이 진행되는 동안 학습 화면의 단추와 입력 칸, 고르기 칸을 모두 잠그고 끝나면 프로젝트를 다시 받아 화면을 다시 그립니다. 펼쳐 둔 접기 칸은 펼친 채로 두고 보던 자리(스크롤)와 고르던 칸도 그대로 둡니다.
- 학습 화면은 다른 데이터 조회가 끝났다고 다시 그리지 않고 머리말 연결 표시만 바꿉니다.

## "1. 사진 준비" 구역

제공 사진을 분류하는 목록과 유형마다 사진을 관리하는 칸이 있습니다. 구역 맨 위 안내는 "제공 사진에는 유형이 없으므로 직접 분류합니다."입니다.

### 제공 사진 분류 목록

- "제공 Train 사진 분류", "제공 Val 사진 분류" 단추: 누르면 그 프로젝트 분류(track)와 그 용도의 제공 사진 목록이 열리고 같은 단추를 다시 누르면 닫힙니다. 한 번에 한 목록만 엽니다.
- 분류 목록: 맨 위에 "분류한 사진 x / y장", 그 아래 서버가 보낸 순서대로 사진마다 "제공 사진 1, 2, …"와 사진, "유형 선택" 고르기 칸(첫 줄 "유형 선택", 그다음 프로젝트 유형)이 있습니다. 이미 넣은 사진은 고른 유형이 선택돼 보입니다. 사진이 많으니 화면에 보이는 것부터 받도록 사진에 loading="lazy"를 둡니다. 목록이 비면 서버가 보낸 오류 문구를, 그 문구도 없으면 "승인된 제공 사진이 없습니다."를 보여 줍니다.
- 유형을 고르면 그 유형·그 용도로 넣고 "제공 사진 3: 찌그러짐 유형으로 넣었습니다."를 보여 줍니다. 다른 유형으로 바꾸면 먼저 빼고 새 유형으로 다시 넣습니다. "유형 선택"으로 되돌리면 빼고 "제공 사진 3: 분류에서 뺐습니다."를 보여 줍니다.

### 유형 칸

- 프로젝트 유형마다 칸이 하나씩 있습니다. 칸에는 유형 이름, "Train n장 · Val m장", "사진 용도" 고르기("Train · 학습", "Val · 검증", 처음은 Train), "직접 사진 추가" 파일 칸(PNG·JPG, 여러 장), 접히는 "사진 배치·제거"가 있습니다.
- "사진 배치·제거"를 펼치면 그 유형에 넣은 사진과 용도(train/val), "제거" 단추가 보입니다. "제거"를 누르면 프로젝트에서 빼고 "현재 학습 목록에서 제거했습니다. 이전 모델의 학습 사진 기록은 보존합니다."를 보여 줍니다.
- 직접 사진 추가: 고른 사진을 위 "사진 넣기와 빼기"의 직접 올린 사진 모양({"label", "split", "filename", "base64"})으로 POST /api/tm/projects/(프로젝트 ID)/samples에 보내 그 칸의 사진 용도로 넣고 "사진을 추가했습니다."를 보여 줍니다. 2MB가 넘으면 "직접 추가하는 사진은 장당 2MB 이하로 준비해 주세요.", 열 수 없으면 "사진을 읽지 못했습니다. 다른 JPG·PNG로 다시 선택해 주세요."를 보여 주고 넣지 않습니다. 서버에 이 모양을 받는 처리와 거절 문구가 아직 없으면 이때 함께 만듭니다.

## "2. 학습·검증" 구역

학습은 이 브라우저 안에서 합니다. 학습 사진은 Google에 보내지 않습니다.

### 단추와 학습 전 검사

- "모델 학습" 단추와 접히는 "고급 학습 설정"이 있습니다. 설정은 학습 회차(처음 50, 1~500), 배치 크기(처음 16, 1~128), 학습률(처음 0.001, 0.00001~0.1)입니다. 범위를 벗어나면 "학습 설정 범위를 확인해 주세요."를 보여 주고 학습하지 않습니다.
- 학습 전 검사: 유형마다 Train 사진이 2장 미만이면 "모든 유형에 Train 사진을 최소 2장씩 준비해 주세요.", Val 사진이 한 장도 없으면 "학습에 쓰지 않은 Val 사진도 준비해 주세요."를 보여 주고 학습하지 않습니다. 설정 범위를 먼저 보고 통과하면 사진 장수를 봅니다.

### 브라우저 안에서 학습하기

- /vendor/tm/runtime.js를 불러온 뒤 tmImage.createTeachable({ labels: 유형 목록 }, { version: 2, checkpointUrl: '/vendor/tm-v2/model.json', trainingLayer: 'out_relu' })로 만들고 바로 setLabels(유형 목록)을 불러 사진 넣을 칸을 준비합니다. 학습할 때 denseUnits는 100입니다. 아래에서 trainer는 createTeachable이 돌려준 값입니다.
- 사진 넣기: Train 사진만 /api/tm/images/(사진 해시)로 받아 입력 그림으로 만들고 trainer.addExample(유형 순서 번호, 그림)을 부릅니다.
- 학습: trainer.train({ epochs, batchSize, learningRate, denseUnits: 100 }, { onEpochEnd: 회차가 끝날 때마다 진행 문구 바꾸기 })를 부릅니다.
- 학습한 모델의 입력 방식("전체 사진 여백 맞춤"): 사진을 224×224 흰 바탕에 비율을 지켜 잘라 내지 않고 통째로 넣습니다. 학습·검증·예측 모두 같습니다.
- 사진이 적은 유형은 같은 사진을 반복해 넣어 유형마다 넣는 장수를 가장 많은 유형에 맞춥니다. 그 유형의 Train 장수가 n이고 가장 많은 유형이 max장이면 그 유형의 k번째 사진(0부터)은 floor(max / n)번 넣고 k가 max % n보다 작으면 한 번 더 넣습니다. 장수 차이가 크면 모델이 사진이 많은 유형만 고르기 쉽기 때문입니다.
- 진행 문구는 "학습 파일을 준비하고 있어요.", "학습 사진 준비 3/20장", "학습 중 12/50회", "Val 확인 중 3/15장", "모델을 저장하고 있어요."입니다. "학습 사진 준비 3/20장"의 20은 반복해 넣기 전의 Train 사진 수입니다.
- runtime.js를 불러오지 못하면 "학습 파일이 없습니다. 터미널에서 npm.cmd run setup:tm(macOS: npm run setup:tm)을 실행한 뒤 페이지를 새로 고쳐 주세요."를 보여 줍니다. createTeachable의 오류 글에 status code 404가 있으면 기초 모델을 불러오지 못한 것으로 보고 "학습 기초 모델 파일이 없습니다. 터미널에서 npm.cmd run setup:tm(macOS: npm run setup:tm)을 다시 실행한 뒤 페이지를 새로 고쳐 주세요."를 보여 줍니다.

### 검증과 저장

- 검증: 학습이 끝나면 프로젝트의 Val 사진마다 모델이 고른 유형(가장 높은 점수)과 사용자가 고른 유형을 비교해 정확도, 혼동표(행: 실제 유형, 열: 모델 예측), 오분류 목록(사진 해시, 실제, 예측), Val 사진이 없는 유형 목록을 만듭니다. 모델의 예측은 model.predict(그림)이고 [{"className", "probability"}, …]로 돌아옵니다.
- 검증 결과(validation) 모양: {"total": Val 장수, "accuracy": 0~1, "matrix": 프로젝트 유형 순서의 혼동표, "errors": [{"sha256", "actual", "predicted", "scores"}, …], "val_hashes": Val 사진 해시를 정렬한 목록, "missing_labels": Val 사진이 없는 유형 목록}입니다.
- 모델 꺼내기: trainer.save(tf.io.withSaveHandler(받는 함수))로 modelTopology, weightSpecs, weightData를 받습니다. weights는 weightData를 base64로 바꾼 글자이고 metadata는 trainer.getMetadata()입니다.
- 저장: 검증 결과와 함께 새 버전으로 저장하고 저장한 모델을 다시 불러와 Train 사진 한 장으로 예측해 본 뒤 "v1 저장 뒤 다시 불러와 확인했습니다. 사용하려면 모델을 적용해 주세요."를 보여 줍니다. 다 쓴 모델을 메모리에서 정리(dispose)할 때 난 예외는 무시합니다.

### 학습 중단

"학습 중단" 단추는 학습하는 동안만 보입니다. 학습이 저장, 실패, 중단 어느 쪽으로 끝나도 학습 구역을 다시 그려 단추를 감춥니다. 누르면 "현재 회차가 끝나면 중단합니다. 모델은 적용하지 않습니다."를 보여 주고 지금 회차가 끝난 뒤 멈추며 모델은 저장하지 않습니다. 멈춘 뒤에는 "완료하지 못했습니다. 학습을 중단했습니다. 이전 모델은 유지됩니다."를 보여 줍니다. 멈춤은 학습 모델의 stopTraining(trainer.trainingModel.stopTraining)을 true로 바꾸는 것으로 하고 회차 끝 처리 안에서 그 결과를 기다리지(await) 않습니다. 사진을 준비하는 중에 누르면 "완료하지 못했습니다. 학습을 중단했습니다.", Val을 확인하는 중에 누르면 "완료하지 못했습니다. 학습·검증을 중단했습니다. 이전 모델은 유지됩니다."를 보여 줍니다.

### 학습 중 안내와 화면 이동

- 학습 구역 안내 두 줄은 "다른 페이지로 이동해도 진행됩니다. 새로고침하거나 브라우저를 닫으면 중단됩니다."와 "학습하는 동안 이 탭을 화면 앞에 두세요. 다른 탭이나 창으로 옮기면 학습이 멈추거나 아주 느려집니다."입니다. 브라우저가 화면에 보이지 않는 탭의 작업을 늦추기 때문입니다.
- 대시보드 안에서 다른 화면에 갔다 와도 학습은 이어지고 학습 화면으로 돌아오면 지금 진행 문구가 보입니다.

## 모델 버전 저장

학습할 때마다 새 버전이 생기고 이전 버전은 그대로 남습니다. 가져온 모델을 받는 규칙은 이 절 끝의 "가져온 모델"에 따로 적었습니다.

POST /api/tm/projects/(프로젝트 ID)/versions가 받는 것: modelTopology(모델 구조), weightSpecs, weights(가중치, base64), metadata(유형 목록 labels 포함), preprocessing("letterbox224"는 전체 사진 여백 맞춤, "tm-center-crop"은 공식 TM 중앙 자르기), base_model("mobilenet_v2_0.35", 학습한 모델만), parameters(학습 설정), validation(검증 결과), sample_hashes(학습을 시작할 때 프로젝트 사진 해시를 정렬한 목록), source("import"면 가져온 모델).

버전 번호(number)는 1, 2, 3…으로 늘리고 이전 버전은 덮어쓰지 않습니다. 버전마다 저장할 때의 프로젝트 사진 목록(해시·유형·용도)을 복사해 samples로 남깁니다. source는 "trained"(학습 모델) 또는 "import"(가져온 모델)입니다.

버전 항목은 id, project_id, track, number, labels(유형 목록), preprocessing, created_at, samples, source, parameters, validation이고 학습한 모델에만 base_model을 더합니다. parameters는 {"epochs", "batchSize", "learningRate"}입니다. 프로젝트의 versions 목록에 이 항목을 더하고 그 항목을 돌려줍니다.

저장하지 않는 경우와 그 문구는 아래와 같습니다.

- modelTopology나 weights, weightSpecs가 없음: "모델 파일이 올바르지 않습니다."
- preprocessing이 위 두 값이 아님: "모델 입력 변환을 확인해 주세요." base_model이 위 값이 아님: "학습 기초 모델을 확인해 주세요."
- 모델 유형 목록이 프로젝트와 다름: "모델의 클래스가 프로젝트와 다릅니다." 이름이 모두 같으면 순서는 달라도 받습니다.
- 출력 수가 유형 수와 다름: "모델 출력과 클래스가 다릅니다." 출력 수는 모델 구조의 마지막 Dense 층 units로 봅니다. modelTopology.config.layers의 마지막 층을 보고, 그 층 안에 다시 config.layers가 있으면 그 안의 마지막 층의 config.units를 씁니다. 그 층의 config.activation이 softmax가 아니어도 같은 문구입니다. 층 목록이 없으면 "지원하지 않는 모델 구조입니다."입니다. 가중치 목록 끝에는 기초 모델 값이 오므로 그 모양으로 보면 안 됩니다.
- 가중치가 12MB 초과: "모델 가중치 크기가 올바르지 않습니다." 가중치 크기가 weightSpecs와 맞지 않음: "가중치 파일이 불완전합니다." 맞는 크기는 weightSpecs 항목마다 shape의 곱에 float32·int32는 4바이트, bool은 1바이트를 곱해 더한 값입니다. 다른 자료형이면 "지원하지 않는 가중치입니다."입니다.
- 학습한 모델인데 sample_hashes가 지금 프로젝트 사진과 다름: "학습 중 사진 구성이 바뀌었습니다. 프로젝트를 다시 확인해 주세요."

버전 폴더에 model.json, metadata.json, weights.bin을 저장하고 GET /api/tm/files/(버전 ID)/(model.json, metadata.json, weights.bin 중 하나)로 다시 보냅니다. 브라우저는 이 주소로 모델을 다시 불러옵니다(tmImage.load('/api/tm/files/(버전 ID)/model.json', '/api/tm/files/(버전 ID)/metadata.json')). 없는 파일이나 없는 버전이면 404와 {"error": "Not found"}입니다. 세 파일의 내용은 이렇습니다.

- model.json: {"modelTopology": 받은 값, "format": "layers-model", "generatedBy": "vision-risk-local", "convertedBy": null, "weightsManifest": [{"paths": ["weights.bin"], "weights": 받은 weightSpecs}]}
- metadata.json: 받은 metadata에 labels, "imageSize": 224, "userMetadata": {"preprocessing": 받은 값}을 더한 것
- weights.bin: 받은 weights를 base64에서 되돌린 파일

### 가져온 모델

가져온 모델(source "import")은 sample_hashes 검사와 base_model 검사를 하지 않고 지금 프로젝트 사진 목록을 버전의 samples로 남깁니다. 화면은 base_model, parameters, validation을 보내지 않고 서버는 parameters와 validation을 null로 저장합니다. 이 samples는 가져온 때의 프로젝트 사진 기록일 뿐 그 모델이 학습한 사진이 아니어서, 카드에 Train 장수로 보여 주지 않습니다.

## "3. 모델 비교·적용" 구역

버전마다 카드가 하나씩 있고 여기서 사건 상세에 쓸 모델을 고릅니다. 버전이 없으면 "저장된 모델이 없습니다."를 보여 줍니다.

### 버전 카드

- 카드의 제목은 "v1 · 학습 모델"(가져온 모델이면 "v1 · 가져온 모델")이고 그 아래 "2026-11-01 14:05 · Train 30장 · 입력 전체 사진 여백 맞춤 · 기초 모델 MobileNet v2"처럼 보입니다. 시각은 YYYY-MM-DD HH:mm, 입력은 "전체 사진 여백 맞춤" 또는 "공식 TM 중앙 자르기", 기초 모델은 학습 모델에만 씁니다. Train 장수는 그 버전 samples의 Train 사진 수(반복해 넣기 전)입니다. 가져온 모델은 어떤 사진으로 학습했는지 알 수 없으므로 "Train …장"을 쓰지 않고 "2026-11-01 14:05 · 입력 공식 TM 중앙 자르기"처럼 보입니다. 카드는 버전 번호 순서로 오래된 것부터 놓습니다.
- 카드의 검증 결과는 "모델 저장 당시 별도 Val 15장 · 정확도 86.7%"(다시 검증했으면 "이번에 확인한 별도 Val 15장 · 정확도 …%")입니다. Val 사진이 없던 유형은 "검증 사진 없음: 오염, 마개 누락. 이 유형은 평가하지 못했습니다."로 따로 적습니다.
- 그 아래 혼동표(표 제목 "행: 실제 유형 · 열: 모델 예측")와 접히는 "유형별 결과와 오분류 n건"(유형마다 "찌그러짐: 2 / 3장", 오분류마다 "사진 보기" 링크와 "실제 찌그러짐, 예측 정상")을 둡니다. Val 사진이 없는 유형도 "찢어짐: 0 / 0장"처럼 적습니다. 검증 기록이 없으면 "검증 기록이 없습니다."입니다.

### 적용

- 적용 모델: GET /api/tm/active는 {"quality": 버전, "safety": 버전}이고 적용한 적이 없으면 {}입니다. POST /api/tm/active에 {"id": 버전 ID}를 보내면 그 버전 항목을 그 분류(track)의 적용 모델로 저장하고 그 버전 항목을 돌려줍니다. 없는 버전이면 "저장된 모델을 찾을 수 없습니다."입니다.
- "이 모델을 사건 분류에 적용" 단추: 그 모델을 불러와 빈 224×224 그림 한 장으로 예측해 점수가 바르면 적용하고 "사건 분류 모델로 연결했습니다: v1"을 보여 줍니다. 점수가 바르지 않으면 "모델의 출력이 올바르지 않습니다. 이전 적용 모델을 유지합니다."를 보여 주고 적용하지 않습니다. 점수가 바르다는 것은 유형마다 0~1 점수가 하나씩 있고 합이 1(±0.01)이라는 뜻입니다.

### 다시 검증과 비교

- "현재 Val로 다시 검증" 단추: 지금 프로젝트의 Val 사진으로 그 버전을 다시 검증해 카드에 "이번에 확인한" 결과로 보여 주고 안내 줄에 "v1: 현재 Val 15장 정확도 86.7%. 모델 저장 당시 결과와 별도입니다."를 보여 줍니다. 저장된 검증 결과는 바꾸지 않습니다.
- 버전이 둘 이상이면 "같은 Val로 최근 두 모델 비교" 단추를 보여 줍니다. 최근 두 버전을 지금 Val로 검증해 "같은 Val 15장: v1 80.0%, v2 86.7% (+6.7%p). 측정상 향상됐습니다."처럼 보여 주고 나아지지 않았으면 끝을 "향상되지 않았습니다."로 합니다.
- 공식 TM 중앙 자르기 모델은 검증·예측할 때 사진을 줄이지 않고 그대로 넣어 공식 Teachable Machine처럼 가운데를 정사각형으로 잘라 쓰게 합니다.

## 홈의 모델 상태

홈의 "모델 학습" 단추 옆에 "택배 발송: 모델 연결됨 · 산업안전: 모델 미연결"처럼 분류마다 적용 모델이 있는지 보여 줍니다. 홈을 그릴 때마다 서버에서 적용 모델을 받아 채우므로, 모델 학습 화면을 다녀오지 않고 홈에서 바로 새로고침해도 보입니다. 학습 중이면 대신 학습 진행 문구를 보여 주고 적용 모델을 받지 못하면 "모델 연결 상태를 확인하지 못했습니다."를 보여 줍니다.

## "모델 가져오기" 구역

공식 Teachable Machine에서 내보낸 모델을 가져옵니다.

- "공식 TM 모델 가져오기" 파일 칸: 공식 Teachable Machine에서 내보낸 model.json, metadata.json, weights.bin 세 파일을 함께 고릅니다. 하나라도 없으면 "model.json·metadata.json·weights.bin을 모두 선택해 주세요.", metadata의 유형 이름이 프로젝트 유형과 같지 않으면(순서는 달라도 됩니다) "모델 클래스 이름을 이 프로젝트의 유형과 맞춰 주세요.", 가중치 파일이 weights.bin 하나가 아니면(model.json의 weightsManifest가 하나이고 그 paths가 weights.bin 하나여야 합니다) "단일 weights.bin 모델을 선택해 주세요."를 보여 주고 멈춥니다. 통과하면 tmImage.loadFromFiles(model.json 파일, weights.bin 파일, metadata.json 파일)로 불러와 빈 그림으로 예측을 확인한 뒤 입력 방식 "tm-center-crop"인 "가져온 모델" 버전으로 저장하고(weightSpecs는 weightsManifest 첫 항목의 weights입니다) "모델을 가져왔습니다. 사용할 버전을 직접 적용해 주세요."를 보여 줍니다.

## 사건 상세 다섯 단계

5회차 문서의 사건 상세 네 단계는 다섯 단계로 바꿉니다.

- 진행 단계는 1 사진, 2 AI 사진 설명 (Gemini), 3 모델 예측 (Teachable Machine), 4 관련 기준 확인 (NotebookLM), 5 내 판단 남기기입니다. 앞 회차 문서의 관련 기준 확인과 내 판단 남기기 단계 번호는 하나씩 밀립니다. 구역 제목도 "4. 관련 기준 확인 (NotebookLM)", "5. 내 판단 남기기"가 됩니다. 번호를 바꿀 곳은 진행 표시, 구역 제목, 다음 단추, 안내 문구, 처음 고르는 단계, "판단 기록하기" 단추를 강조하는 단계(5단계)입니다.
- 2단계와 관련 기준 확인 사이에 "3. 모델 예측 (Teachable Machine)" 구역을 둡니다. 구역 안내는 "사진별 분류 결과를 보고 확인할 점을 살펴보세요. 적용된 모델이 없으면 모델 학습 화면에서 학습하고 적용합니다."이고 처음 내용은 "적용 모델과 사진을 확인하고 있어요."입니다.
- 다음 단추는 2단계 끝 "다음: 모델 예측 확인", 3단계 끝 "다음: 관련 기준 확인", 4단계 끝 "다음: 내 판단 남기기"입니다. 안내 문구는 3단계 "Teachable Machine 모델 예측을 확인해 주세요.", 4단계 "AI 결과를 확인했다면, NotebookLM으로 관련 기준을 찾아 사진과 비교해 주세요.", 5단계 "사진과 기준을 비교하고, 직접 확인한 판단을 남겨주세요."입니다.
- 처음 열 때 고르는 단계: 사진이 없으면 1, Gemini 설명이 없으면(Gemini가 꺼져 있지 않을 때) 2, 현재 정보 버전의 모델 예측이 없으면 3, 기준 확인이 없으면(NotebookLM이 꺼져 있지 않을 때) 4, 아니면 5입니다. 판단을 저장한 사건의 규칙은 앞 회차 문서 그대로입니다.

## 모델 예측

사건 상세를 열면 적용 모델로 사건 사진을 예측해 사건별로 저장하고 3단계에 보여 줍니다.

### 저장과 데이터 주소

- 예측 한 건의 항목: id, record_id(사건 번호), record_version(사건 정보 버전), image_index(사진 번호, 0부터), image_sha256(사진 해시), model_id, model_number(버전 번호), track, preprocessing, scores([{"className": 유형, "probability": 0~1}]), created_at.
- POST /api/tm/predictions: 위 항목을 받아 사건별로 저장합니다(id와 시각은 서버가 정함). 화면이 보내는 것은 record_id, record_version, image_index, image_sha256, model_id, scores이고 model_number, track, preprocessing은 서버가 그 모델 버전에서 채웁니다. id는 사건 번호·정보 버전·사진 번호·사진 해시·모델 ID로 만든 해시(이 다섯 값의 JSON 배열 글자의 SHA-256)라서 다섯 값이 같으면 새로 만들지 않고 저장된 것을 그대로 돌려줍니다.
- 막는 것: 사건이 없으면 404와 "사건을 확인하지 못했습니다.", 모델 분류가 사건 분류와 다르거나 사진 번호가 사진 수 이상이거나 정보 버전이 지금보다 크면 "사건과 모델·사진 연결이 올바르지 않습니다.", 점수 합이 1(±0.01)이 아니면 "클래스별 점수의 합이 올바르지 않습니다."입니다. 사건은 사건 상세를 읽는 기존 방법(지금 저장 방식)으로 확인합니다.
- GET /api/tm/predictions/(사건 번호): 그 사건의 예측 목록입니다. 사건 상세 조회 응답에도 tm_predictions로 넣습니다.

### 상세에서 예측하기

- 상세를 열면 사건 분류(택배 발송 quality, 산업안전 safety)의 적용 모델로 사진마다(최대 5장) 예측해 저장합니다. 사진 해시는 화면이 사건 사진 파일(2회차 문서의 GET /api/records/(사건 번호)/images/(순서))을 받아 계산합니다. 사건의 분류는 category, 정보 버전은 version, 사진 수는 image_count입니다. 같은 모델·정보 버전·사진 번호·해시의 예측이 이미 있으면 다시 계산하지 않습니다. 이때도 모델 입력 그림은 사진에서 다시 만들어 보여 줍니다.
- 같은 사건·정보 버전의 예측이 진행 중이면 새로 돌리지 않고 그 결과를 같이 기다립니다. 서버가 저장된 것으로 돌려준 예측도 화면 목록에 넣습니다. 다른 결과가 도착해 상세를 다시 그려도 이미 그린 예측은 다시 계산하지 않고 그대로 옮깁니다.
- 사건 주소가 다른 사건으로 바뀌면 이전 사건의 상세와 예측을 먼저 비우고 "사건 정보를 불러오고 있어요."를 보여 줍니다. 늦게 도착한 이전 사건의 예측은 새 사건 화면에 그리지 않습니다.

### 3단계 표시

- 위에서부터 소제목 "Teachable Machine 모델 예측", 안내 "모델 점수는 위험 확정·안전 인증이 아닙니다. 낮은 점수나 불명확한 사진은 추가 확인이 필요합니다.", 택배 발송 사건이면 안내 "정상 예측은 발송 승인이 아닙니다. 주문·수취인·배송 주소·수량은 실제 주문 자료와 따로 대조하세요.", 사진마다 "사진 1 · 찌그러짐"과 "Teachable Machine 모델 예측 · v1", 맨 아래 "사진별 대표 유형을 고릅니다. 여러 위험의 위치나 사건 흐름을 자동 확정하지 않습니다."입니다. 맨 아래 문구는 적용 모델이 없을 때도 보여 줍니다. 안내 두 줄은 적용 모델이 있을 때만 보여 줍니다.
- 지금 결과는 현재 정보 버전·적용 모델의 예측입니다. 가장 높은 점수가 70% 미만이면 그 사진에 "분류 점수가 낮습니다. 사진과 기준을 더 확인해 주세요."를 보여 줍니다. 사진마다 접히는 "클래스별 점수·모델 입력 보기"에 유형별 점수(높은 순, "찌그러짐 92.0%")와 모델에 넣은 224×224 그림을 보여 주는데, 공식 TM 중앙 자르기 모델이면 사진 가운데를 정사각형으로 잘라 224×224로 줄인 그림입니다.

### 모델이 없을 때

- 적용 모델이 없으면 "사용할 모델이 없습니다. 모델 학습에서 사용할 버전을 선택해 주세요."와 #training으로 가는 링크 "모델 학습으로 이동"을 보여 줍니다.

## 관련 기준 확인과 판단 화면

5회차 문서는 Gemini 설명이 있어야 관련 기준을 찾을 수 있게 했습니다. 이 조건을 아래처럼 바꿉니다.

- 4단계 "관련 기준 찾기"는 현재 정보 버전의 Gemini 설명이나 현재 정보 버전·적용 모델의 예측 중 하나만 있어도 켭니다. 둘 다 없으면 "먼저 2단계 Gemini 설명이나 3단계 모델 예측을 준비해 주세요."를 보여 줍니다. 상세에서 예측이 끝나면 새로 고치지 않아도 바로 켭니다. 저장돼 있던 것을 포함한 예측 목록을 보고 켤지 판단합니다. NotebookLM이 꺼졌거나 기다리는 요청이 있으면 앞 회차 문서의 규칙대로 둡니다.
- 서버의 기준 확인 요청도 같은 조건입니다. 둘 다 없으면 400, error_code "AI_DRAFT_REQUIRED", "현재 사건의 모델 분류 또는 Gemini 설명을 먼저 준비해 주세요."입니다. Gemini 설명이 수정 전 것이어도 현재 예측이 있으면 막지 않고 질문에 수정 전 설명 값을 넣지 않습니다. 수정 전 설명만 있고 현재 예측이 없으면 5회차 문서의 AI_DRAFT_STALE 답을 그대로 씁니다.
- NotebookLM에 보내는 질문에 사진마다 "사진 1 TM 모델 v1 예측: 찌그러짐 (모델 점수 92.0%, 관찰 사실·위험 확정이 아님)" 줄을 넣고 요청 기록(작업에 질문 글을 남기는 자리)에 tm_model_id(적용 모델 ID)와 tm_prediction_ids(쓴 예측 ID 목록)를 남깁니다. Gemini 설명이 없으면 Gemini 값(관찰 초안, 불확실성 등)은 빼고 질문을 만들고 불확실성 자리에는 "모델 예측은 현장 사실 확정이 아닙니다."를 씁니다. 질문 글만이 아니라 NotebookLM에 함께 넘기는 관찰 값과 불확실성에서도 Gemini 값을 빼고, Gemini 설명이 없다고 오류를 내지 않습니다.
- "내 판단 남기기" 화면의 참고 칸에서 "Gemini 관찰 사실"과 "NotebookLM 기준 확인" 사이에 "Teachable Machine 모델 예측 (모델 v1): 사진 1 · 찌그러짐 92.0% / 사진 2 · 정상 81.3%"를 넣습니다. 현재 정보 버전에서 가장 최근에 예측한 모델의 예측만 사진 순서대로 씁니다. 가장 최근은 created_at이 가장 늦은 예측이라 지금 적용한 모델과 다를 수 있습니다. 없으면 "현재 사진의 모델 예측이 없습니다."이고 있으면 아래에 "모델 점수는 위험 확정·안전 인증이 아닙니다."를 붙입니다.
- 상세에서 막 끝난 예측은 판단 화면이 상세를 다시 받지 않아도 바로 씁니다. 판단 화면을 이미 열었으면 참고 칸만 다시 그리고 작성 중인 입력은 그대로 둡니다.

## 만들지 않는 것

- 서버 창과 화면 위 연동 상태 줄의 "Teachable Machine 브라우저" 이름표: 학습은 브라우저 안에서 돌아가 켜고 끌 설정이 없으므로 만들지 않습니다.
- 학습 중 새로고침할 때 브라우저가 한 번 묻게 하는 것과 새로고침 뒤 "학습이 중단됐다"는 안내: 혼자 쓰는 연습용 앱이라 만들지 않습니다. 새로고침하면 학습이 멈추고, 저장된 프로젝트에서 다시 학습하면 됩니다.
- 프로젝트 백업과 백업 파일 가져오기: 학습 자료가 이 PC에 그대로 남는 연습용 앱이라 만들지 않습니다.
- 3단계의 예측 실패 안내와 "AI로 사진 다시 분류하기" 단추: 상세 페이지를 다시 열면 다시 예측하므로 만들지 않습니다.
- 3단계의 "이전 정보·모델의 예측" 접기 칸: 지금 정보 버전·적용 모델의 예측만 보면 되어 만들지 않습니다.
- README에 이번 회차 사용법(준비 명령, 모델 학습 순서, 사건 상세 다섯 단계)을 적는 일: 혼자 쓰는 연습용 앱이라 하지 않습니다.
