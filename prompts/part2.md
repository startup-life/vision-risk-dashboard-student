# 2회차: 사건 등록·목록·홈 큐(로컬 저장)

시작: `milestone-1` 브랜치(또는 지난 회차까지 내가 만든 코드)
끝나면: 사진 파일을 올리거나 사진 저장소의 사진을 골라 사건을 등록하면 사건 목록과 홈의 "확인이 필요한 현장"(검토 대기)에 나온다. 기록과 사진은 이 PC의 파일에 저장되어 서버를 다시 켜도 남는다.

## 시작하기 전에
Antigravity에서 프로젝트 폴더(`vision-risk-dashboard-student`)를 열고 터미널에서 아래를 칩니다. 내 코드로 이어 하면 첫 줄은 건너뜁니다.
```powershell
git switch milestone-1
npm.cmd ci
npm.cmd start
```
브라우저에서 `http://127.0.0.1:8765`를 열어 1회차 홈과 "확인 기준 보기"가 보이는지 봅니다. 서버를 다시 켤 때는 서버 터미널에서 `Ctrl+C`를 누른 뒤 `npm.cmd start`를 칩니다.

## 2-1. 사진 저장소 받기 (직접 하기)
사건 등록에 쓸 사진은 공개 저장소에 있습니다. 프로젝트 폴더 **바로 옆**에 `git clone`으로 받습니다(ZIP으로 받으면 쓰지 못합니다).
서버 터미널이 아닌 새 터미널에서, 프로젝트 폴더에 있는 상태로 칩니다. `git --version`이 안 나오면 git-scm.com/download/win 에서 Git을 기본값으로 설치하고 Antigravity를 다시 엽니다.
```powershell
git --version
cd ..
git clone https://github.com/startup-life/vision-risk-student-images.git
(Get-ChildItem vision-risk-student-images/assets/dataset/images -Filter *.png).Count
cd vision-risk-dashboard-student
```
확인: 마지막 숫자가 `210`이고, 탐색기에서 `vision-risk-dashboard-student`와 `vision-risk-student-images`가 같은 폴더 안에 나란히 있다. 폴더 이름은 바꾸지 않습니다.

## 2-2. 서버가 사진 목록 읽기
서버가 옆 폴더 사진 저장소의 사진 목록을 읽게 합니다.
```text
서버가 옆 폴더 vision-risk-student-images(사진 저장소)의 사진 목록을 읽게 해 줘.
목록은 그 저장소에서 git으로 origin/main 커밋의 metadata/generation_manifest.csv를 읽어 줘(작업 폴더의 파일이 아니라 커밋의 내용).
status가 accepted, split이 train, sequence_id가 빈 줄만 쓰고, 사진 번호(image_id)·분류(track: quality 또는 safety)·sha256·파일 위치만 꺼내 줘.
서버를 켤 때 한 번 읽어 두고, 읽은 사진 수를 터미널에 한 줄로 알려 줘.
```
확인: 서버를 다시 켜면 터미널에 사진 180장을 읽었다는 줄이 나온다.

## 2-3. 사진 저장소 위치 설정
사진 저장소를 다른 곳에 받았을 때 위치를 설정 파일로 바꿀 수 있게 합니다.
```text
설정 파일을 읽는 코드에 REPOSITORY_IMAGES_ROOT 키를 추가해 줘. 값이 있으면 그 폴더를 사진 저장소로 쓰고, 비어 있으면 프로젝트 폴더 바로 옆 vision-risk-student-images를 써 줘.
config/local-connection.example.json에도 이 키를 빈 값("")으로 넣어 줘.
config/local-connection.json이 없으면 "설정 파일 없이 시작한다"는 알림만 띄우고 서버는 그대로 켜 줘.
```
확인: 서버를 다시 켜면 터미널에 "설정 파일 없이 시작한다" 알림이 나오고, 사진 수 줄은 2-2와 같다. 사진 저장소를 옆 폴더에 받았으면 설정 파일은 만들지 않아도 됩니다.

## 2-4. 사진 저장소 검사와 실패 원인 알리기
받은 사진 저장소가 맞는지, 사진이 바뀌지 않았는지 검사합니다.
```text
사진 저장소를 쓰기 전에 origin 주소가 https://github.com/startup-life/vision-risk-student-images.git 인지 확인해 줘.
사진마다 작업 폴더의 실제 파일이 PNG인지, 2MB 이하인지, 목록의 sha256 값과 같은지 보고 다르면 그 사진만 빼 줘.
못 읽으면 서버는 그대로 켜고, 터미널에 [RepositoryImages]로 시작하는 한 줄로 원인을 알려 줘.
원인은 경로 없음, git 미설치, git 저장소가 아님, origin 원격 없음, origin이 다른 저장소, origin/main 없음, 쓸 수 있는 사진 0장으로 나눠 줘.
```
확인: 서버를 다시 켜면 `[RepositoryImages]` 경고 없이 사진 수 줄만 나온다.

## 2-5. 저장소 사진 목록 주소
화면이 저장소 사진을 받아 갈 주소를 만듭니다.
```text
저장소 사진 목록을 주는 /api/repository-images 주소와 사진 한 장을 주는 /api/repository-images/<사진 번호>/file 주소를 서버에 만들어 줘.
사진 한 장 주소는 브라우저가 캐시해도 되게 해 줘.
목록에는 사진 번호, 분류, 사진 주소와 전체 장수만 넣고, 정답이 될 수 있는 다른 칸(subtype 등)이나 내 PC 경로는 넣지 마.
?track=quality 처럼 분류로 거를 수 있게 하고, 사진 저장소를 못 읽었으면 빈 목록과 이유를 돌려줘. 이유에도 내 PC 경로는 넣지 마.
```
확인: 서버를 다시 켜고 `http://127.0.0.1:8765/api/repository-images`를 열면 사진 번호(`Q-IND-001` 같은)와 분류가 보이고 전체가 180장이다. 사진 주소 하나를 열면 그림이 보인다.

## 2-6. 사건 기록 저장소와 목록 주소
등록한 사건을 이 PC의 파일에 저장할 곳을 만듭니다.
```text
사건 기록을 이 PC에 저장하게 해 줘. 기록은 courses/vision-96h-v2/preview/_synthetic_store.json에, 사진은 같은 폴더의 _synthetic_store_images 폴더에 한 장씩 파일로 저장해 줘.
서버를 다시 켜면 이 파일들을 읽어 이어 쓰고, 둘 다 git에 올라가지 않게, 브라우저 주소로 직접 열 수 없게 막아 줘(대문자로 바꿔 써도 막혀야 해).
/api/records 주소로 사건 목록을 돌려주게 해 줘. 최근 등록한 사건이 앞에 오게 해 줘.
```
확인: 서버를 다시 켜고 `http://127.0.0.1:8765/api/records`를 열면 `"success":true`와 빈 목록(`"records":[]`)이 보인다.

## 2-7. 사건 목록 화면
```text
사건 목록 화면(#records)을 만들어 줘. 표에 상태, 사건 번호, 장소, 분류, 사진 수, 등록일(YYYY-MM-DD HH:mm)을 보여 주고 최근 사건이 위에 오게 해 줘.
사건이 없으면 "등록된 사건이 없습니다. 새 사건을 등록하세요."를 보여 줘. 화면 위에 "← 홈으로" 단추를 두고, 머리말 경로는 "← 홈으로 / 사건 목록"으로 해 줘.
홈 맨 위 단추에 "전체 사건"을 추가해서 누르면 사건 목록으로 가게 해 줘.
```
확인: 홈에서 "전체 사건"을 누르면 사건 목록 화면에 "등록된 사건이 없습니다."가 보인다.

## 2-8. 사건 등록 화면 틀
```text
사건 등록 화면(#records/new, 제목 "현장 사건 등록")을 만들어 줘. 사진 파일 칸(JPG/PNG, 여러 장 선택), 장소(처음 값 "물류창고 A"), 분류(산업안전 / 택배 발송 확인), 현장 메모 칸을 넣어 줘.
아래에 "사건 등록" 단추와 "목록가기" 단추를 두고, 머리말 경로는 "← 사건 목록 / 현장 사건 등록"으로 해 줘.
홈 맨 위에 "사진 등록" 단추를, 사건 목록 화면에 "+ 새 사건 등록" 단추를 추가해서 이 화면으로 오게 해 줘. 지금은 화면만 만들고 등록은 다음 단계에서 해.
```
확인: 홈의 "사진 등록"을 누르면 등록 화면이 열리고 장소 칸에 "물류창고 A"가 들어 있다.

## 2-9. 사진 올려 사건 등록하기
```text
"사건 등록"을 누르면 장소, 분류(safety 또는 quality), 메모, 사진 파일을 서버의 /api/records로 보내 저장하게 해 줘. 새 패키지는 설치하지 말고 Node 기본 기능만 써 줘.
서버는 사건 번호를 R-101부터 차례로 붙이고 등록 시각과 상태 REGISTERED를 함께 저장해 줘. 사건 목록에는 이 상태를 '검토 대기'로 보여 줘.
성공하면 입력을 비우고 사건 목록으로 가서, 그 화면에 "사건이 등록되었습니다: R-101" 알림을 보여 줘. 실패하면 이유를 알리고 입력한 값은 그대로 둬.
보내는 동안에는 "사건 등록" 단추를 잠가서 두 번 저장되지 않게 해 줘.
```
확인: 사진 1장으로 등록하면 사건 목록 화면에 "사건이 등록되었습니다: R-101" 알림이 보이고, 표에 `R-101`이 '검토 대기', 사진 1장으로 나온다. 올릴 사진은 `vision-risk-student-images/assets/dataset/images` 폴더의 PNG를 써도 됩니다.

## 2-10. 등록 규칙 지키기
화면에서 막은 것을 서버도 한 번 더 검사합니다.
```text
장소가 비었거나 공백뿐이면 화면은 장소 칸에 "장소를 입력해 주세요."를 띄우고 보내지 말고, 서버도 같은 이유로 거절해 줘.
사진은 1장 이상 5장 이하, 한 장에 2MB 이하만 받게 화면과 서버 둘 다 막아 줘.
서버는 파일 앞부분을 읽어 진짜 JPG나 PNG인지 확인해서, 확장자만 바꾼 파일은 거절해 줘.
거절할 때는 "2번째 사진이 2MB보다 큽니다"처럼 몇 번째 사진이 문제인지 한국어로 알려 줘.
```
확인: 장소에 띄어쓰기만 넣고 누르면 "장소를 입력해 주세요."가 나오고, 사진 6장을 고르면 등록되지 않는다. 두 경우 모두 입력한 값은 남아 있다.

## 2-11. 같은 요청을 두 번 보내도 한 번만 저장
응답을 못 받아 다시 눌러도 사건이 두 개 생기지 않게 합니다.
```text
등록할 때 요청 번호(request_id)를 함께 보내게 해 줘. 서버는 같은 요청 번호가 다시 오면 새로 저장하지 말고 처음 저장한 사건을 돌려줘.
화면은 같은 내용을 다시 보내면 같은 요청 번호를, 사진이나 내용을 바꿔 보내면 새 요청 번호를 쓰게 해 줘. 등록에 성공하면 그 번호는 버려 줘.
```
확인: 사건을 하나 더 등록하면 목록이 한 건만 늘어 `R-102`가 맨 위에 나온다. 같은 요청을 다시 보내는 상황은 화면에서 만들기 어려우므로, Antigravity가 알려 준 변경 요약에 요청 번호(request_id) 처리가 들어 있는지 본다.

## 2-12. 등록한 사진 보기 주소
```text
등록한 사진을 /api/records/<사건 번호>/images/<순서> 주소로 볼 수 있게 해 줘. 순서는 0부터야.
없는 사건이나 없는 순서면 다른 사진으로 대신하지 말고 '찾지 못함'(404)으로 답해 줘.
```
확인: `http://127.0.0.1:8765/api/records/R-101/images/0`을 열면 올린 사진이 보이고, `images/9`는 찾지 못했다는 답이 나온다.

## 2-13. 서버를 다시 켜도 남는지 보기 (직접 하기)
서버 터미널에서 `Ctrl+C`로 끄고 `npm.cmd start`로 다시 켭니다. 다른 터미널에서 `git status`를 칩니다.
확인: 사건 목록에 `R-101`, `R-102`가 그대로 있고 2-12의 사진 주소도 그대로 열린다. `git status`에 `_synthetic_store`로 시작하는 이름이 보이지 않고, `http://127.0.0.1:8765/_synthetic_store.json`을 열면 막혀서 내용이 보이지 않는다.

## 2-14. 홈: 확인이 필요한 현장
```text
홈에 "확인이 필요한 현장" 칸을 만들어 줘. 검토 대기 사건을 오래된 순으로 최대 6건, 사진 카드로 보여 줘.
카드에는 첫 사진, '검토 대기' 표시, 사진이 2장 이상이면 "사진 N장", 장소 · 분류, "현장 메모: …"(없으면 "현장 메모 없음"), 등록 시각을 넣어 줘.
사진을 못 읽으면 카드에 "사진을 불러오지 못했습니다"를 보여 주고, 사건이 없으면 "현재 확인이 필요한 사건이 없습니다."를 보여 줘.
```
확인: 홈에 `R-101`, `R-102` 카드가 오래된 것부터 나오고 사진이 보인다.

## 2-15. 홈: 검토 대기 단추와 위쪽 단추 정리
```text
서버의 사건 목록 응답에 검토 대기 건수를 넣고, 홈 위쪽에 "검토 대기" 단추와 그 건수를 보여 줘(목록을 받기 전에는 "—").
단추를 누르면 홈의 "확인이 필요한 현장" 카드를 검토 대기 사건만 거르고, 다시 누르면 거르기를 풀어 줘. 거른 결과가 없으면 "해당하는 사건이 없습니다."와 "전체 보기" 단추를 보여 줘.
홈 맨 위 단추는 "사진 등록", "전체 사건" 둘로 하고, "확인 기준 보기"는 홈 맨 아래 링크로 옮겨 줘.
```
확인: 홈 위쪽에 "검토 대기 2"가 보이고, 누를 때마다 눌린 표시가 켜졌다 꺼진다(지금은 모든 사건이 검토 대기라 카드 수는 그대로다). 맨 아래 "확인 기준 보기"를 누르면 확인 기준 화면이 열린다.

## 2-16. 홈: 최근 등록한 사건
```text
홈의 "확인이 필요한 현장" 아래에 "최근 등록한 사건" 표를 만들어 줘. 최근 등록한 순으로 3건까지 사건 번호, 장소, 분류, 상태, 등록일을 보여 줘.
사건이 하나도 없으면 이 표는 숨겨 줘.
```
확인: 홈에 "최근 등록한 사건" 표가 보이고 `R-102`가 맨 위에 있다.

## 2-17. 등록 화면: 저장소 사진 탭
```text
등록 화면에 "저장소 사진 선택 (1~5장)"과 "직접 파일 업로드 (1~5장)" 두 탭을 만들어 줘. 저장소 사진이 있으면 저장소 사진 탭이 먼저 열리게 해 줘.
저장소 사진 탭은 사진을 12장씩 보여 주고 "사진 더보기 (12 / 180)" 단추로 12장씩 더 보여 줘. 분류 거르기 단추(전체 / 산업안전 / 택배 발송 확인)도 넣어 줘.
사진마다 체크 상자, 사진 번호, 분류를 보여 주고 위에 "선택된 사진: N / 5장"을 보여 줘.
탭이나 거르기를 바꿔도, 사진 목록이 늦게 와도 입력 중인 장소·메모는 지우지 마.
```
확인: 등록 화면을 열면 저장소 사진 12장이 보이고, "사진 더보기"를 누르면 24장이 된다. "산업안전"을 누르면 산업안전 사진만 남는다("전체"에서는 택배 발송 확인 사진 90장이 먼저 나온다).

## 2-18. 저장소 사진 고르는 규칙
```text
저장소 사진은 5장까지만 고르게 해 줘. 6번째를 고르면 "최대 5장까지만 선택할 수 있습니다" 알림을 띄우고 체크를 풀어 줘.
한 사건에는 같은 분류의 사진만 고르게 하고, 다른 분류를 고르면 알림을 띄우고 체크를 풀어 줘.
사진을 고르면 분류 칸도 그 사진의 분류로 바꿔 줘.
```
확인: 택배 발송 확인 사진을 하나 고르면 분류 칸이 "택배 발송 확인"으로 바뀌고, 이어서 산업안전 사진을 고르면 알림이 나오며 체크가 풀린다.

## 2-19. 저장소 사진으로 사건 등록하기
```text
저장소 사진 탭에서 "사건 등록"을 누르면 사진 파일 대신 고른 사진 번호를 보내고, 서버가 사진 저장소에서 그 사진을 직접 꺼내 저장하게 해 줘.
서버는 사진 파일과 사진 번호를 함께 받거나, 분류가 없거나, 사진 분류가 사건 분류와 다르거나, 같은 번호가 두 번이거나, 없는 번호면 거절해 줘.
서버는 메모 끝에 출처 줄([Repository Images: 저장소 이름 @ 커밋]과 사진마다 번호·sha256)을 붙여 저장해 줘. 홈 카드의 현장 메모에는 출처 줄을 빼고 보여 줘.
```
확인: 저장소 사진 2장으로 등록하면 사건 목록에 새 사건(예: `R-103`)이 사진 2장으로 나오고, 홈 카드에 "사진 2장"과 내가 쓴 메모만 보인다.

## 2-20. 홈: 등록할 사진 찾기
```text
홈 아래쪽에 접었다 펴는 "등록할 사진 찾기" 칸을 만들어 줘. 펴면 저장소 사진을 택배 발송 확인 3장, 산업안전 3장 보여 줘.
사진마다 "사진 선택" 단추를 두고, 누르면 등록 화면으로 가서 그 사진이 골라져 있고 분류와 분류 거르기도 그 사진 분류로 맞춰지게 해 줘.
사진 저장소를 못 읽으면 "저장소 사진을 불러오지 못했습니다."와 "다시 시도" 단추를 보여 줘.
서버가 사진 저장소를 못 읽은 상태라면, 사진 목록을 다시 요청받을 때 서버를 다시 켜지 않아도 사진 저장소를 다시 읽게 해 줘.
```
확인: 홈에서 "등록할 사진 찾기"를 펴고 산업안전 사진의 "사진 선택"을 누르면 등록 화면에 그 사진이 체크되어 있고 분류가 "산업안전"이다.
해 보려면: 서버를 끄고 탐색기에서 `vision-risk-student-images` 폴더 이름을 잠시 바꾼 뒤 서버를 켜면 홈에 "저장소 사진을 불러오지 못했습니다."와 "다시 시도"가 보인다. 폴더 이름을 되돌리고 "다시 시도"를 누르면 서버를 다시 켜지 않아도 사진이 나온다.

## 2-21. 불러오는 중·실패 표시
```text
홈과 사건 목록은 사건 목록을 불러오는 동안 "불러오는 중" 문구를 보여 줘.
불러오지 못하면 이유와 "다시 조회" 단추를 보여 주고, 누르면 다시 불러오게 해 줘.
```
확인: 이 PC의 서버는 바로 답하므로 "불러오는 중" 문구는 보이지 않을 만큼 빨리 지나갈 수 있다. 실패 표시도 서버가 응답하지 않을 때만 나온다. 두 문구와 "다시 조회" 단추는 Antigravity가 알려 준 변경 요약에서 확인한다.

## 2-22. 안내 문서 고치기
```text
README에 이번 회차 내용을 더해 줘. 사진 저장소를 프로젝트 옆 폴더에 git clone으로 받는 법(ZIP 금지), REPOSITORY_IMAGES_ROOT 설정, 이 PC에 생기는 기록 파일과 사진 폴더를 적어 줘.
```
확인: README에 사진 저장소 받는 명령과 `_synthetic_store.json` 설명이 보인다.

## 회차 끝 확인
- [ ] 사진 파일을 올려 등록한 사건과 저장소 사진을 골라 등록한 사건이 모두 사건 목록에 '검토 대기'로 나온다.
- [ ] 홈 "확인이 필요한 현장"에 검토 대기 사건이 사진 카드로 나오고, "검토 대기" 단추의 숫자가 사건 수와 같다.
- [ ] 장소가 공백뿐이거나, 사진이 없거나 6장 이상이거나, 2MB보다 크면 등록되지 않고 입력한 값은 남는다.
- [ ] 저장소 사진은 5장까지, 같은 분류끼리만 고를 수 있다.
- [ ] 서버를 껐다 켜도 사건과 사진이 그대로 있고, `git status`에 기록 파일이 보이지 않는다.
- [ ] `/api/repository-images` 목록에 사진 번호·분류·사진 주소만 있고 다른 칸은 없다.
