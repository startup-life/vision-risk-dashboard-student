# 1회차: 준비와 화면 틀, 확인 기준 목록

시작: `milestone-0` 브랜치(안내 파일, 수업 규칙 파일, `materials/` 폴더만 있는 빈 프로젝트)
끝나면: `npm.cmd start`로 켠 서버가 브라우저에 화면 틀(머리말, 홈, 확인 기준 화면)을 보여 주고, 확인 기준 화면에 기준 9개가 표로 나온다.

## 시작하기 전에

- 준비물: 인터넷이 되는 Windows 10·11 PC, 수업에 쓸 Google 계정 1개.
- 작업 폴더는 `C:\vision-ai`로 한다. 바탕 화면·문서 폴더(OneDrive 동기화)와 한글이 든 경로는 쓰지 않는다.
- 1-1부터 1-4까지는 학생이 직접 하고, 1-5부터 Antigravity에 프롬프트를 보낸다.
- Antigravity가 파일을 만들거나 명령을 실행해도 되는지 물으면, 보낸 프롬프트와 관계있는 일인지 보고 승인한다. 서버를 켜겠다고 하면 거절한다.
- 1회차는 한 대화로 이어 가도 된다. 답이 이상해지면 새 대화를 열고 그 단계 프롬프트부터 다시 보낸다.

## 1-1. 프로그램 설치 (직접 하기)
수업에 쓸 프로그램 네 개를 설치한다. 모두 기본값으로 설치한다.
1. Chrome을 설치한다.
2. nodejs.org에서 Node.js 24 LTS의 Windows 설치 파일(.msi)을 받아 설치한다. 22.9 이상이면 된다.
3. git-scm.com/download/win에서 Git for Windows를 받아 설치한다.
4. Antigravity를 설치하고 Google 계정으로 로그인한다. 탐색기 보기 메뉴에서 "파일 확장명"도 켠다.

확인: 설치 프로그램 네 개가 모두 끝까지 진행된다.

## 1-2. 설치 확인 (직접 하기)
설치를 마쳤으면 열려 있던 터미널과 Antigravity를 모두 닫는다. 시작 메뉴에서 새 PowerShell을 열고 두 명령을 친다.
```powershell
node -v
git --version
```
확인: `v24.`처럼 22.9 이상인 판 번호와 `git version ...` 줄이 나온다. "찾을 수 없다"가 나오면 PowerShell을 닫고 다시 연다.

## 1-3. 수업 저장소 받기 (직접 하기)
같은 PowerShell에서 아래를 한 줄씩 친다. 마지막 두 줄은 출발점 브랜치로 옮긴 뒤 내 작업 브랜치(`my-work`)를 만든다.
```powershell
mkdir C:\vision-ai
cd C:\vision-ai
git clone https://github.com/startup-life/vision-risk-dashboard-student.git
cd vision-risk-dashboard-student
git switch milestone-0
git switch -c my-work
```
확인: `dir`을 치면 `README.md`, `.agent` 폴더, `materials` 폴더가 보인다.

## 1-4. Antigravity로 폴더 열기 (직접 하기)
1. Antigravity의 파일 메뉴에서 폴더 열기로 `C:\vision-ai\vision-risk-dashboard-student`를 연다. 폴더를 신뢰할지 물으면 신뢰한다.
2. Antigravity 설정에서 터미널 명령 자동 실행을 끈다. 명령마다 내 승인을 받게 한다.
3. 에이전트 대화 창을 열고 새 대화를 시작한다.

확인: 왼쪽 파일 목록에 `.agent`, `materials`, `README.md`가 보인다.

## 1-5. 프로젝트 둘러보기
Antigravity가 수업 규칙과 지급 자료를 읽었는지 확인한다.
```text
이 프로젝트 폴더의 파일을 읽고, 수업 규칙과 materials 폴더에 무엇이 있는지 세 줄로 알려 줘.
아직 파일은 만들거나 고치지 마.
```
확인: 답에 "서버는 학생이 켠다", "npm.cmd" 같은 수업 규칙과 `standards.json`, `factory-logo.png`가 나온다.

## 1-6. 프로젝트 파일 만들기
Node.js 프로젝트의 시작 파일과, git에 올리지 않을 파일 목록을 만든다.
```text
이 폴더를 Node.js 프로젝트로 시작하려고 해. package.json을 만들어 줘.
외부 패키지는 쓰지 않고 Node.js 기본 기능만 쓸 거야.
서버 파일은 server/server.js로 할 거야. npm.cmd start를 치면 이 파일이 켜지게 start 명령을 넣어 줘.
.gitignore도 만들어서 node_modules, .env, config/local-connection.json이 git에 올라가지 않게 해 줘.
```
확인: 파일 목록에 `package.json`과 `.gitignore`가 생긴다.

## 1-7. 첫 서버와 첫 화면
내 PC에서만 열리는 서버를 만들고 첫 화면 한 장을 띄운다.
```text
server/server.js에 서버를 만들어 줘. 127.0.0.1의 8765번 포트만 쓰고, public 폴더의 파일을 브라우저에 보내 줘.
주소 /로 들어오면 public/index.html을 보여 주고, 없는 파일은 'Not found'로 답해 줘.
public/index.html은 탭 제목 'Vision QC', 본문에 '현장 리스크 대시보드' 한 줄만 넣어 줘.
서버가 켜지면 터미널에 '현장 리스크 대시보드: http://127.0.0.1:8765'를 찍어 줘.
```
확인: 파일 목록에 `server\server.js`와 `public\index.html`이 생긴다. Antigravity가 서버를 켜지 않고 켜는 명령만 알려 준다.

## 1-8. 서버 켜고 끄기 (직접 하기)
1. Antigravity의 터미널 메뉴에서 새 터미널을 연다. 이 창이 서버 창이다. 수업 내내 서버는 이 창에서만 켠다.
2. 서버 창에서 `npm.cmd start`를 친다. Chrome에서 `http://127.0.0.1:8765`와 `http://127.0.0.1:8765/nothing.html`을 연다.
3. 서버 창에서 `Ctrl+C`를 눌러 끈다. 앞으로 서버 코드가 바뀌면 이렇게 끄고 다시 `npm.cmd start`를 친다. 화면 코드만 바뀌면 브라우저를 새로 고친다.

확인: 탭 제목이 "Vision QC"이고 "현장 리스크 대시보드"가 보인다. 없는 파일 주소는 "Not found"가 나온다.

## 1-9. 서버 지키기
보내면 안 되는 파일과 요청을 막고, 같은 포트로 두 번 켜는 것을 막는다.
```text
서버가 public 폴더 밖의 파일, 이름이 점으로 시작하거나 .env가 들어간 파일은 보내지 말고 403으로 답하게 해 줘.
다른 사이트 주소에서 온 요청도 403으로 거절해 줘. 127.0.0.1과 localhost에서 온 요청은 받아.
브라우저가 옛 화면을 기억하지 않게 캐시를 꺼 줘.
8765번 포트를 이미 쓰고 있으면 한국어로 알려 주고 서버를 켜지 않고 끝나게 해 줘.
```
확인: 서버를 다시 켜고 `http://127.0.0.1:8765/%2e%2e%2fpackage.json`을 열면 `package.json` 내용 대신 "HTTP ERROR 403"이나 "Forbidden" 같은 거절 문구가 보인다. 터미널을 하나 더 열어 `npm.cmd start`를 치면 포트를 이미 쓰고 있다는 안내가 나오고 끝난다. 그 터미널은 닫는다.

## 1-10. 확인용 주소 만들기
서버가 켜졌는지, 확인 기준 목록을 보내 주는지 브라우저로 볼 수 있게 한다.
```text
서버에 확인용 주소 두 개를 만들어 줘. /api/health는 {"status":"ok"}로 답해 줘.
/api/standards는 materials/standards.json 내용을 그대로 JSON으로 돌려줘. 파일이 없으면 standards를 빈 목록으로 줘.
/api/로 시작하는데 없는 주소는 404와 함께 오류 문구를 JSON으로 답해 줘.
```
확인: 서버를 다시 켜고 `http://127.0.0.1:8765/api/health`를 열면 `{"status":"ok"}`가, `/api/standards`를 열면 기준 목록 JSON이, `/api/abc`를 열면 오류 JSON이 보인다.

## 1-11. 화면 틀 만들기
모든 화면 위에 같은 머리말을 둔다.
```text
화면 틀을 만들어 줘. 모든 화면 위에 머리말을 두고, 왼쪽에 로고와 사이트 이름 '현장 리스크 대시보드'를 보여 줘.
로고는 materials/factory-logo.png를 public 폴더 안 assets 폴더로 복사해서 써. 로고나 이름을 누르면 홈으로 가.
화면을 그리는 코드는 public 폴더의 js 파일에, 모양은 css 파일에 따로 둬.
머리말 아래는 화면마다 바뀌는 본문 자리로 비워 둬.
```
확인: 브라우저를 새로 고치면 머리말에 로고와 "현장 리스크 대시보드"가 보인다. 탭 제목은 그대로 "Vision QC"다.

## 1-12. 주소로 화면 바꾸기와 홈
주소 끝의 `#` 뒤 이름으로 화면을 바꾼다.
```text
주소 뒤 # 이름으로 화면을 바꾸게 해 줘. #dashboard나 # 없음은 홈, #models는 확인 기준 화면, 모르는 이름은 홈이야.
홈에는 제목 '현장 리스크 확인'과 '확인 기준 보기' 단추를 두고, 단추를 누르면 확인 기준 화면으로 가.
확인 기준 화면은 지금은 제목 '확인 기준'만 두고, 그 위에 '← 홈으로 / 확인 기준' 길잡이 줄을 둬. '← 홈으로'를 누르면 홈으로 가.
홈에는 길잡이 줄을 두지 않고, 화면이 바뀌면 맨 위로 올라가게 해 줘.
```
확인: "확인 기준 보기"를 누르면 주소가 `#models`로 바뀌고 확인 기준 화면이 나온다. 브라우저 뒤로 가기를 누르면 홈으로 돌아간다. `#abc`를 열면 홈이 보인다.

## 1-13. 확인 기준 화면 설명
확인 기준 화면 제목 옆에 설명과 돌아가는 단추를 둔다.
```text
확인 기준 화면 제목 아래에 설명 '물류창고에서 구매자에게 택배를 보내기 전 확인할 발송·산업안전 기준입니다. 사진만으로 주문 일치나 배송 완료를 확정하지 않습니다.'를 넣어 줘.
제목 오른쪽에는 '← 홈으로' 단추를 두고, 누르면 홈으로 가게 해 줘. 위쪽 길잡이 줄은 그대로 둬.
```
확인: 확인 기준 화면에 설명 두 문장과 "← 홈으로" 단추가 보이고, 단추를 누르면 홈으로 간다.

## 1-14. 확인 기준 표
서버에서 기준 목록을 받아 표로 보여 준다.
```text
화면을 처음 열 때 /api/standards를 한 번 불러와서, 확인 기준 화면의 '택배 발송·산업안전 기준' 상자 안에 표로 보여 줘.
표의 열은 항목, 분류, 추가 확인 조건, 판단 보류 조건, 원문 인용이야. 항목은 'C-01 · 머리 보호구'처럼 번호와 이름을 함께 써.
분류는 category가 quality면 '택배 발송 확인', 아니면 '산업안전'으로 쓰고, 원문 인용은 큰따옴표로 감싸 줘.
조건 두 칸은 hazard_condition과 hold_condition, 원문 인용은 canonical_quote 값을 써.
```
확인: 표에 C-01부터 C-09까지 9줄이 나온다. C-01~C-04는 "산업안전", C-05~C-09는 "택배 발송 확인"이다.

## 1-15. 불러오는 중과 실패 안내
기준을 불러오는 동안과 불러오지 못했을 때 보일 문구를 정한다.
```text
화면 틀은 기준을 받기 전에 먼저 보여 줘. 받는 동안 표 자리에 '확인 기준을 불러오고 있어요.'를 보여 줘.
불러오지 못하면 표 자리에 '기준 조회 실패: (이유)'를 보여 줘.
서버에 닿지 못해 실패하면 이유를 '로컬 서버에 연결하지 못했습니다. 터미널에서 npm.cmd start(macOS: npm start)가 켜져 있는지 확인하세요.'로 써 줘.
```
확인: 평소에는 표가 그대로 나온다. 두 문구는 순간이거나 실패할 때만 보이므로, Antigravity의 답에 두 문구를 넣었다고 나오는지 본다.

## 1-16. 연결 표시와 알림 줄
머리말 오른쪽에 서버 연결 상태를, 본문 맨 위에 처리 상태를 보여 준다.
```text
머리말 오른쪽에 연결 표시를 넣어 줘. 처음엔 '연결 대기', 서버에 요청하는 중이면 '연결 확인 중...', 응답을 받으면 '데이터 연결됨', 실패하면 '조회 실패 (이유)'야.
한 번 연결된 뒤에는 요청 중에도 '데이터 연결됨'을 유지해 줘. 서버가 400번대 오류로 답한 것은 연결 실패로 치지 않아.
본문 맨 위에 알림 줄을 두고, 요청 중이면 '처리 중...', 오류가 있으면 '오류: (이유)'를 보여 줘. 둘 다 아니면 비워 둬.
```
확인: 브라우저를 새로 고치면 머리말 오른쪽에 "데이터 연결됨"이 보이고, 홈과 확인 기준 화면을 오가도 그대로다.

## 1-17. 설정 파일 읽기
뒤 회차에서 키를 넣을 설정 파일을 서버가 읽게 한다. 지금은 쓰는 설정이 없다.
```text
서버가 켜질 때 config/local-connection.json이 있으면 읽게 해 줘. 없으면 그냥 시작해.
JSON 형식이 틀리면 오류 원문은 찍지 말고 몇 행 몇 열인지만(모르면 '문법 오류'만) 한국어로 알리고 서버를 켜지 마.
들어 있는 키는 '설정 경고: 알 수 없는 설정 키 (이름)는 무시한다'처럼 이름만 알려 줘. 파일 안의 값은 터미널에 절대 출력하지 마.
config/local-connection.example.json도 { }만 넣어 만들고, 이 예시 파일은 git에 올라가게 해 줘.
```
확인: 파일 목록에 `config\local-connection.example.json`이 생긴다. 서버를 다시 켜면 설정 경고 없이 켜진다.

## 1-18. 설정 파일 시험해 보기 (직접 하기)
1. `config\local-connection.example.json`을 같은 폴더에 `local-connection.json`으로 복사하고, 내용을 `{ "TEST_KEY": "abc" }`로 바꿔 저장한 뒤 서버를 다시 켠다.
2. 내용을 `{ "TEST_KEY": "abc", }`(끝에 쉼표)로 바꿔 저장하고 서버를 다시 켠다.
3. 내용을 `{}`로 되돌려 저장하고 서버를 다시 켠다.

확인: 1번에서는 `TEST_KEY` 이름만 든 설정 경고가 나오고 `abc`는 나오지 않는다. 2번에서는 행·열을 알려 주고 서버가 켜지지 않는다. 3번에서는 경고 없이 켜진다.

1회차 결과를 내 브랜치에 저장한다. 서버를 끄고 서버 창에서 친다. 앞의 두 줄은 처음 한 번만 친다.
```powershell
git config --global user.name "내 이름"
git config --global user.email "내 메일 주소"
git add -A
```
